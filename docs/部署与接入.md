# 服务部署与接入

## 三套服务的职责

皮肤站继续使用 `https://skin.hxzmc.top`，登录接口为 `/api/yggdrasil`。HXZ UP 继续维护整合包、版本、文件和更新策略。新增社区服务只维护公告、聊天记录、在线状态和语音信令；不接管皮肤站密码，也不复制整合包文件。

## 启动社区服务

安装 Node.js 24，进入 `server`，运行 `pnpm install --frozen-lockfile`，复制 `.env.example` 为 `.env`。填写配置后执行 `node --env-file=.env src/server.mjs`。Windows 可双击根目录 `start-community.bat`。默认监听本机 8787，访问 `/health` 检查状态，网页管理在 `/admin/`。账号 admin，初始随机密码位于服务端 data/初始管理员密码.txt；修改密码后删除该文件。可通过 HXZ_ADMIN_PASSWORD 设置首次密码。客户端不会启动此服务。

生产环境通过 HTTPS 反向代理暴露接口，WebSocket 使用同域 `/ws`。提供了 `nginx-community.conf.example`。实际域名与证书需使用自己的配置；在客户端“设置 → 社区服务”填该 HTTPS 根地址。

也可在 `server` 目录执行 `docker compose up -d --build`，先创建 `.env`。绑定挂载 `data` 时确保容器 node 用户（通常 UID 1000）有写权限。示例只把容器端口映射到宿主机回环地址，供 HTTPS 代理使用。Docker 部署模板尚未在本机执行。

## 配置项

| 项目 | 用途 |
| --- | --- |
| HOST / PORT | 默认 127.0.0.1 / 8787 |
| HXZ_DATA | SQLite 和社区会话签名密钥目录 |
| HXZ_SKIN_API | 默认幻想镇 Yggdrasil 根接口 |
| HXZ_ADMIN_IDS | 管理员游戏角色 UUID，逗号分隔，从启动器账号页复制；不是邮箱，也不是皮肤站数字用户 ID |
| HXZ_ORIGINS | 允许的页面来源；Electron 桌面需要 `file://` 和 `null`；开发预览需对应端口来源 |
| HXZ_TURN_URL | TURN 地址，可逗号分隔，例如 `turn:voice.example.com:3478?transport=udp,turn:voice.example.com:3478?transport=tcp` |
| HXZ_TURN_SECRET | 与 coturn 的 static-auth-secret 相同；不要提交到仓库 |

独立网页后台可以直接发布公告，无需运行客户端。管理员登录启动器并连接社区后，客户端公告页面也会出现发布/删除按钮。三个公告组固定为 `survival`、`mod-1`、`mod-2`。服务端再次检查权限，修改客户端界面不能绕过校验。

## 公网语音

使用 coturn 或兼容的 TURN 服务，开启 `use-auth-secret`，配置 `static-auth-secret` 与 `realm`，必要时设置公网地址映射。开放 TURN 监听端口与实际配置的中继 UDP 端口范围，配置防火墙；仅开放 443 的 WebSocket 不能替代音频中继。

社区服务为已登录用户生成一小时的临时 TURN 凭据。没有 TURN 配置时仍能在部分网络中直连，但不保证跨运营商/复杂 NAT 可达。当前音频由各成员间直接连接，每房限制 8 人，较大语音频道需要 SFU，不能简单调高人数上限。

## 皮肤站统一身份

客户端直接向皮肤站 authenticate/validate/refresh。社区服务通过上游 refresh 获取可信的 `selectedProfile`，只接受上游返回的 UUID/角色名，随后签发社区会话。刷新后的皮肤站凭据由桌面主进程加密保存，不传给页面。页面只持有短期社区令牌，WebSocket 连接后发送认证包，不把令牌放在 URL。

已保存社区会话在有效期内复用，避免每次短暂重连都轮换皮肤站令牌。删除/换角色会断开旧连接。若皮肤站账号失效，重新登录即可。

网站后台管理是独立网页会话。本次没有皮肤站管理权限或已注册 OAuth 客户端，因此没有修改皮肤站以强行兑换 Cookie。若未来需要首次登录也直接进入网站后台，应在皮肤站配套部署正式 OAuth/单点登录回调。

## HXZ UP

每个实例保存自己的地址列表，也兼容已有 `versions/<实例>/updater/config.json` 中的 servers。填写的是能访问 `version.json` 的客户端根地址，而非管理后台登录页。新增实例必须在 HXZ UP 后台配置并发布游戏版本/加载器。

启动顺序：更新器独立 Java 进程 → 检查是否存在未完成更新 → 重新读取实例 JSON → 选择匹配 Java → 校验资源 → 外置登录 → 启动 Minecraft。服务维护时沿用 HXZ UP 原有“保留本地文件并跳过更新”的行为；首次安装处于维护则不会凭空产生可启动实例。

无需再往游戏 JVM 中手工添加 updater 的 javaagent。HXZ UP 的更新文件策略仍由原有后台定义，本启动器不额外覆盖其策略。

## 运行维护

备份社区 data（建议停服复制，包含 SQLite 和密钥），不要公开 `session.key`、`.env` 或启动器的账号文件。更换社区签名密钥会让所有社区会话失效。聊天不无限存储，数据库删除旧记录后复用页；无需每条消息 VACUUM。

默认按连接来源做频率限制。使用本机反向代理时配置 `HXZ_TRUST_PROXY=loopback`，并由代理覆盖 `X-Real-IP`（示例已配置）；只信任来自回环地址的代理头，公网客户端无法直接伪造。跨机器代理请保持默认不信任，按实际网络增加严格的代理地址白名单。单实例服务适合当前小型社区，多节点部署需要共享在线状态与信令。

封禁 API：管理员社区令牌下，`POST /api/moderation`，JSON 为 `{"uid":"角色UUID","banned":true}`；`false` 为解封。封禁立即断开该角色现有连接。独立 /admin/ 页面提供封禁与解封。

0.2.1 兼容旧配置中只填写 null 的情况，同时识别桌面 WebSocket 使用的 file:// 来源。来源使用明确白名单，未知网站仍拒绝。

## 0.2.2 更新日志与头像

独立社区后台 → 服务配置 → HXZ UP 更新日志来源，分别填写原版生存群组、模组一服、模组二服的客户端根地址（能请求 version.json），可以是同一个 HXZ UP 服务的不同整合包路径。不能填写后台地址、JSON 文件地址或将一个包的多个镜像分配给不同服务器。相同根地址拒绝保存；留空明确显示尚未配置。客户端不根据当前选择的实例推测归属。当前尚未收到这三个正式地址，初始配置保持空白。

通知公告首页按三个服分别展示最新更新日志，进入各服子菜单只显示该服日志和公告。日志纯文本显示，保留版本、日期、来源标识及最多100条历史入口。每组独立缓存30秒、每分钟自动刷新；维护中、格式错误、无法连接不会借用其他组的数据。发布前后核对版本标识，防止维护/发布过程混合不同版本的内容。

玩家在个性化中设置的头像按皮肤站角色保存；社区 API 只允许令牌持有人更新自己，图片有体积和尺寸限制。头像在聊天历史和在线成员中显示，广播只包含头像版本号，不包含大段图片。未连接时本地保存，下次连接再同步；社区服务端 profiles 表保存已同步的头像，属于 data 备份内容。客户端自定义头像不修改皮肤站游戏皮肤。

HXZ UP 窗口开关默认开启，仍需实例配置启用自动更新才会在启动前检查。独立窗口完成或关闭更新日志后再继续游戏启动；失败仍保留任务详情，取消或关闭未完成的更新会阻止本次启动。窗口主题跟随启动器，原配置的日志显示时长等选项保留。


## 0.3.0 使用与升级

默认社区根地址为 https://qqbot.hxzmc.top。公网0.2.2服务在开发期间可正常握手；要应用服务端15秒心跳，请管理员停止旧社区进程，保留并备份data和.env，替换0.3.0服务程序后重启。不要删除session.key，否则所有社区会话失效。客户端与独立服务端分别升级。代理应转发HTTP/1.1 Upgrade / Connection，关闭缓冲并给WebSocket至少180秒读写空闲时限，例见 nginx-community.conf.example；TLS证书校验继续开启。已配置HXZ_TRUST_PROXY=loopback时，代理必须覆盖X-Real-IP。

启动器更新日志：通知公告 → 启动器更新。自动更新：设置 → 启动器更新，默认开启；自动从0xiaoyun0/HXZ_LAUNCHER正式Release读取并比较版本，下载校验后等待游戏/安装结束，15秒后静默安装并重启。开关立即生效，不需要再手动运行安装向导。当前没有Windows代码签名证书，沿用原NSIS安装形式；正式用户环境跨版本覆盖仍应按常规发布验收。

整合包：拖入mrpack确认名称，主进程执行安装，任务详情可关闭再打开。失败/取消/重启后在下载页或任务详情的“未完成的安装”继续或清理，原mrpack需保留；继续复用完整校验文件，不是单个文件的HTTP字节续传。正式实例直到安装成功才出现；取消与失败不改变其他实例和共享资源。关闭仍在安装的主窗口只最小化，明确点取消才中止。

固定服默认显示在实例列表。原版生存群组服首次启动下载26.2，选择本机合适Java，缺少时下载官方Java25运行环境；默认进入s1.hxzmc.top。模组一、二服版本未确定，保持不可启动占位。实例配置可关闭自动进入或修改地址，实例列表的进入按钮可以单次启动并进入已配置地址。

MOD管理入口位于实例概览和实例列表，支持添加、搜索、启停和回收站删除；共享游戏目录模式的mods同样共享。个性化中背景应用整个窗口；首页头图由各实例单独保存，设置的简化首页开关可以隐藏详细属性和公告区。
