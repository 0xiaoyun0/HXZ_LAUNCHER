# 幻想镇 0.10.0 Windows 验收

2026 年 11 月 23 日，本轮在 Windows 11 专业版 x64（10.0.26200）上验证了 x64 和 ia32 的 Windows 安装版。ia32 在这台电脑的 WOW64 环境中运行。GitHub 正式频道在验收期间仍为 v0.9.2。

### 测试边界

- 0.9.2 的回放把更新源、下载缓存、安装目录与用户资料指向隔离环境，并跳过旧客户端的系统协议注册。原更新器的签名、摘要、自动安装和进程交接逻辑均参与测试。只有公开后才能实测普通玩家从 GitHub 的 latest 发现 0.10.0。
- 扩展安装使用本机 HTTP 服务提供与草稿相同的 ZIP，包含和 GitHub 附件相同的重定向步骤。正式公开后，双架构安装测试可加 `--github` 直接验收公开下载入口。
- 皮肤管理网页也单独做了检测。本机默认网络曾连续三次在 7.5 秒内未能打开网页，同一时段账号接口也曾连接超时。随后默认网络访问网页和账号接口都返回 HTTP 200。两处公共 DNS 返回的两个节点也分别通过域名及 TLS 校验。这些观测能确认恢复，不能代表全天可用率。
- 本机默认网络访问社区域名曾出现 TLS 握手中断。使用公共 DNS 返回的节点并保留域名与证书验证后，社区健康检查和服务器列表均返回 HTTP 200。皮肤站使用其正常域名完成了独立实测。跨公网 NAT 联机、生产积分入账、长期网络可用性和 Windows 原生 32 位操作系统仍需分别验证。
- Windows 草稿阶段也检查了 Android 社区界面、内存策略和两个测试 APK。正式版另提供 ARM64 和 x86_64 完整 APK。0.9.2 安卓更新器只接受 64 MiB 以内的安装包，因此原安卓更新清单继续提供其兼容版本，安卓用户从发布页手动下载。游戏运行组件和社区服务端也沿用各自的签名清单。

### 维护者复验

本次发布候选包又在 1250 × 825 和 960 × 620 的原生窗口检查了任务中心。测试实际启动 Java，测量执行步骤标题与卡片两边的间距、状态图标与正文的间距，并保留了两种窗口的截图。完整布局矩阵覆盖 55 个路由、6 种窗口与字号组合、18 个弹窗。

Android 11 的 Google APIs x86_64 模拟器安装了原始 0.9.2 APK，再用原发行签名的 0.10.0 覆盖安装。原包名、首次安装时间和旧资料目录内的测试文件均可读回。ARM64 包通过模拟器的原生指令翻译运行，另验了 x86_64 原生包。正式包的旧版 WebView 83 能通过首页打开栏目、进入 LINKING 登录入口，并显示 24 款小游戏。隔离皮肤站角色还通过 FCL 打开了 Minecraft 1.16.5 演示世界，保存退出后回到社区。

跨端积分使用隔离的社区服务和同一角色验证。测试预置了接近 24 小时的累计在线记录，可信游戏服的后续在线报告触发 5 积分，手机与第二个登录会话读回了同一笔奖励。小游戏测试在服务端已经结算时丢弃响应，手机重试后仍是原来的成绩。以上测试没有给正式玩家账本写入数据。

先运行 `npm test`、`npm run test:engine`、`npm run test:community`、`npm run test:native` 和 `npm run test:desktop:layout`。本轮四组功能测试数量依次是 31、64、135 和 8，布局矩阵见上表。安装验证使用 `npm run test:desktop:installed` 和 `npm run test:desktop:installed -- --ia32`。

要回放旧版，设置 `HXZ092_RELEASE` 指向带有原始 Windows 安装包和 updates 目录的 0.9.2 发布目录，`HXZ_QA_7Z` 指向 7-Zip，`HXZ_QA_ASAR` 指向 @electron/asar 的 lib/asar.js。运行 `node scripts/check-092-handoff.mjs`，然后附加 `--ia32` 再运行一次。

正式发布后，在这两条命令末尾分别加 `--github`，原版程序会使用自带的公开更新源。玩家资料和安装目标继续位于临时目录。两个 Android 正式包的身份、签名、架构和内置游戏组件使用 `node apps/android/verify-apk.mjs --release` 验证。

构建两个 Windows 版本、签发清单并提交源码后，运行 `node scripts/prepare-windows-draft.mjs` 生成待上传文件和对应的 SHA256SUMS.txt。独立扩展、签名更新清单、旧版认识的安装包文件名及其他平台的更新入口都由该脚本校验。审核后先让 main 和发布标签指向经验证的源码，再将草稿设为正式版。
