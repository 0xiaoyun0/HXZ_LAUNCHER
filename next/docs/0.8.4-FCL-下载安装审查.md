## 逐机制对照

| 链路 | FCL 已读机制 | HXZ 对应与差异 |
|---|---|---|
| 任务调度与并发 | `AsyncTaskExecutor` 把 preExecute、前置任务、execute、后置依赖、postExecute 串联，集合任务用 CompletableFuture 并行；`FetchTask` 下载池默认 `min(CPU×4,64)`，可重设；`Schedulers.io` 另有 8 线程池。 | `RuntimeDownloads.fetchAll` 使用固定 4..32 并发与 CompletionService；最多只提交并发数的在途任务，避免一次为十万资源对象建立全部 Future。GamePreparation 分阶段规划；安装器处理器按声明顺序运行。没有移植通用任务图框架。 |
| 取消 | FCL 执行器共享取消标记，传给子任务；FetchTask 在循环与失败重试前检测，退避时每 100ms 检测。 | HXZ Cancellation 向子下载组传播；失败后取消其余下载、shutdownNow 并等待退出；读流前后和处理器之间检查。修复本轮最后失败与取消竞态。Socket 正阻塞读时仍受读取超时约束，不能声称可即时关闭所有阻塞读。 |
| 重试与恢复 | FCL FetchTask 每源有限重试，404 跳源，I/O 重试前 500/2000/5000ms 退避；FileDownloadTask 每次写临时文件、检查缓存/ETag。其已读实现没有实际发 Range 请求，虽有 DownloadState 类型。 | HXZ 先跑完一轮所有等价源再重试暂时错误，每源最多 5 次；404/auth/校验失败不重试。按源隔离 partial，只有有上游摘要时续传；206 校验起点，200 回退重写，完整摘要通过后激活。HXZ 当前没有退避/Retry-After 支持，也没有照搬 FCL 未实际使用的 DownloadState。 |

## HXZUP 自有链路核对

FCL 没有本项目的 HXZUP portable 协议；这里核对的是 HXZ 自有实现，不把 FCL 整合包类当成可替换组件。

阅读 `HxzupPlan`、`ServerPreparation`、`ServerPresets` 全部流程，并阅读 `resources/installer/src/up/hxz/Updater.java` 的 1–190、220–244、300–386 行：

1. 预设只接受三个固定 id、受限 URL 与明确 loader；ServerPreparation 用准备锁防止重复安装，context.run 必须匹配隔离实例。
2. HXZUP 来源检查有总计 16 秒、单源最多 8 秒的预算，status 与 game-profile 必须来自同一来源；维护状态优先。本地不完整、强制更新或非网络错误不能退回离线。
3. 先完成 Minecraft 与 loader，才运行现有 updater。portable.json 固定已装游戏/loader，`maxParentLevels=1`，managed 模式不会触发 PC 游戏安装器或交互强制继续。
4. 相同远端版本原本会跳过清单；本地回执不完整时 HxzupPlan 设置既有 repairGameFiles。Updater 在暂存后复查服务版本，journal 记录备份与目标，失败逆序恢复，最后提交 local-version/local-manifest。
5. Wrapper 检查退出码、未完成事务、版本标记、修复是否真的产生新提交，再检查游戏完整性与本地 pack 回执。JAR 摘要固定；允许用户编辑配置，也允许已成功规则记录的主动删除。

本轮没有修改 HXZUP 规则引擎、资源包、版本号或发布文件。Updater 未读的辅助方法、Network/Rules/IO 类属于本报告明确的未审范围；不能据上述片段声称所有更新和崩溃恢复场景已证明。

## 只扫描、未移植与验证边界

仅通过官方 tree 清单定位、未阅读实现：Curse/MCBBS/MultiMC 的完整导入链、OptiFine/Cleanroom/LiteLoader/LegacyFabric 安装器、JavaVersion.kt 与 Java管理界面、Unzipper、具体远端组件版本列表与缓存仓库实现。它们不能列入已完成迁移。

已读但本轮没有移植：FCL HMCL patches/TLauncher/Classic 版本导入；通用整合包导入及 overrides 更新策略；FCL 的旧库 `checksums` 多摘要与包内 checksums.sha1 兼容校验；下载退避与 ETag；可变旧资源索引放宽；任意 JRE 导入/自动下载；跨 Java 版本自动重试处理器。HXZ 已有标准 artifact SHA-1/SHA-256 与无上游摘要文件的本地 SHA-256 pin，旧 checksums 字段仍是明确兼容性缺口，不能把 pin 当作上游真实性证明。

旧 Forge 本轮证明的是两种安装器格式的规划与旧格式受控安装链，真实格式样本为 Forge 1.7.10 与 1.12.2；没有宣称所有 1.5–1.12、所有 NeoForge/Forge 版本或所有 loader 组合已支持。现有运行模块只有 Java 21/25；Java 8 模块未提供，所以旧 Forge 不能作为本次新增的可玩游戏支持项。实际 Android legacy LWJGL2、Java8与模组 API兼容仍需对应模块、设备与游戏测试。所有成果只写源码/测试/文档，未发布或更改构建版本。
