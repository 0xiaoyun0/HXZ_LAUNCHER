## 2. JVM 执行模型：同样需要生命周期隔离，实现条件不同

FCL 的 ART JNI 入口把 Java 参数转为 C argv，然后 `dlopen("libjli.so")` 调用 `JLI_Launch`。启动前重设信号处理并用 SIGABRT 管道通知专用线程，最后经 `nominal_exit` 返回 Android 退出桥。JLI 的完整命令行解析由 JRE 承担；这和 HXZ 的 JNI Invocation API 不能在参数处理上直接互换。[启动入口与信号处理](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/jni/jre_launcher.c#L123)

HXZ 的 `hxz_jvm_exec.cpp:11` 是独立可执行入口，设置父进程死亡信号，读取有 magic/长度/数量限制的 job，再初始化 IPC/renderer 并调用 `hxz_java`。`hxz_jvm.cpp:38` 从指定 JRE 的绝对路径加载 `libjvm.so`，解析 `JNI_CreateJavaVM`，由游戏 VM 的 JNIEnv 构造参数并调用 main。它清除 `JAVA_TOOL_OPTIONS`、`_JAVA_OPTIONS`、`JDK_JAVA_OPTIONS`；UTF-8 参数经 `String(byte[], UTF-8)` 构造，不让 ART 的对象进入游戏 JVM。借鉴目标是 VM、对象、线程和退出码的边界，不是新增 ART/JLI 混用层。

FCL `fcl_loader.c:79` 以 stdio 管道转发日志到 ART，对 NewStringUTF 不接受的 UTF-8 字节替换为问号。HXZ 可以继续通过子进程标准输出收集原始字节，在 Java/UI 边界解码；没有理由照搬可能丢失补充字符的转换。FCL 的 `POJAV_ENVIRON` 在环境变量中保存一个进程内堆指针（`environ.c:13`），只在同一地址空间有意义，不能作为 HXZ 跨进程协议。

HXZ `hxz_vm_heap.cpp:14` 在独立进程加载 JVM/renderer 前处理 Android heap tagging：API29无需关闭、API31+使用 mallopt、API30动态解析 legacy 接口，并验证 malloc 指针确为未标记。此文件不链接进 ART 使用的 shared library。该 API30 动态入口仍需设备/OEM验证，不能称为所有 Android 通用能力。FCL 上述已读文件不能证明其有完全相同的机制。

HXZ `hxz_jvm_shutdown.h:10` 对已知同步 BinaryPatcher CLI 单独请求 Java System.exit，其他 main 等待 DestroyJavaVM；独立进程最后 `_exit(result)`，避免 detached 线程访问销毁后的 C++ 全局对象。FCL 的全局 exit hook/atexit 是维护 ART 与游戏 VM 同进程生命周期，不适合移植替代 HXZ 这条退出路径。

## 4. LWJGL：官方绑定、独立 GLFW 与补丁构建是三件事

FCL 两套构建把 Java 源覆盖与部分模块合并成运行时 jar，其余 jar复制到assets。3.3.3以Java8构建、3.4.1以Java17构建；两者声明复制模块为输入，3.4.1另声明复制产物为输出，设置固定文件顺序/去时间戳。3.3.3 明确排除 jsr305 打包，以避免 JDK 模块同名包。可借鉴“准确声明构建输入输出、避免模块元数据与注解包污染”的约束，不复制 FCL 的合并 jar 或 Java patch。[3.3.3 构建](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/LWJGL/3.3.3/build.gradle.kts#L27)、[3.4.1 构建](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/LWJGL/3.4.1/build.gradle.kts#L38)

FCL `CallbackBridge` 在3.4.1增添SDL初始化和手柄共享buffer native入口；`SDLInit.java:75` 在SDL_Init前通知启动器；`GLFW.java:567–575` 主动加载pojavexec，并使用其native桥。这些Java类不是可脱离FCL/Pojav执行层随意复用的官方jar。`PojavRendererInit.java:15–31` 用同一个FunctionProvider初始化GL4ES；可借鉴同源符号解析原则，不能照搬库名特判或把FCL renderer能力归给HXZ。

FCL `glxshim.c:7–10` 的实际功能只是把 `glXGetProcAddress` 转给现有 `getProcAddress`。注释给出旧LWJGL解析背景，但本轮未独立核查注释链接的外部提交，不能以注释代替所有版本的兼容证明。HXZ `glfwGetProcAddress`（`:489`）在当前上下文上直接路由 OSMesa 或 EGL/GLES，采用独立 C ABI；本轮不额外加入 GLX 假层。

HXZ `upstream-build/CMakeLists.txt` 从固定第三方源构建 lwjgl core/opengl/stb/tinyfd 与libffi，剔除WGL生成源，使用ARM64/Linux编译宏、符号版本脚本、无未定义符号与16KiB链接对齐。Java GLFW仍是官方绑定，实际平台能力由HXZ独立native实现提供。`dependencies.lock.json` 记录3.3.3源提交 `ddf2a2aa31b578cc89bc5644fba5057f56d66867`、3.4.1源提交 `ef3ffcba821accd5274be9661c2a6604a13e607c`，来源为ZalithLauncher/lwjgl3的固定第三方源；这不是“所有第三方代码都由HXZ原创”，也不是复制FCL app glue。

依赖锁明确排除 `FCL vendor AAR or assets`、`launcher Java GLFW/CallbackBridge code`。lock的JNI覆盖/ELF构建状态是既有证据声明，本轮未重跑生成报告。对官方Java API是否可玩仍要验证实际native ABI、版本、上下文、输入、资源、生命周期，不能只看jar/so都存在。

`Lwjgl3ifyPatcher.java:163–179` 将mod内嵌RFB入口、JVM参数、Java要求和完整库闭包覆盖到内存版本；此外提取嵌入forgePatches、禁用Linux桌面入口生成、清理历史落盘版本。它说明“旧MC+新Java”是显式兼容层提供的另一条启动链。HXZ没有本轮移植GTNH/lwjgl3ify/RFB支持；当前Java21/25不能由此推导普通1.7.10/1.12.2 Forge已可玩。此前补全的旧Forge路径只属于安装准备能力。

## 5. 音频与 AWT 的依赖边界

FCL将三条能力分开：游戏的LWJGL/OpenAL、Java Sound的libjsound/DAUDIO、AWT的Cacio/窗口输入桥。

FCL `jsound_openal.c:119–184` 复用同名OpenAL库、解析所需函数、创建独立device/context并在调用时置current；`:269–343` 提供PCM单双声道8/16bit格式、OpenAL播放源和采集设备；`:392–542` 实现6×50ms缓冲、欠载恢复、flush、available与相对播放位置。`CMakeLists.txt:253–293` 同时编译OpenJDK libjsound通用层，并关闭PORT/MIDI，不是“只塞libopenal.so”即可提供javax.sound。原生声明/库名、JDK内部ABI、Java通用层转换都属于完整契约。

这个后端仍不宜按源码直接采用。例如采集Start分支（`:354–355`）未像播放分支设置 `info->started=1`，而Read与StillDraining（`:437`、`:468`）读取该字段；这是静态审查可见的后续验证点，本轮没有设备录音复现，也没有修改FCL。更不能将其头部的多JRE ABI说明当作HXZ所有JRE的实测保证。

FCL `awt_bridge.c:35–50` 保存ART/游戏VM，`:126–167` 从Cacio屏幕取RGB数组再复制到Android VM，输入与剪贴板也分别attach到目标VM调用；Java对象没有直接跨VM共享。`runtimeJNIEnvPtr_GRAPHICS/INPUT` 是缓存的线程相关JNIEnv，不能脱离原调用线程约束照搬。`awt_headless/placeholder.c` 只有两行占位注释，构建成空库不构成AWT/Swing显示支持。[AWT桥](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/jni/awt_bridge.c#L126)

HXZ `hxz_jvm.cpp:53` 默认headless；依赖锁列出OpenAL Soft1.24.3、OpenSL、noHRTF，未列独立的JSound后端或Cacio运行模块。它目前支持的基础依赖不能升级表述为“Java Sound采样/录音、MIDI、Swing/AWT窗口和Java Desktop模组全部兼容”。后续若需要，应独立实现公开契约，并明确音频context并发/恢复、录音权限、PCM格式转换、线程生命周期，以及跨进程图像/输入/剪贴板协议。本轮不新增占位库来掩盖缺失能力。

## 6. 依赖锁能证明什么

| HXZ现有记录 | 可下结论 | 仍不能下结论 |
| --- | --- | --- |
| Java21/25固定publisher tar、source/builder提交、SHA256与法律树，JRE页大小4096 | 来源和交付边界有记录；支持目标限ARM64与4KiB JRE | 没有Java8/17模块；不能因launcher/native 16KiB对齐宣称整个JRE能在16KiB页设备运行 |
| LWJGL3.3.3/3.4.1源码构建、官方Java模块和JNI覆盖记录 | 可继续用独立glue接官方绑定，保持版本匹配 | 不代表FCL Java桥、SDL3、所有LWJGL native模块已经提供 |
| 3.4.1 coreClassifier=unsafe；shaderc/spvc/vma列为unsupportedNativeModules | 运行准备必须遵守真实能力，Vulkan游戏后端关闭 | 存在对应Javajar不构成native能力；不能用强制参数绕过能力检查 |
| JNA5.14/5.17官方AAR匹配native，源档内二进制一致记录 | 使用对应版本的jnidispatch，保持Java/native ABI对应 | 不能把5.x库随意给另一个版本使用，也不能从JNA存在推导TTS/所有系统集成可用 |
| 独立Mesa25.3.4+官方24.3.4 OSMesa源、公开Android依赖、softpipe/zink记录 | 不依赖FCL vendor graphics包；现有游戏入口优先OpenGL | 不能宣称所有GPU、所有mod、Vulkan入口均验证通过 |

Java25的builderBranch名含`fcl/BUILD_JRE_25`，说明第三方JDK发行者构建来源，不等同于把FCL app源码引入HXZ。JDK、LWJGL、OpenAL、Mesa、JNA各自法律/来源义务仍要保留。本轮只核对锁定记录与排除项，没有进行新的法律审查或全部二进制重验。

## 7. 本轮产出与验证限制

本轮新增文件仅本审查文档。没有新增native hook、JNI桥、共享指针环境、SDL3、AWT、JSound、Vulkan或GTNH代码；没有改版本/发布/构建产物。前一轮下载安装修复和22项定向回归另见 `0.8.4-FCL-下载安装审查.md`，不重复算作本原生审查的实测。

可安全沿用的机制要求：明确VM/线程/进程所有权，保留准确退出与日志，参数编码不损坏，native库版本/符号与Java绑定一致，renderer符号来自同一实例，构建输入输出完整，能力不足时给出真实失败。HXZ现有独立执行与依赖锁已实现其中部分原则；其他差异列为后续有具体需求再独立实现的工作。

未完成/未声称：Android实机全链路、OEM矩阵、SIGABRT恢复验证、全部GLFW API、SDL3/新Vulkan游戏入口、Cacio/AWT模组、javax.sound播放/采集、多窗口共享context、语音和TTS、完整JRE/图形依赖源码逐行阅读。固定SHA源文件阅读与静态对照不能代替这些运行验证。
