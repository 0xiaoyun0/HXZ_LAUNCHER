# HXZ 启动器插件 API 1

0.9.2 的插件运行在 Windows 桌面启动器。Windows x64 与 ia32 共用 API；Android 当前提供社区与游戏功能，不执行桌面 Node 插件。插件可以改变所有启动器界面与行为，属于完整信任的本机代码。审核和 SHA-256 只能确认来源与完整性，不能代替用户对作者的信任。

## 包格式

扩展名为 `.hxzplugin`，内容为 UTF-8 JSON，最多 4 MiB、256 个文件、每文件最多 1 MiB。所有代码和文本资源内嵌，发布不允许外置下载的入口脚本。不得包含凭据、用户文件或真实账号信息。

```json
{
  "format": "hxz-plugin-v1",
  "manifest": {
    "id": "my-launcher-plugin",
    "name": "我的启动器插件",
    "version": "1.0.0",
    "apiVersion": 1,
    "author": "作者名",
    "description": "插件行为与用途",
    "permissions": ["launcher.full"],
    "platforms": ["win32-x64", "win32-ia32"],
    "main": "main.cjs",
    "renderer": "renderer.js",
    "style": "style.css"
  },
  "files": {
    "main.cjs": "exports.activate = api => { return () => {}; };",
    "renderer.js": "const el=document.createElement('div');el.textContent='我的插件';document.body.append(el);api.onDispose(()=>el.remove());",
    "style.css": ""
  }
}
```

`main` 与 `renderer` 至少提供一个，`style` 可选。ID 使用小写字母开头的 3–64 位字母、数字和连字符；版本为三段数字。文件只接受相对路径，拒绝目录穿越、Windows 保留名、大小写冲突和链接。每次发布必须增加版本；已有 ID 只能由原提交账号继续发布。

## 主进程

`main.cjs` 导出 `activate(api)`，可同步或异步，返回可选的清理函数。支持打包为单文件 CommonJS 或多文件 CommonJS；第三方依赖需要打入包内，不在用户机器执行 npm 安装。

| 字段 | 用途 |
| --- | --- |
| `api.apiVersion`, `api.id` | API 版本和插件 ID |
| `api.app`, `api.window` | Electron App 与主 BrowserWindow，可修改窗口及完整界面行为 |
| `api.services.invoke(action, input)` | 启动器服务入口，覆盖实例、设置、账号、联机等功能；允许包装此方法以扩展流程 |
| `api.require` | 从插件目录解析 CommonJS 和 Node 内置模块 |
| `api.storage` | 插件持久数据目录；由插件按需创建 |
| `api.onDispose(fn)` | 注册定时器、事件、服务包装等恢复动作 |
| `api.report({message,detail,context})` | 进入启动器自动诊断管道，遵循用户的诊断开关 |

例如，在 `activate` 中保存原 `services.invoke`，包装以增加前后处理，并在清理函数恢复原方法。不得把无关服务请求改为虚假成功。长任务必须可取消，不要在主进程阻塞文件或网络操作。

## 界面入口

`renderer.js` 在主页面加载后作为异步函数体执行，接收 `api`。它可直接访问 `document` 与 `window`，修改页面、增加组件或替换界面。`api.invoke(action,input)` 返回已解包的服务结果；`api.navigate('/settings')` 切换页面；`api.onDispose(fn)` 清理页面元素与监听器。`style.css` 作为独立样式注入，停用时删除。页面恢复或重新加载后会重新执行入口。

## 权限、生命周期与恢复

所有包必须声明 `launcher.full`。安装或升级后均停用，用户确认完整本机文件、执行程序、网络、账号及界面权限后启用。不要假设此权限是沙箱；插件拥有宿主进程能力。插件必须自行维护清理函数，停用后建议重启。插件数据在移除后保留，便于恢复。

启动期异常会停用对应插件；若进程在加载某插件时中断，下次启动会自动停用它。运行期死循环或任意全局修改无法由清理函数保证恢复，可执行 `幻想镇启动器.exe --disable-plugins` 或包内的“禁用插件启动.bat”进入安全模式，然后在设置中停用/移除。

## 市场流程与接口

用户在“设置 → 插件与市场”提交本地包，社区后台“插件市场审核”查看完整代码、批准、拒绝或下架。市场只公开已批准的版本，下载重新校验 SHA-256。提交者的账号身份与清单作者同时展示。

| 接口 | 权限与行为 |
| --- | --- |
| `GET /api/plugins?q=&offset=` | 已发布版本列表 |
| `GET /api/plugins?mine=1` | 当前登录作者的提交与审核说明 |
| `POST /api/plugins`，`{package}` | 登录用户提交待审核版本 |
| `GET /api/plugins/:id/package` | 已发布包及 SHA-256 |
| `GET /api/admin/plugins` | 管理员审核队列 |
| `GET /api/admin/plugins/:id/package` | 管理员查看尚未发布的源码 |
| `PUT /api/admin/plugins/:id` | `{status,reason,updated}`；乐观并发校验 |

交付目录 `plugin-sdk` 提供可直接导入的示例包与生成脚本。SDK 基于 Electron 的本地插件机制；参考 [webContents API](https://www.electronjs.org/docs/latest/api/web-contents) 与 [Electron 安全说明](https://www.electronjs.org/docs/latest/tutorial/security)。
