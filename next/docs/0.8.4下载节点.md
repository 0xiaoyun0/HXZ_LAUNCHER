# 0.8.4 下载节点与同文件恢复

调研与实测日期：2026-10-21。原始记录：`.runtime/review084/downloads/`。本次使用 research 的主来源核验和 diagnosing-bugs 的复现流程；所有公网结果来自当前一台设备，不代表世界各地同时可用。

## 结论与计数

登记 **34 个不同文件主机**，另列 **5 个元数据主机**，元数据不计入下载节点。地区不同的 Google Central 三个端点分别计数，但明确共享运营方；Eclipse 新旧路径、GH-Proxy 的 `.org`/`.com`、重定向最终存储域名均不重复计数。

这满足跨不同文件用途的 30 个来源登记数量，**没有证明任意同一个文件有 30 个可用副本，也没有证明 34 个节点当前全部可达**。Minecraft 元数据指定的 Gson 2.10.1 文件有 20 个已完整下载并比对官方 SHA1 的候选；Fabric/Quilt、authlib、游戏本体、资源对象各有适用备用。Azul Java 暂无已核实的同版本备用，不能任意换厂商、Java 版本或架构。

最后一次全表探测（`node-probes.json`，01:48 UTC；BMCLAPI 文件样本 01:49 UTC 单独复查）为 32/34 个文件样本收到成功响应头，5/5 个元数据样本成功。文件样本失败：NeoForge 6 秒超时、MCIM HTTP 503。上一轮记录 `node-probes-31.json` 曾有网易、GitHub、ghproxy.net 超时，这轮恢复，显示单机网络随时间变化。BMCLAPI 初次元数据样本超时，改用真实 Maven 文件样本复查成功。界面展示“样本可达/本次失败/尚未检测”，不将探测结果变成永久禁用，也不把响应头探测当作完整文件哈希验证。

## 恢复与安全边界

默认 official 模式先尝试原始官方 URL，在当前文件的有界尝试失败后依次转下一个适用来源。修复了“上一文件官方故障产生的主机冷却把下一文件官方排到镜像之后”的错误：新文件仍先试官方；同一轮不会在尚有备用未试时跳回官方。全部候选失败后，现有总重试预算仍可发起下一轮（含可重试的官方来源）；Retry-After 冷却和永久错误排除继续生效。用户明确选择的 domestic 模式仍兼容原有镜像偏好和有限并发。

Maven 保持完整 group/artifact/version/classifier/extension 路径。Central 镜像只用于 Central 或 Minecraft 依赖，Fabric、Forge、Quilt、NeoForge 仅按明确的类型代理扩展，绝不把其专属坐标泛发到所有 Central 镜像。Java/Android 原 12 来源截断上限增为 32，避免已核实的后段备用丢失；独立 HTTP 连接上限没有放大。

可用性只能尽力恢复：断网、全部相关域名被封锁、作者删除文件、权限失效或所有副本缺失时会给出真实失败，不能承诺“任意网络必定成功”。有权威哈希的传输继续保留可校验的分段/部分进度，在相同目标下续传；不能把未校验的部分文件视为安装成功，也不能为求成功静默改成另一个版本。

带 query、userinfo、fragment、非默认端口或非 HTTPS 的地址不扩展到其他运营方。保持跨源敏感请求头隔离、取消传播、临时文件及完整哈希验证后原子提交。authlib 的 `latest.json` 校验元数据仍只取发布者原站，镜像仅提供同版本 JAR；不会让镜像同时决定待校验内容和预期哈希。公网记录只存普通样本 URL/最终主机，不存 GitHub 最终签名查询参数、令牌或凭据。

CurseForge 2026-07-16 起要求下载 API key，不能把 `edge.forgecdn.net` 等匿名地址添加成新公共节点，也不能将原站 key 转发给镜像绕过权限。现有适用映射继续遵守原有权限处理。
