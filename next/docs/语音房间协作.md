# 语音房间协作 · 0.8.0

同一语音房间内提供自由聊天、课堂、自习、互助四种模式。首先进入的有效房间成员担任主持；主持离开后交给仍在线的成员，也可以主动交接。课堂模式由主持人允许发言，服务端同时限制 Opus 转发，不能只靠界面静音。自习支持 15/25/45/60 分钟共同计时，互助按举手顺序展示。

## 屏幕分享

电脑用户主动选择一个窗口或屏幕后开始分享。默认 720p、10fps，上限 1080p、15fps，单连接视频码率上限 1.2Mbps；每次一个分享者、最多四位观众。画面采用 WebRTC 点对点传输，社区只交换连接信息，不传输和保存视频，不启用 TURN。不能保证所有 NAT 或运营商网络都能直连，失败会提供重新连接入口。

手机端可以观看。离开本页停止分享或观看，离开语音/断线会清理连接。服务器检查同一设备的当前语音成员身份，不接受仅凭用户 ID 进入别的房间；信令按观看连接版本隔离，避免重连时混入旧协商。长时间未续期自动回收。

窗口选择仅来自 Electron 主窗口的受限 IPC；一次选择只有十秒有效期，首次捕获后即失效。远程 iframe 不能调用主窗口 IPC，也不能获取屏幕授权。摄像头请求保持拒绝。

## 字幕与翻译

所有客户端可发送实时文字字幕，最多 500 字，房间内只保留最近 40 条/5 分钟，不写入聊天记录。课堂模式仍需要发言许可。

具有本地识别能力的运行时提供中文语音字幕入口；首次需要用户确认下载模型，只进行本地识别，识别文字才发送至房间。静音时停止识别，识别失败三次停止尝试。没有该系统能力时保留输入字幕，不偷偷使用云端识别。

提供本地 Translator API 的运行时可选择原文和目标语言翻译某条字幕。首次下载语言模型需要用户主动点击。翻译结果只在本机显示，保留原文。此能力在当前 Electron 44 x64 中可检测到；Electron 22 ia32 不提供，Android WebView 不作为已支持承诺。模型下载和识别效果仍需设备与网络条件，原生能力检测不能当成实际语音识别验收。

## 接口与边界

`GET /api/voice-tools/state?client=<当前语音连接 ID>&after=<信令序号>` 返回房间模式、成员、举手、计时、短期字幕与发给自己的信令。

`POST /api/voice-tools/{mode,host,hand,speaker,timer,caption,screen/start,screen/stop,screen/watch,screen/signal}` 均携带当前连接 ID，分享协商另携带分享 ID 和本次观看连接版本。修改主持设置只允许当前主持。读取/写入分别限频；信令仅允许媒体协商，拒绝数据通道 SDP。

参考官方接口：[Electron desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer/)、[Web Speech 本地处理](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/processLocally)、[本机翻译 API](https://developer.chrome.com/docs/ai/translator-api)。

## 验证

- 后端两项真实 HTTP/WebSocket 测试覆盖跨房间/跨设备拒绝、角色控制、字幕隔离、信令游标、观看登记、主持交接、课堂下真实二进制语音转发限制。
- 两个浏览器通过真实社区信令完成生成画面的 WebRTC 传输、重连和停止；手机网页 390/320px、桌面浅色和暗色 22px 截图已检查。使用生成画面和模拟 Android 桥，不冒充安卓实机或跨运营商结果。
- Electron 44.3.0 x64、22.3.27 ia32 在本机实际获取并立即释放屏幕流，重复使用选择被拒绝；未录制或保存桌面画面。32 位测试运行于 x64 Windows，并非 Windows 7 实机。
