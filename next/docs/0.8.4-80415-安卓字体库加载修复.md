# Android 80415：Java 字体依赖初始化

80414 的 vivo V2408A / Android 16 诊断显示，游戏已进入 NeoForge 模组初始化阶段，随后 ModernUI 的 `icyllis.modernui.text.Typeface` 初始化失败。真正的底层异常为 `libfontmanager.so` 加载时找不到其依赖 `libfreetype.so`。代码 255 是 Java 主动退出后的进程状态，不能单独当作内存或渲染器故障。

## 修复依据与行为

- 核对已发布运行模块中的 Java 21 和 Java 25：均包含 `libfreetype.so`，其 SONAME 为 `libfreetype.so`。字体管理库依赖 FreeType、AWT、Headless AWT、Java 和 JVM；并非下载遗漏。
- 对照 FCL 固定源码提交 `efe4dcc5dbc78c55be177c330239e12845ae7ccf` 的 `FCLauncher.setUpJavaRuntime`：使用绝对路径预加载原生依赖。Android ART 已创建服务中的链接器命名空间不会仅因修改 `LD_LIBRARY_PATH` 就找到所有相邻的 JRE 库。
- HXZ 独立游戏进程先加载现有核心 Java 库，再依次加载 `libfreetype.so`、`libawt.so`、`libawt_headless.so`、`libfontmanager.so`。在 `JNI_CreateJavaVM` 前完成，依赖缺失会记录实际路径及链接器错误。
- 独立安装处理器不使用这条字体初始化路径；保留认证代理预加载和 JNI exit 回调。无需禁用 ModernUI，也不修改模组 JAR、账号或存档。

参考：[FCL 原生依赖初始化源码](https://github.com/FCL-Team/FoldCraftLauncher/blob/efe4dcc5dbc78c55be177c330239e12845ae7ccf/FCL/src/main/java/com/tungsten/fclauncher/FCLauncher.java)。

## 定向验证

先将真实 `hxz_jvm.cpp` 接入模拟关闭本地库搜索路径的链接器：修复前复现 `libfreetype.so` 缺失，修复后通过。覆盖单/双认证代理、无代理、JLI 缺失、代理缺失或损坏、字体库缺失、纯安装处理器，以及 Java 主动退出时跳过全局析构，共 9 项。

诊断提示包含 19 项判断，新增真实字体异常、缺失 AWT 依赖及正常字体加载日志的区分。完整 Android 签名构建用于验证 ARM64 编译和打包；未进行手机实机运行或帧率验收。
