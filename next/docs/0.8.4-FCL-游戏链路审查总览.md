## 图形性能：确认的差距

主审查另读取固定 FCL 的 `FCLauncher.java` 渲染环境部分、`egl_bridge.c` 驱动与上下文部分、`ctxbridges/gl_bridge.c` 和 `ctxbridges/osm_bridge.c` 全文、`RendererManager.kt` 全文、Vulkan 探测和 `JVMActivity` 分辨率/刷新部分。相关结论：

1. FCL 的 Zink 主路径通过 Mesa EGL/Kopper 向窗口提交；HXZ 使用隔离的 Java 进程、OSMesa 与共享像素通道。二者架构不同，不能替换一个渲染器名称就获得同等速度。
2. HXZ 的 80410 已有真实 GPU 探测、软件驱动识别、按实际路径限制默认分辨率、Surface 缓冲复用和连续帧整块呈现；80411 保留这些改进。
3. 临时将 OSMesa 重绑到空闲共享槽，调用 glFinish 再恢复缓冲，存在游戏先行 flush 或用户 FBO 导致新槽未写入的源码反例。本轮保留正确的同步与复制，未冒险删除。
4. FCL 的自定义 Turnip 装载依赖 Android linker/namespace 等特定实现；其 AWT、JSound 和 SDL/LWJGL 补丁也不是普通 OpenAL/GLFW 库可以替代。未把这些代码或二进制混入 HXZ。

下一阶段真正的渲染提升应独立设计跨进程窗口/硬件缓冲呈现，并验证同步、窗口重建、后台恢复和多设备 GPU。尚未完成这条架构改造；本轮不承诺已达到 FCL 帧率。
