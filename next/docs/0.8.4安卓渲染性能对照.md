## 先做什么

1. **先记录实际 GPU 与阶段耗时。** 将请求的渲染器、实际 `GL_VENDOR / GL_RENDERER / GL_VERSION`、Vulkan 物理设备名与类型、最终分辨率放入诊断；分别统计 `glFinish`、像素复制、Surface lock/post、发送成功和丢帧次数。不能仅凭清单中的 `zink` 判断已经使用硬件 GPU，也不能在没有日志时断言用户正在使用 softpipe。
2. **短期优化现有独立桥。** 只在 Surface 实例或尺寸/格式改变时设置 buffers geometry；连续行布局可以整块复制；提供便于比较的低分辨率档位。对双槽共享帧缓冲的掉帧与 ACK 统计后，再考虑直接把 OSMesa 输出绑定到安全持有的共享槽，减少一次复制。这些均需验证生命周期、stride 与背压，不应通过删除同步或覆盖未 ACK 帧取得表面提速。
3. **中期建立独立的 Mesa EGL/Kopper 直接呈现。** 官方 FCL 当前的内置 Zink 已不是 OSMesa 像素桥，而是 Mesa EGL/Kopper。HXZ 可从官方 Mesa 固定版本独立构建同类能力，自己实现桌面 OpenGL 上下文与 Surface 生命周期；现有 EGL GLES3 分支与当前 Mesa 构建不足以直接承担此任务。

以上是基于源码的优先顺序，不是实测 FPS 承诺。不要先通过增加堆、盲设线程数或伪报 OpenGL 版本代替渲染链路诊断。

### GPU、softpipe 与 Vulkan/Turnip

- HXZ 明确设置 `GALLIUM_DRIVER`；只有选中 softpipe 时才额外设置 `LIBGL_ALWAYS_SOFTWARE=1`。因此源码没有显示“所有设备强制软件渲染”。不过，Android Vulkan feature flag 不能证明所选驱动可创建当前游戏所需的 OpenGL 上下文。[HXZ L115–140](E:/hxz_next/mobile/android/app/src/main/java/top/hxzmc/community/game/GameRuntimeActivity.java:115)
- HXZ 当前 Mesa 构建同时包含 zink、softpipe，禁用 LLVM、EGL、GBM，Vulkan drivers 为空。它没有自己构建 Turnip；更换驱动需要完整、可复现的驱动加载方案。不能通过设置一个 Turnip 名字获得驱动。[构建脚本 L18–23](E:/hxz_next/mobile/runtime/upstream-build/build-mesa.ps1:18)
- FCL 将 `DRIVER_PATH / DRIVER_LIB / DRIVER_GPU` 和 system-driver 选择传给 native，定制路径通过 GPU 家族检测后加载；系统路径使用 Vulkan loader。默认 Adreno 家族门控要求 Qualcomm/Adreno，Mali 有独立分支。[FCLauncher L210–219](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/java/com/tungsten/fclauncher/FCLauncher.java#L210-L219)、[system 选择 L246–248](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/java/com/tungsten/fclauncher/FCLauncher.java#L246-L248)、[GPU 检查 L129–138](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/jni/egl_bridge.c#L129-L138)、[加载 L188–256](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/jni/egl_bridge.c#L188-L256)。
- FCL 的检测器实际枚举 Vulkan 设备、扩展与特性，并将检测记录关联到所选驱动。其检测器选择最高 API 版本的设备；这属于兼容性检测策略，不等于自动选出了最快 GPU，也不证明运行时使用同一物理设备。HXZ 应记录并验证实际选中设备，避免把 CPU Vulkan 实现当作 GPU。[枚举和选择 L320–378](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/jni/vulkan_check/vulkan_checker.c#L320-L378)、[缓存键 L141–156](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/java/com/mio/device/VulkanCheckManager.kt#L141-L156)。
- Mesa 官方说明 Zink 把 OpenGL 转为 Vulkan，功能级别取决于 Vulkan 驱动能力；Turnip 属于 Adreno 驱动，应按具体 Mesa 版本的设备表核对支持范围。不要对 Mali 或所有 Adreno 机型统一强制 Turnip。[Mesa Zink](https://docs.mesa3d.org/drivers/zink.html)、[Mesa Freedreno/Turnip](https://docs.mesa3d.org/drivers/freedreno.html)

建议最小探测流程：在隔离的短生命周期执行器里加载目标库，创建实际目标版本的 OSMesa 上下文，读取 GL 字符串并完成一帧；同时枚举 Vulkan 设备并记录 vendorID/deviceID/deviceType/API 版本。选择结果按模块哈希、系统版本和 GPU/驱动信息缓存。若自动退回 softpipe，应明确显示原因和诊断，不能把它描述为硬件加速成功。当前没有实机证据支持某一驱动一定更快。

### OSMesa、复制与 EGL

HXZ 每帧先 `glFinish`，再调用 frame sink。sink 找不到空闲槽时丢帧，但这个判断发生在 `glFinish` 之后，因此呈现跟不上时仍可能支付 GPU 完成/读回代价；host 接收一帧后复制到 `ANativeWindow`，完成后才 ACK。该结构有背压保护，不能简单移除。[HXZ swap L449–456](E:/hxz_next/mobile/runtime/native/hxz_glfw.cpp:449)、[sink L104–114](E:/hxz_next/mobile/runtime/native/hxz_ipc.cpp:104)、[host L86–96](E:/hxz_next/mobile/runtime/native/hxz_ipc.cpp:86)

FCL 旧 OSMesa 桥将 `OSMesaMakeCurrent` 的输出指向 native buffer，并使用 `OSMESA_ROW_LENGTH` 处理 stride；swap 仍先 `glFinish` 再 post。这说明“OSMesa 是软件 GPU”和“删 glFinish 就能优化”都不是有效推论。OSMesa 是输出接口，实际 Gallium driver 才决定渲染实现；在读取/发布像素前必须保留正确的完成同步。[FCL OSMesa 绑定 L74–82](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/jni/ctxbridges/osm_bridge.c#L74-L82)、[swap L111–126](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/jni/ctxbridges/osm_bridge.c#L111-L126)。

由当前两次显式 RGBA 复制可计算：1920×1080 每帧单份约 8.29 MB，两次复制的有效像素数据量为 16.59 MB；60 帧时约 995 MB/s。该数值不含内存读取/写入的双向总线流量、GPU 读回、SurfaceFlinger 或缓存行为，是数量级分析，不是设备测量。缩放比例从 70% 改为 50%，像素数理论上约为原来的 `(50/70)^2≈51%`，前提是未触及最小/最大边限制；不能据此承诺 FPS 翻倍。

独立优化的落点：

- 现有 `hxz_present_frame` 每帧调用 `ANativeWindow_setBuffersGeometry`；将该设置绑定到 Surface generation 与渲染尺寸变更。对失效 Surface 仍需重试，不能只按宽高缓存。
- 统计 `glFinish` 与 present 耗时后再选择优化：若前者高，优先分辨率/驱动/直接呈现；若后者高，优先 geometry、复制、队列与帧率配合。
- 直接输出到共享槽可去掉 vector→共享内存复制，但必须在 draw 开始前持有可写槽，并保持 OSMesa 指针、stride、上下文线程与 ACK 生命周期正确。没有空闲槽时必须保留安全的退路。
- EGL/Kopper 路线需要自己解决桌面 GL 配置、Mesa Android WSI、GPU buffer/surface 归属和跨进程生命周期。当前独立游戏子进程只拿到像素共享内存，没有直接 Android Surface；不能仅添加 `eglSwapBuffers` 即宣称已完成直接呈现。

上述建议分别由 [当前 geometry/复制实现](E:/hxz_next/mobile/runtime/native/hxz_glfw.cpp:267)、[IPC 初始化与帧传输](E:/hxz_next/mobile/runtime/native/hxz_ipc.cpp:73)、[当前 EGL 限制](E:/hxz_next/mobile/runtime/native/hxz_glfw.cpp:343)、[Mesa 构建关闭 EGL](E:/hxz_next/mobile/runtime/upstream-build/build-mesa.ps1:18) 推导，均须实机验证。

### 线程、帧率与环境变量

FCL 有条件地将启动 Java 线程设置为 `Thread.MAX_PRIORITY`，并把 `FORCE_VSYNC` 设为 false；它并未由这些代码保证所有渲染线程达到某个调度优先级。[启动线程 L552–584](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/java/com/tungsten/fclauncher/FCLauncher.java#L552-L584)、[环境配置 L219](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/java/com/tungsten/fclauncher/FCLauncher.java#L219)。HXZ 的单线程 Executor 负责准备并等待独立游戏进程；给该 Executor 提高优先级不等于优化子进程渲染线程。[HXZ L26](E:/hxz_next/mobile/android/app/src/main/java/top/hxzmc/community/game/GameRuntimeActivity.java:26)、[启动子进程 L115–119](E:/hxz_next/mobile/android/app/src/main/java/top/hxzmc/community/game/GameRuntimeActivity.java:115)

本次核对的 FCL 启动配置没有给出可直接照用的 `mesa_glthread`、`LP_NUM_THREADS` 或 `ZINK_DESCRIPTORS` 性能配方。HXZ 构建禁用了 LLVM，不能把 LLVMpipe 线程设置当成 softpipe 优化。应先测 CPU 核心占用与 render thread 时长，再做单变量实验。

FCL 会写 Mesa GLSL cache 目录及 GL/GLSL version override；这是它的兼容性策略，不是 HXZ 获得真实功能或性能的证据。Mesa 官方说明 `MESA_GL_VERSION_OVERRIDE` 改变报告版本，`MESA_NO_ERROR` 关闭错误检查且对错误 API 使用产生未定义行为；不能盲抄为默认优化。[FCL L380–385](https://github.com/FCL-Team/FoldCraftLauncher/blob/a36e1e42292d6a67c93be0dafbfdceff01823e71/FCL/src/main/java/com/tungsten/fclauncher/FCLauncher.java#L380-L385)、[Mesa 环境变量](https://docs.mesa3d.org/envvars.html)。缓存路径可独立实现，但应先确认当前固定 Mesa 版本支持的变量、可写性与冷热启动差异。

## 实机验证清单与判定

同一台设备、同一个游戏/模组版本、同一世界同一视角，先预热再采集至少 60 秒；记录冷启动与热启动，区分着色器编译卡顿和稳定帧率。每组仅改变一个变量：现有分辨率与低档分辨率、系统 Zink 与已经验证支持的替代驱动、现有复制与优化复制。

至少记录：实际 GL/Vulkan 驱动信息、渲染像素数、游戏产帧数、宿主发布帧数、丢帧数、`glFinish`/copy/lock/post 的平均及 P95 耗时、CPU 使用率和温度。若游戏产帧高而发布帧低，应优先处理呈现；若软件 driver 被实际选中，先恢复可用 GPU 路径；若 GPU draw/完成等待主导，复制优化不能承担主要收益。

本次尚未确定：用户设备实际 GPU/驱动、实际 GL_RENDERER、帧率数值、卡顿发生在加载还是稳定场景、降温后的持续性能，以及哪一阶段主导。不能把源码瓶颈候选写成已测根因。
