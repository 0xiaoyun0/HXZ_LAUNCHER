# 0.8.1 音乐档案适配

用户要求：LINKING 剧情达到相应节点后，将整个音乐页面迁入 Rhine Music Database 的界面与交互，再逐项接回幻想镇原有音乐功能。不是对经典卡片的换色。经典卡片、保存布局和音频播放状态继续保留。

## 来源

- 音乐界面、原场景行为：https://github.com/MikeQu223/Rhine-Music-Database ，提交 `36aa998228f63d7ab5d43484102aaccbccf7fb02`。
- 同源 Web 场景实现与模型：https://github.com/LBEILC/RhineLabUI ，现有 LINKING 固定版本见 `apps/linking/UPSTREAM.md`。
- 原项目使用 Qt/QML/C++，本适配采用 Web 页面与隔离的 Three.js 场景，嵌入启动器。Qt 进程、原独立播放器自动更新器、账号存储与网络代理不引入启动器；播放与账号统一使用已有服务。
- 原始 MIT 许可、模型来源、Three.js 许可随 `public/licenses` 分发；不添加上游字体、音乐素材或第三方账号凭据。

## 界面到功能的对应

| 原项目区域 | 幻想镇接口与行为 |
| --- | --- |
| 三维唱片资料库 | 当前音乐库条目对应唱片索引；呼吸、悬停、选取波纹、抽取与详情检视使用场景层，不能改变页面几何 |
| 曲库列表及分组 | `music.items`；按已有歌手、专辑资料分组，不编造缺失资料 |
| 曲目详情 | 真实标题、歌手、来源与格式；播放调用 `playTrack` |
| 搜索入口 | 复用 `music.search` / `music.add`，搜索和错误状态仍由原页面管理 |
| 本机曲库 | `music.list`、`music.import`、`music.remove`；删除保留原确认流程 |
| 歌单导入 | `music.playlist`；公开歌单链接、数量、重复与不可用结果继续显示 |
| 播放控制 | `toggleMusic`、`nextTrack`、`seekMusic`、`setMusicVolume`，同一音频实例，不在换肤时重建 |
| 当前播放列表 | 显示已有引擎的音乐库循环序列；没有独立待播增删 API，不伪装成另一套队列 |
| 歌词 | 复用 `LyricsCard` 的获取、匹配、点击跳转、悬浮/桌面歌词与刷新能力 |
| 账号 | `NeteaseAccount`；社区授权和登录风险确认继续有效；不读取/共享其他用户账号 |
| 一起听 | 使用原语音房间及 `shareMusic`，加入/离开/停止分享沿用已有逻辑 |
| 设置 | 现有主题、播放顺序、音量、动效、歌词与经典外观切换；不提供无接口的假选项 |

这是整体视觉与交互迁移，服务能力仍以幻想镇现有接口为准。原项目的 QQ/酷狗在线服务、平台歌单写入、独立账号与更新器未接入，不显示为已支持功能。

## 性能与验收

音乐主页面按需加载场景，引擎不引入 LINKING 活动状态或全局 DOM 初始化。减少动态效果时静态绘制；切出与窗口隐藏时停止场景刷新；销毁时释放模型、材质、渲染器和事件。所有音频保持原生命周期。

完整场景保留原 GLB 外壳，按 DiscGeometry / RhiScene 的形状和尺寸替换 CD 内芯，支持真实封面贴图。每张唱片采用原 8 秒/13 秒异相浮动，保留悬停、选择波纹、抽取、拖拽和详情旋转。首次加载先完成稳定镜头与首帧再显示；画质提供性能、均衡、原版三档。WebGL 的材质实现不承诺与 Qt 逐像素相同。

验收应分别说明隔离界面、真实社区 API 与真实音频播放的范围，不能以假音频桥通过宣称网络播放已验证。截图必须查看中间帧、稳定帧和窄窗口，不仅检查动画结束后的坐标。
