# 安卓 80418：可直接发送的卡顿诊断

80417 的实时诊断默认展示所有线程。大量普通线程会把渲染或加载线程挤出前 100 个；两次快照共用字符上限，也可能让第二次缺少关键线程。报告过长，玩家无法直接发送。用户提供的末尾 `ScheduledThreadPoolExecutor.take` 堆栈只说明一个工作线程在等待任务，不能据此判断游戏卡死原因。

## 修改

- 默认显示、复制不超过 4,800 个字符的报告，包含版本与设备、两次关键线程、锁持有者、最近异常上下文和日志末尾；刷新后回到报告开头。
- 完整脱敏诊断保存在应用私有缓存 `game-live-diagnostics/live-latest.txt`，长按“复制诊断”仍可复制全部。采集未完成时禁止复制半成品。
- 实际游戏 JVM 优先记录渲染、主线程、模组加载和相关锁持有者。每次快照独立使用 56,000 UTF-8 字节的预算，总响应低于 Android 读取上限；不再按普通线程名称截掉关键线程。
- 可用时读取 JVM 原生提供的锁循环、锁持有者及累计 CPU 时间；接口不可用则降级为线程快照。不会把等待、两次堆栈相同或零 CPU 变化直接认定为死锁。
- 仍由玩家手动采集，不持续分析、强制结束游戏或修改模组。

## 验证与限制

`scripts/tests/android-network084.mjs` 在真实桌面 HotSpot JVM 中创建 160 个等待线程及一个已知 Java 锁循环；旧版本稳定漏掉 Render thread，修订后两次快照均保留关键线程、锁持有者及 JVM 检出的循环，验证 UTF-8 输出预算。

`scripts/tests/android-live-diagnostics084.mjs` 覆盖大量线程、超长模组清单和日志下的分享长度、两次关键线程、异常与末尾保留、缺少响应降级，以及原生弹窗的脱敏/复制接线。`android-crash-diagnostics084.mjs` 继续覆盖既有诊断脱敏与崩溃证据。

这是诊断采集和分享修复。尚未获得该手机的完整渲染/加载线程证据，不能宣称已修复模组加载停滞；也未进行手机实机运行验收。无需重新下载整合包或运行模块。
