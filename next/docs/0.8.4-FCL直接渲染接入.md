# Android 80412 · FCL 直接渲染接入

用户于 2026-10-22 明确授权使用 FCL 对应源码，取代此前只参考、不移植的约束。
本次实际引入渲染代码；此前 80411 的“独立实现、未复制”仅描述此前构建。

## 来源与范围

- FCL 固定提交：`a36e1e42292d6a67c93be0dafbfdceff01823e71`。
- 直接接入 `ctxbridges/gl_bridge.c/.h`、`egl_loader.c/.h`，代码在
  `mobile/runtime/native/fcl/`；对接层为 `hxz_fcl_render.cpp`。
- NG 二进制来自同一 FCL 提交的 `FCL/libs/NG-GL4ES-release.aar`，ARM64
  SHA256：`cfee8bf238fc508478454c2daf19b518182827b426d5d4556f1e93a0ad348ea7`。
- 上游 NG 说明与源码阅读基准：`FCL-Team/NG-GL4ES` 提交
  `472f55e549e2bc76c87454905db52661c3cf57a9`。该阅读基准并非二进制构建版本声明。
- 不引入整个 FCL 启动器、不替换社区账号、不要求第二个 APK。现有安装器和
  HXZUP 保留，以免渲染修改影响已经完成的安装修复。

## 数据路径

社区进程提供登录 → `:game` Activity 安装/显示控件 → 私有 Binder 把 Surface
交给 `:jvm` 服务 → 新原生线程启动 HotSpot → HXZ GLFW ABI 调用 FCL EGL
桥接和 NG-GL4ES → GPU/EGL 直接显示。

独立同 UID socket 在直出模式只传输入、焦点、尺寸和鼠标捕获状态；不创建
共享像素内存、不读回 GPU 画面、不逐帧向 UI 进程复制。旧 Zink/softpipe 模式
保留为用户手动兼容选项，使用旧像素路径，不能混称为直接渲染。

## 适配差异

- FCL 旧桥接依靠全局窗口和固定 750 ms 延迟；这里通过互斥锁及持有的
  ANativeWindow 引用串行交接，Surface 消失时换到 pbuffer，恢复后重建窗口。
- 使用 ES3 EGL config。NG 的桌面 OpenGL 目标配置为 3.3，对应当前 Minecraft
  要求；这是 GL 转译层，不把手机 GLES 原生能力误报成桌面显卡能力。
- EGL 核心符号先从库解析，再用 eglGetProcAddress，缺失时明确失败。
- 使用 FCL 的 loader-path 更新方式；没有移植私有命名空间绕过、全局信号
  处理器清空或通用 exit hook。游戏服务独立退出，社区与诊断界面继续存活。
- Android manifest 禁用原生堆指针标签；安装器独立 exec 原有兼容保护继续保留。
- APK 桥接为 16 KiB 对齐，但上游 NG/既有 Java 仅 4 KiB；仍保留页大小检测。

## 验证与边界

`node mobile/runtime/test/fcl-surface084.mjs` 执行真实导入的 C 桥接，mock EGL 和
Android 窗口，检查替换/销毁/恢复、坏 Surface、初始化失败和引用清理。

`node mobile/runtime/test/hxz-glfw-host084.mjs` 执行真实 GLFW 适配层，检查 MC
3.2/3.3 请求、240 次向 FCL 委派的直接提交、无 CPU 帧缓冲、上下文释放和
输入回归。完整 Android Release 编译与签名另外验证。

未进行实机游戏测试，未测量 FPS，未证明所有 GPU/模组组合均可用；设备上的
图形初始化与游戏日志记录实际 GL_VENDOR、GL_RENDERER、GL_VERSION。
