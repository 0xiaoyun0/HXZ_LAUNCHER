## 独立构建与 ABI 审计

构建入口为 [`mobile/runtime/upstream-build/build.ps1`](../mobile/runtime/upstream-build/build.ps1)，CMake wrapper 和 libffi Android 配置为同目录自写文件。它编译固定上游 C 源，不编译任何启动器 glue。配置使用 NDK r30、CMake 3.22.1、Ninja、Release、ARM64，显式设置 16 KiB max/common page。并发限制为 2。OpenAL 采用 `c++_static`，同时保留其 fmt/pffft/BSD/运行库相关许可；Clang21 编译 fmt 11.1.1 时通过编译参数 `-include stdlib.h` 解决标准声明缺失，没有修改上游源码。

已完成以下本机静态检查：

- 两版 core/OpenGL/STB/TinyFD、OpenAL 与 libsync 交叉编译成功；所有 LOAD 的 `p_align` 为 `0x4000`。
- 比较官方 Java class 的 native 方法与动态导出，Android/Linux 所需入口全部存在；Windows WGL、macOS 与 FreeBSD 专属类从目标平台覆盖范围排除。3.4.1 同时检查 `META-INF/versions/25` 的 JNI 类。
- `liblwjgl.so` 的回调依赖仅 `org.lwjgl.system`、标准 Java Thread 和 libffi；没有启动器 CallbackBridge 或 FCL Java 类依赖。3.3.3 使用 Callback handler，3.4.1 使用 Upcalls handler，不可混装。
- core/OpenGL/STB/TinyFD 的 DT_NEEDED 仅 `libdl.so/libm.so/libc.so`；OpenAL 另有 `liblog.so`。libsync 只有 libc 家族符号，不链接私有 Android 平台共享库。

JNI 与 ELF 证据在 `.runtime/hxz-runtime-upstream/research/`。这不能证明图形上下文、声音、JIT 或触控已经在 Android 设备运行。

**双虚拟机约束：** `liblwjgl.so` 的 `JNI_OnLoad` 缓存传入的 `JavaVM*`，回调线程由它 AttachCurrentThread。必须由 HotSpot 的 `System.load` 加载，不能先从 ART 加载。独立 Activity/native glue 只通过自写 C ABI 接口交接窗口与输入。不要设置 `POJAV_RENDERER`：Android fork 的 Java GL 分支会反射查找启动器式 `GLFW.mainContext`；本项目使用官方 Java JAR、标准 GL 初始化与自写 GLFW C ABI。

当前不供应 jemalloc native，启动属性使用 `-Dorg.lwjgl.system.allocator=system`。TinyFD 库虽可装载，其桌面对话框后端不能自动变成 Android UI；需要 Activity 自己的文档选择器与提示框行为。OpenAL 可通过 `org.lwjgl.openal.libname` 指向所供应的 `libopenal.so`。

## Mesa 独立构建结果

正式输入来自 [Mesa25.3.4 官方源码归档](https://archive.mesa3d.org/mesa-25.3.4.tar.xz)，提交 `23e3445940104465152dcfc1d5952d09d3ba7b37`。25版已删除 OSMesa，因此仅从 [官方24.3.4固定提交](https://gitlab.freedesktop.org/mesa/mesa/-/tree/769e51468b49b2a42f0a0eaf71cf9eed5ff4e5de) 恢复 OSMesa header、frontend 和 target 共9个文件；逐文件 URL/SHA256 已锁。所有这些文件保留原 MIT 头。准备脚本自写了 Mesa25 API/构建适配，禁用不需要的 KMSRO、私有 libcutils tracing，以公开 `__system_property_get` 代替 Android 私有 property_get。没有使用其他启动器图形桥，也没有使用 Vera 补丁树作为最终输入。

可复现入口为 `mobile/runtime/upstream-build/build-mesa.ps1`；`prepare-mesa.py` 先验证源码 SHA256，再应用明确适配。配置为 `gallium-drivers=zink,softpipe`、OSMesa 开启、LLVM/EGL/GLX/GBM/Vulkan驱动构建关闭；Zink 使用系统公开 `libvulkan.so`。实际驱动只有 **softpipe、zink**，没有 llvmpipe、freedreno、GL4ES 或 VirGL。源树未修改文件仍来自25.3.4官方归档。

产物 `renderers/osmesa/libOSMesa.so` 为20,604,664字节，SHA256 `a1bd589ce45971a06847b7b22710389d3bb86500ca26269bd0fd7a3e7219f1eb`。所有 LOAD 为16KiB，DT_NEEDED 仅 `liblog.so/libz.so/libm.so/libdl.so/libc.so`。标准 OSMesa API 导出存在，无 JNI Java 类依赖。原生 TLS 使此构建要求 **Android API29或更高**。构建成功及 ELF 审计不能替代设备上的 OpenGL 功能、Vulkan 兼容性和性能验证。

官方 LWJGL **3.3.3** 使用 `-Dorg.lwjgl.opengl.libname=<绝对libOSMesa.so路径>`；该版没有 contextAPI/osmesa.libname 配置。**3.4.1** 使用 `-Dorg.lwjgl.opengl.contextAPI=OSMesa`、`-Dorg.lwjgl.opengl.osmesa.libname=<绝对路径>`。两版 Linux FunctionProvider 均有 `OSMesaGetProcAddress` fallback，不需要虚构 GLX 入口。已从两个固定版本的官方 Maven sources JAR 核对，不能用主干替代版本审计。自写 GLFW C ABI 层创建真实 OSMesa 离屏上下文并把缓冲复制到 ANativeWindow。

先前 [Vera-Firefly/android-mesa-build v25.3.4](https://github.com/Vera-Firefly/android-mesa-build/releases/tag/v25.3.4) 发布包仍保留为研究候选：其脚本标签与二进制源码版本不能对应，且移动补丁仓库许可范围不明确。该旧候选在锁内保持 excludedFromStage；正式输入完全由上面固定的官方源码重建。

## 分发与运行边界

JRE21 的 38 个 ELF 都含 4 KiB LOAD，JRE25 的 43 个 ELF 中 42 个如此。因此当前输入只覆盖 **Android10的API29及以上、4 KiB page 的 Android ARM64 系统**，不能宣称支持 16 KiB page。即使所有 HXZ 自建基础库已对齐，JVM 仍需另外重建或取得可核验的 16 KiB 发布版。

Java 的完整 `legal/`、LWJGL BSD3 与内嵌依赖许可、OpenAL LGPL2+ 与静态依赖通知、AOSP Apache2 NOTICE 均随输入保留。对于 GPL/LGPL 组件，还需在实际对外分发时提供对应源码归档、适用构建脚本和说明。源包及 SHA256 已锁定于本地 downloads，不可只保留一个会过期的 CI 链接。某些下载采用镜像传输，身份仍以原始拥有者 URL、固定 commit 和 publisher SHA256 为准，镜像不是来源拥有者。

## JNA、FreeType 与26.2补充审计

Minecraft26.2的 [官方版本JSON](https://piston-meta.mojang.com/v1/packages/bdfd9856166b7171857c491f15479762f3abda99/26.2.json) 明确使用 JNA5.17.0；1.21.1使用5.14.0。两版 native 分别从 [官方Maven5.14.0 AAR](https://repo.maven.apache.org/maven2/net/java/dev/jna/jna/5.14.0/jna-5.14.0.aar) 与 [5.17.0 AAR](https://repo.maven.apache.org/maven2/net/java/dev/jna/jna/5.17.0/jna-5.17.0.aar) 的 `jni/arm64-v8a/libjnidispatch.so` 提取，和各自固定源码提交内 `lib/native/android-aarch64.jar` 完全相同。固定提交为 `c366bc4fd0c50a30ac8d2475603ec564f6611462` / `695ae749e7bfd92f88324147c5d96b7129efec3e`。所有69个JNI方法均有导出，JNI_OnLoad使用标准JavaVM接口，无启动器或ART类依赖。DT_NEEDED只有c/dl/m；5.14.0的LOAD为64KiB，5.17.0为16KiB。设置 `-Djna.boot.library.path=<jna对应版本目录>`，保留Minecraft下载的匹配标准Java JAR。Android AAR的classes.jar仅用于审计，不替换标准JAR。JNA选择Apache2许可，libffi保留MIT。

26.2核心使用官方 `lwjgl-3.4.1-unsafe.jar`，SHA1 `129e06a04f93992cb2a45172435b21fc4b60dd7d`，2,142个目标平台JNI方法均被已构建core导出覆盖。其FreeType使用独立上游 [FreeType2.13.3](https://github.com/freetype/freetype/tree/42608f77f20749dd6ddc9e0536788eaad70ea4b5) 源码构建，210个非optional入口全部覆盖，16KiB LOAD、无额外第三方动态依赖。可复现脚本 `mobile/runtime/upstream-build/build-freetype.ps1`；模块路径 `lwjgl/3.4.1/libfreetype.so`，属性 `org.lwjgl.freetype.libname`。该软件部分基于FreeType项目（https://freetype.org），以FTL许可分发并保留完整许可。

新增shaderc/spvc/vma/vulkan官方Java JAR已固定并随模块保留，但不供应shaderc/spvc/vma native。根据 [26.2官方发布说明](https://feedback.minecraft.net/hc/en-us/articles/46690753273997-Minecraft-Java-Edition-26-2)，OpenGL仍为默认；Prefer OpenGL完全不触碰Vulkan。本项目固定 `options.txt` 的 `preferredGraphicsBackend:"opengl"`，模块明确 `vulkanGameBackend:false`。这与OSMesa内部Zink调用Android系统Vulkan属于不同层。当前自写GLFW没有VkSurfaceKHR支持，不能开放游戏Vulkan后端。
