# 0.7.0 安卓游戏适配修订

2026-10-12。用户实机反馈：小米 Pad 8 Pro，模组一服，卡在 NeoForge 安装；期望安装加速、恢复与诊断，以及更新前自动处理不兼容模组。当前无连接的 Android 设备，也没有此次手机日志，不能把本机测试等同于实体设备故障已经解决。

## 范围

- 修订原生游戏运行组件，保留 FCL 核心与 GPL 许可；必要时同步社区端的安装设置与诊断入口。
- 默认官方优先、32 并发；复用已有校验、重试和缓存，避免无效下载和 Java 版本试错。
- 安装记录与真正的完成状态分离。中断之后允许继续，不能把一个残留版本 JSON 当成安装已完成。
- 安卓兼容策略先于整合包更新。只对有依据的具体组件采用禁用；可恢复隔离，保留记录。服务器必需组件不直接移除，明确报告阻碍，防止下载完成后又不能进服。
- 不修改 PC 包、真实游戏目录、线上配置或社区数据。不开子 Agent。
- 交付修订 APK 供用户验证；用户后续明确要求通过内置更新使用，因此使用现有 GitHub v0.7.0 的运行组件更新通道分发构建 70001，不另改社区本体版本。

## 实际配置

模组一服：Minecraft 1.21.1 / NeoForge 21.1.250，当前 HXZUP 清单快照在 `.runtime/android-adaptation`。模组二服也同步检查，但不扩大到无关界面重构。

## 已证实与待验证

- ProcessService 仍将安装日志写到共享存储 `/FCL/log`，而宿主轮询私有外部目录中的 `log`；路径不一致，且 Android 分区存储可能拒绝前者。
- NeoForgeOldInstallTask/ForgeNewInstallTask 固定从 Java 8 开始，失败后依次 17、11、21；应根据处理器要求与游戏版本一次选对运行时。
- HxzRunner 仅凭版本 JSON 存在跳过安装；需要使用完成凭据并验证加载器与必要文件。
- 手机上这一次卡住的精确原因仍待实机日志，不能由上述代码缺陷直接推定。

## 验证记录

实现与维护入口：`mobile/game-engine/src`、`apply-adaptation.mjs`。初次适配脚本自动调用第二阶段脚本；已适配的完整源码无需重跑初次适配。

- `node scripts/tests/android-adaptation070.mjs`：真实下载层在本机 HTTP 中途断流后使用 Range 续传，SHA-1 校验通过；404 转备用源；JSON 残留不误判成功；UTF-8 跨缓冲区和日志截断正常；已知不兼容组件在请求下载前过滤；恢复备份及依赖保护通过。
- `node scripts/tests/android-mapping070.mjs`：实际更新器的 0–5 投影、实例优先、共享目录、严格清理、存档与运行库保护通过。
- 用实际清单与目录读取做核验：Zink 下模组一服投影后 1,145 项保留 1,143 项，模组二服投影后 1,686 项保留 1,684 项；后者 GL4ES 模式再跳过 Modern UI。未下载或写入真实玩家实例。
- 当前 Sable 2.0.3 原文件改名后仍可按内容识别、安装适配器；同一适配器改名不会再安装第二份。53 个 JNI 方法导出名称均存在，原生库为 Android ARM64，依赖 bionic，ELF LOAD 对齐 0x4000。
- APK Gradle 原生编译与 Release lint 通过。未连接手机，没有 Android 实机截图；原生诊断窗口和游戏运行仍待用户验收。没有对社区 Web UI 做布局变更。

## 交付方式

保持 0.7.0，运行组件内部构建号增加到 70001；仍使用原应用 ID 和签名。修订 APK 与对应完整 GPL 源码放在 `release/0.7.0/android/revision-70001`。不要先卸载原组件，否则 Android 会清除其私有实例目录。保留 GitHub 的原 70000 安装包和源码，新增带 70001 的附件；只有 APK 和源码上传校验完成后才将签名的 `game-engine-latest.json` 切换到新构建。现有社区客户端按构建号识别更新，无需先更新社区本体。

内置更新：幻想镇社区「发现 → Minecraft → 检查组件更新」，下载完成后点击「安装组件更新」，按 Android 提示覆盖安装。首次安装则使用「下载运行组件」。「我的 → 应用更新」只检查社区本体，本次本体仍为 70000。

用户验收：覆盖安装运行组件 → 幻想镇社区「发现 → Minecraft」→ 模组一服 → 安装并进入；渲染器选择「跟随运行引擎」。旧文件和可恢复断点会继续使用。若再次停住或失败，复制新窗口的诊断信息；其中包含具体 NeoForge 处理器和退出原因，可进一步定位这台平板的问题。
