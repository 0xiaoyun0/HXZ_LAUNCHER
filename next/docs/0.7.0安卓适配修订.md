# 0.7.0 安卓游戏适配修订

2026-10-12。用户实机反馈：小米 Pad 8 Pro，模组一服，卡在 NeoForge 安装；期望安装加速、恢复与诊断，以及更新前自动处理不兼容模组。70001 的初次验证没有实体设备；70002 已连接用户的小米平板，后续实测记录见本文末尾。

## 范围

- 修订原生游戏运行组件，保留 FCL 核心与 GPL 许可；必要时同步社区端的安装设置与诊断入口。
- 默认官方优先、32 并发；复用已有校验、重试和缓存，避免无效下载和 Java 版本试错。
- 安装记录与真正的完成状态分离。中断之后允许继续，不能把一个残留版本 JSON 当成安装已完成。
- 安卓兼容策略先于整合包更新。只对有依据的具体组件采用禁用；可恢复隔离，保留记录。服务器必需组件不直接移除，明确报告阻碍，防止下载完成后又不能进服。
- 不修改 PC 包、真实游戏目录、线上配置或社区数据。不开子 Agent。
- 交付修订 APK 供用户验证；用户后续明确要求通过内置更新使用，因此使用现有 GitHub v0.7.0 的运行组件更新通道分发构建 70001，不另改社区本体版本。

## 实际配置

模组一服：Minecraft 1.21.1 / NeoForge 21.1.250，当前 HXZUP 清单快照在 `.runtime/android-adaptation`。模组二服也同步检查，但不扩大到无关界面重构。

## 已证实与待验证

- ProcessService 仍将安装日志写到共享存储 `/FCL/log`，而宿主轮询私有外部目录中的 `log`；路径不一致，且 Android 分区存储可能拒绝前者。
- NeoForgeOldInstallTask/ForgeNewInstallTask 固定从 Java 8 开始，失败后依次 17、11、21；应根据处理器要求与游戏版本一次选对运行时。
- HxzRunner 仅凭版本 JSON 存在跳过安装；需要使用完成凭据并验证加载器与必要文件。
- 手机上这一次卡住的精确原因仍待实机日志，不能由上述代码缺陷直接推定。

## 验证记录

实现与维护入口：`mobile/game-engine/src`、`apply-adaptation.mjs`。初次适配脚本自动调用第二阶段脚本；已适配的完整源码无需重跑初次适配。

- `node scripts/tests/android-adaptation070.mjs`：真实下载层在本机 HTTP 中途断流后使用 Range 续传，SHA-1 校验通过；404 转备用源；JSON 残留不误判成功；UTF-8 跨缓冲区和日志截断正常；已知不兼容组件在请求下载前过滤；恢复备份及依赖保护通过。
- `node scripts/tests/android-mapping070.mjs`：实际更新器的 0–5 投影、实例优先、共享目录、严格清理、存档与运行库保护通过。
- 用实际清单与目录读取做核验：Zink 下模组一服投影后 1,145 项保留 1,143 项，模组二服投影后 1,686 项保留 1,684 项；后者 GL4ES 模式再跳过 Modern UI。未下载或写入真实玩家实例。
- 当前 Sable 2.0.3 原文件改名后仍可按内容识别、安装适配器；同一适配器改名不会再安装第二份。53 个 JNI 方法导出名称均存在，原生库为 Android ARM64，依赖 bionic，ELF LOAD 对齐 0x4000。
- APK Gradle 原生编译与 Release lint 通过。未连接手机，没有 Android 实机截图；原生诊断窗口和游戏运行仍待用户验收。没有对社区 Web UI 做布局变更。

## 交付方式

保持 0.7.0，运行组件内部构建号增加到 70001；仍使用原应用 ID 和签名。修订 APK 与对应完整 GPL 源码放在 `release/0.7.0/android/revision-70001`。不要先卸载原组件，否则 Android 会清除其私有实例目录。保留 GitHub 的原 70000 安装包和源码，新增带 70001 的附件；只有 APK 和源码上传校验完成后才将签名的 `game-engine-latest.json` 切换到新构建。现有社区客户端按构建号识别更新，无需先更新社区本体。

内置更新：幻想镇社区「发现 → Minecraft → 检查组件更新」，下载完成后点击「安装组件更新」，按 Android 提示覆盖安装。首次安装则使用「下载运行组件」。「我的 → 应用更新」只检查社区本体，本次本体仍为 70000。

用户验收：覆盖安装运行组件 → 幻想镇社区「发现 → Minecraft」→ 模组一服 → 安装并进入；渲染器选择「跟随运行引擎」。旧文件和可恢复断点会继续使用。若再次停住或失败，复制新窗口的诊断信息；其中包含具体 NeoForge 处理器和退出原因，可进一步定位这台平板的问题。

## 70002：下载、账号与真实启动链路

维护入口仍为 mobile/game-engine/src、apply-adaptation.mjs；不改 Windows 或社区服务端。社区和运行组件都使用 0.7.0 / 70002，原包名与原签名覆盖安装。交付目录为 release/0.7.0/android/revision-70002。

- Nashorn 等公共 Maven 依赖在 NeoForge Maven 连接失败后补充 Maven Central、阿里云、华为云与 BMCL 镜像，保留原始来源，校验 SHA-1；只扩展已知公共仓库的规范路径，不转发私有地址和查询参数。
- 修正 FCL 外置认证根地址缺少末尾斜线时拼错验证、刷新和皮肤接口的问题。社区账号经同签名桥导入 FCL 正常账号库，刷新后可持续使用；高级设置入口也会同步所选皮肤站角色。令牌不写日志、不交给网页。
- HXZUP 首次安装或事务未完成时不能因关闭自动更新而跳过。安装过的完整实例仍遵守用户的关闭更新选项；管理员强制更新要求仍生效。原生 FCL 启动按钮也走同一更新流程。
- 修正 Android 恢复 MainActivity 时路径未初始化导致 Accounts 初始化崩溃；实例启动参数保存到独立配置，避免污染全局设置。
- 自动模式先检测 Vulkan 驱动，内置 Turnip 不可用时选择系统 Vulkan，并按系统和驱动版本缓存检测；手动渲染器选项继续保留。
- 第一次为托管实例应用手机画质：视距 6、模拟距离 4、60 FPS、Mipmap 2、关闭包内默认 Iris 光影；原文件备份到 updater/android-settings。后续玩家修改不重复覆盖。高分屏首次设置最高约 1600 像素长边，可在原生运行设置继续调整；限制资源加载线程的 CPU 数为 4。

针对性检查：android-maven-fallback070.mjs 复现 NeoForge IPv6 超时后从 Maven Central 取得同一 SHA-1 文件；android-auth-endpoints070.mjs 验证实际 FCL 认证提供器的验证/刷新/皮肤地址；android-update-gate070.mjs 验证首次安装、关闭更新、强制更新和事务恢复。android-mapping070.mjs 验证真实更新器的 0–5 目录投影。

实机：Xiaomi 25091RP04C / Android 16。社区账号和皮肤成功导入，皮肤站验证通过，HXZUP 完成同步；直接点击 FCL 启动也记录了认证与 HXZUP。内置 Turnip 无法创建 GLFW 窗口，系统 Vulkan 成功进入模组加载。随后系统退出记录明确为 LOW_MEMORY，峰值约 4.4 GB；该包包含默认开启的 BSL 光影。针对这个新阻塞补充手机画质和分辨率默认值。用户要求停止实机测试，后续仅编译、签名和发布校验；没有完成进服验收，不将中间结果视作三服或全部安卓设备通过。

### 70002 内存保护与重新编译

- 自动内存同时受设备分档、物理内存一半和当前可用内存预算约束；修复旧逻辑在空闲不足时仍强制抬高 Java 堆的问题。
- Java 之外另留 768–1536 MB 给图形及原生组件，系统预留不低于 512 MB 且不低于 Android 报告的低内存阈值。手动内存也受预算限制，日志列明总量、可用、Java 和预留量。
- 大型模组实例的 Java 启动下限为 2048 MB，原版实例为 1024 MB；不足时清楚提示关闭其他应用或选择轻量整合包，保留已完成的安装。仅安装模式不因游戏启动内存不足被拒绝。该下限是启动保护策略，不代表任何包都能用此内存运行。
- 检出覆盖内存保护的自定义堆参数时提示改用运行设置，防止旧 JVM 参数绕过预算。默认最多四个资源加载计算线程；不终止其他应用、不清空用户数据、不循环强启游戏。
- SM8750 系列已证实内置 Turnip 存在枚举成功而 GLFW 失败的情况，自动模式优先使用经检测可用的系统 Vulkan；其他设备继续按驱动能力检测，不对所有机型强制同一种驱动。

最后一轮仅重编译社区客户端与运行组件，沿用原证书。新的内存策略未再次跑手机游戏压力测试，不能承诺所有设备或未来任意 PC 模组包不会崩溃。

驱动检测沿用 [FCL 的 Vulkan 能力检测](https://github.com/FCL-Team/FoldCraftLauncher)，本次不替换其原生驱动二进制，不要求用户安装系统驱动。

## 70003：首次账号导入与启动前渲染适配

70002 完成编译和覆盖安装后，用户反馈新用户已经登录社区但直接打开运行组件没有账号，并补充认证连接失败与自动渲染适配要求。停止尚未完成的 70002 上传，其更新清单未公开启用。最终修订提高内部构建号到 70003，版本名称仍为 0.7.0。

- 原桥只在社区的启动或高级设置操作中传递账号；直接打开 FCL 图标不执行导入。新增同签名且校验调用包名的本地 ContentProvider，FCL 账号库初始化后及返回前台时拉取当前社区角色。没有网页令牌接口，不把账号写入实例文件。相同账号凭据指纹不重复替换已经刷新过的账号。社区增加「导入社区账号」按钮，成功后显示提示。
- 对幻想镇皮肤站首页、用户页与 Yggdrasil 根接口做明确规范化。认证元数据、验证与刷新使用同源 HTTPS 连接，优先系统 DNS 返回的 IPv4、保留 IPv6 备用，保留证书及主机名验证；不向下载镜像传送账号。响应有体积限制、请求超时与明确错误分类；不把 HTTP 错误或 HTML 网页当作认证成功。
- 启动前在私有独立进程创建小型 EGL 上下文、检测系统 Vulkan 和适用的内置 Turnip。结果按系统指纹及组件路径缓存一天；图形探测超时/崩溃不会带走主界面。结合游戏版本、加载器和检测结果选择 NG-GL4ES、VirGL 或 Zink，把渲染器、驱动写入 FCL 的独立实例配置。手动选择不满足能力条件时自动纠正；找不到可用环境时停止启动并保留文件。
- 系统 Vulkan 与 OpenGL 能力可检测，不代表所有桌面模组都支持手机。按用户要求不再跑游戏压力测试或重复截图，不声明已实际进服。70003 的发布证明为 `.runtime/android-adaptation/release-70003-verified.json`。
