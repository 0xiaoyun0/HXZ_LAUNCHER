# 0.8.0 游戏服务端桥

组件仅安装在游戏服务端，玩家无需额外安装。社区服务端也需升级到 0.8.0。三个服各用独立令牌，不把令牌放入整合包、截图或公开仓库。

只读核对本机客户端得到：原版 26.2/Fabric 0.19.5/Java 25；模组一服 1.21.1/NeoForge 21.1.250；模组二服 1.21.1/NeoForge 21.1.251/Java 21。客户端安装 Fabric 不能证明原版游戏服务端使用 Fabric。原版桥按已知 MCDR 场景提供，实际部署前确认管理方式。

## 社区准备

管理员在游戏统计/游戏桥配置中为 survival、mod-1、mod-2 分别创建或轮换接入令牌。令牌为 64 位十六进制字符串。桥只连接 HTTPS 社区地址；本机隔离测试可以使用回环 HTTP。代理需要放行 /api/game-bridge/ 与原游戏统计接口，不要把游戏桥凭据当成用户登录令牌。

游戏桥启动后上报实际版本、人数、支持的能力和统计。聊天及白名单默认关闭，需在社区端与游戏端都开启。没有任意控制台命令执行接口；白名单只接受经过验证的角色 UUID 和名称，操作有持久化回执，网络重试不会反复执行同一操作。

## 原版服：MCDR

将 game-server 中的 hxz-community-bridge-0.8.0-mcdr.mcdr 放到实际 MCDR 的 plugins 目录，重新加载插件。要求 MCDR 2.12 或以上。

首次生成 config/hxz_community_bridge/config.json。根据实际游戏服务端目录填写：

```json
{
  "enabled": true,
  "community": "https://qqbot.hxzmc.top",
  "server": "survival",
  "token": "填入该服独立令牌",
  "server_directory": "server",
  "world": "world",
  "game_version": "26.2",
  "chat": false,
  "whitelist": false,
  "interval": 5
}
```

server_directory 是实际游戏服目录，相对 MCDR 工作目录或使用绝对路径；world 必须位于该目录内。不要填写玩家客户端 .minecraft。桥读取服务器 stats、角色缓存和真实在线事件，在有界后台线程处理网络与文件，游戏服停止后不会继续显示为正常在线。

## 两个模组服：NeoForge

将 hxz-community-bridge-0.8.0-neoforge-1.21.1.jar 放入游戏服务端 mods，重启后编辑 config/hxz-community-bridge.properties：

```properties
enabled=true
community=https://qqbot.hxzmc.top
server=mod-1
token=填入模组一服独立令牌
chat=false
whitelist=false
```

模组二服将 server 改为 mod-2，并使用其独立令牌。需 Java 21。仅 dedicated server 加载；没有给玩家客户端增加模组依赖。启动后采集真实统计、配方与在线状态；不存在受支持数据时不伪造机器产量或玩家行为。

## 安装后核对

用一个普通角色登录，确认社区显示正确服务器与版本，统计关联的是同一个角色 UUID。开启聊天桥后分别发一条测试消息；启用白名单同步前备份白名单，使用测试申请核对审核、入队、游戏端回执和失败提示。停服或断网后状态应变为离线/未知，不保留虚假的在线计数。

本机已完成两个 NeoForge 版本的依赖编译、MCDR 六项单元检查、社区鉴权/队列/幂等/统计接口测试。真实服务端目录尚未提供，尚未安装到线上或完成专用游戏服务端启动验证。交付组件与已部署组件需要明确区分。
