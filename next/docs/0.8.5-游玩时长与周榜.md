# 0.8.5 游玩时长与周榜：服务端与游戏桥部署

PC 与手机使用同一社区服务、同一个皮肤站角色身份和同一组 API。计时发生在社区服务端，无需客户端常驻或额外安装手机计时插件。升级后的记录从可信游戏桥开始核验时产生；旧版 Minecraft 累计统计不会倒灌成历史日历或奖励。

## 部署与接入

1. 升级社区服务并沿用原数据目录。首次启动自动创建 `playtime_*` 表，保留原账号、积分、站内信与游戏桥授权。正常停服后备份整个数据目录；在线备份应使用 SQLite 一致性备份，不能只复制正在写入的主数据库文件。
2. 打开网页管理 `/admin/` → 默认服务器 → 游戏统计接入，为 `survival`、`mod-1`、`mod-2` 分别创建或使用各自的桥接令牌。令牌按服务器隔离，轮换后旧令牌立即失效。
3. 在游戏服务器安装对应的既有桥接适配器。MCDR 源码位于 `integrations/game-bridge/mcdr/`，首次载入生成 `config/hxz_community_bridge/config.json`；NeoForge 服务端适配器源码位于 `integrations/game-bridge/neoforge/`，首次启动生成 `config/hxz-community-bridge.properties`。按实际游戏版本使用兼容构建，不能把 NeoForge 适配器安装到不兼容的加载器。
4. 在桥接配置中设置 `enabled=true`、`community=<社区服务 HTTPS 基址>`、`server=<对应服务器标识>`、`token=<该服务器令牌>`。MCDR 还需正确填写 `server_directory`、`world` 与 `game_version`，并能读取游戏服 `usercache.json`，以便把角色名解析为真实 UUID。缺失 UUID 的玩家不会获得可核验在线时段。
5. 桥接配置变更后按该适配器的正常流程重载或重启游戏服，确认 `/api/game-bridge/poll` 成功。NeoForge 默认每 5 秒轮询，MCDR 的 `interval` 默认为 5 秒、有效范围 5–60 秒。保持频率小于 90 秒，允许反向代理转发请求头与 JSON 请求体。
6. 网页管理 → 活动与积分 → 游玩日历与周榜，检查本周规则、设置下周规则，并查看已结束周的结算记录与名次明细。仅开启在线统计不要求启用聊天或白名单自动同步。

访问令牌只放在对应的可信游戏服务器上，不能发给 PC/手机客户端。桥接令牌授权的在线玩家列表是本功能的信任边界；管理者需要信任持有该令牌的游戏服务器。

## 计时与规则

- 唯一计时来源为已授权游戏服的 `POST /api/game-bridge/poll` 中 `status.players` 的 UUID。社区服务使用自己的接收时间，忽略请求中的累计时长、历史时间戳及其他时长声明。`/api/game-stats/report` 上报的 `play_time` 等累计统计不参与奖励计时。
- 玩家需连续出现于同一游戏服相邻两次有效 poll，才确认两次接收之间的时段。首次出现不补算此前时间；不在下一次列表中的玩家，不追记最后一段。间隔超过 90 秒则整段丢弃。社区服务重启会清空待确认心跳，保留已核验的历史会话与汇总。
- 同一 UUID 跨服、跨设备的重叠时段取并集，不能重复累计。UUID 大小写、连字符规范化匹配社区角色，奖励钱包与名称使用社区已认证身份，不能由游戏上报的显示名改投他人钱包。未登录过社区的游戏身份可以留下核验记录，但只有已登记的社区成员进入周榜与奖励结算。
- 日期与周都以 `Asia/Shanghai`（UTC+8）为准，周一 00:00 开始。跨日、跨周的会话按边界分拆；明细中的连续/重叠区间会合并。明细不保留或猜测区间的服务器来源。
- 默认开启奖励；每周最低有效时长 30 分钟；每日参加周榜的时长上限 480 分钟；前十名奖励为 `[100,80,60,40,30,20,20,10,10,10]` 积分。周榜以每日封顶后时长之和排序；同分按 UUID 稳定排序。未达每周最低时长仍展示记录，奖励为 0。个人日历与会话明细保留原始核验时长，同时返回封顶后的有效时长。
- 管理员规则修改从下周一生效，本周规则与已结算周规则不会被回溯改变。最低时长为 1–10080 分钟，每日上限为 1–1440 分钟；最低时长不能超过七天上限之和。奖励数组最多 100 项，每项为 0–1000000000 的整数，可为空；关闭奖励后仍统计在线记录。
- 在线状态只表示可信游戏服核验到该角色在线，不等于持续操作，无法识别全部挂机。本功能没有承诺强防挂机或活动量检测。

## 自动结算与持久化

结束周保留 90 秒心跳核验窗口，允许跨周会话先完成分拆。后台每分钟尝试结算，读取游玩 API 和收到有效 poll 时也会触发检查。服务重启会补结算遗漏的已结束周。

每个周榜保存固定的规则和名次快照。周结算标记、积分钱包/流水/当周积分榜、站内信在同一 SQLite 事务内落库；错误会整体回滚。奖励流水与消息均使用 `playtime:<week>:<uid>` 唯一标识，重复检查及重启不会重复发放。奖励计入**到账当周**的积分榜，再由现有积分模块正常汇总年榜，避免向已封账的历史积分周写入而漏掉年榜。通知指向 `/community/playtime?week=<北京时间周一起点毫秒>`。

个人日历与详情提供含今天在内的 365 个北京时间日期。当前实现不会定时删除 `playtime_intervals` 或 `playtime_days`，因此区间明细完整覆盖该窗口，重启不丢失；接口不会因此允许读取窗口外的个人详情。已结算周的名次快照独立保留。备份/恢复时需要一并保留这些表及既有 `points_*`、`inbox` 表，不能单独回滚奖励标记而保留钱包。

## PC/手机共用 API

用户 API 均要求正常社区登录的 `Authorization: Bearer <社区会话令牌>`。社区会话令牌与游戏桥令牌用途不同。日历和详情固定使用当前登录者身份，不接受 `uid` 参数指定他人；管理员也没有通过这两个端点读取他人日历的特权。

| 方法与端点 | 返回与用途 |
| --- | --- |
| `GET /api/playtime/calendar` | `{timezone,from,to,days:[{date,seconds,eligibleSeconds}],summary:{seconds,eligibleSeconds,activeDays,streak,longestStreak},rules,verification,updated}`；过去365天，缺失日期补0。`seconds` 是原始核验时长；`eligibleSeconds` 是每日封顶后时长。 |
| `GET /api/playtime/detail?date=YYYY-MM-DD` | `{date,timezone,seconds,eligibleSeconds,sessions:[{start,end,seconds}],rules,dailyCapMinutes,verification}`；严格校验真实日期、未来日期与365天范围，非法日期返回400。`start/end` 为 Unix 毫秒，`seconds` 为区间秒数，空日期返回空 `sessions`。只返回合并后的真实核验时段，不附伪造的 `server` 字段。 |
| `GET /api/playtime/leaderboard?week=<毫秒>` | `{week,label,timezone,items,self,total,settled,settledAt,rules,weeks,verification}`；省略 `week` 为本周，否则必须是北京时间周一00:00的有效时间戳。`items` 最多100名，`self` 提供本人完整名次或null；每项为 `{uid,name,seconds,rank,reward,eligible}`。`reward` 是十进制字符串；本周未结算时为预计奖励，已结算周为固定实发值。`weeks` 提供最近最多104个有记录的周和本周。 |
| `GET /api/admin/playtime/rules` | 管理员专用，返回 `{rules,nextRules,effectiveWeek,timezone,verification,maxHeartbeatGapSeconds,settlements}`。结算记录包含 `week,label,created,total,points,rules`，历史名次可用上面的周榜端点查询。 |
| `PUT /api/admin/playtime/rules` | 管理员专用，提交 `{enabled,minWeeklyMinutes,dailyCapMinutes,rewards}`；返回 `{ok,effectiveWeek,rules}`，保存下周配置。 |

桥接端点为 `POST /api/game-bridge/poll`，请求头必须同时包含 `Authorization: Bearer <该游戏服64位令牌>` 和 `X-HXZ-Server: survival|mod-1|mod-2`，请求体格式沿用现有桥接协议：

```json
{
  "status": {
    "version": "1.21.1",
    "loader": "neoforge/21.1.250",
    "online": 1,
    "max": 20,
    "capabilities": ["status", "statistics"],
    "players": [{"uid": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa", "name": "Player"}]
  }
}
```

不能让玩家客户端调用此端点代报时长。PC与手机只读取个人日历/详情和已认证可见的周榜，不需要获取桥接令牌。

## 验证

服务端专项命令：在 `apps/community-server` 运行 `node --test test/playtime-085.test.mjs`。覆盖伪造权限与累计时长、跨服并集、时钟回拨、跨日跨周、断连、每日封顶、同分排序、规则冻结、幂等奖励、真实SQLite关闭重开补结算、积分一致性、明细越权与严格日期范围。管理员页面以一次性本地数据验证过保存下周规则、读取结算记录和展开名次明细。
