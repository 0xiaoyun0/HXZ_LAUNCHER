# 0.8.4 独立实例计划器

更新：2026-10-21。此处是新编写的纯 Java 安装/启动计划核心，位于 `mobile/runtime/src/main/java/top/hxzmc/runtime/`。没有引用、复制、改名或翻译 FCL/Pojav 启动器代码。它不提供 Android JVM、图形、音频或输入实现，不能据此声称可在设备运行游戏。

## 宿主契约

统一入口：

```java
ServerPreparation preparation = new ServerPreparation(minecraftRoot,
    new RuntimeDownloads(8), verifiedHxzupToolJar);
LaunchPlan plan = preparation.prepare(preset, context, engineHost,
    cancellation, progress);
int exit = engineHost.runJava(plan.javaJob(), cancellation, progress);
```

`RuntimeDownloads` 允许按设备设置 4–32 并发，默认 8。`Progress.update(phase,item,completed,total)` 可能从多个下载工作线程调用；UI 必须投递到主线程。下载取消保留有权威散列的每源 `.part-*`；网络读被连接/读取超时约束，取消可在下一次读取或超时后完成。不得把临时文件视为已安装。

`EngineHost.runJava(JavaJob,Cancellation,Progress)` 返回真实 JVM 退出码。任务包含 Java major、main class、工作目录、classpath、JVM 参数、应用参数，全部是独立 token。宿主须自行提供对应 Android JVM 并等待进程结束，取消时终止真实任务。未实现 JVM 的宿主必须抛出明确异常。处理器非 0、缺产物、坏产物均不会完成安装。

`GamePreparation.Context` 提供 run/natives 目录、已验证账号身份/令牌、窗口/内存、功能规则；Android 默认为 Mojang 的 linux/aarch64 规则环境。新引擎模块负责 Android 原生 LWJGL/GLFW 等库；这里明确排除桌面 native classifier，不把下载桌面 Linux 动态库当作 Android 支持。

房间启动调用 `prepare(..., false)` 关闭预设自动入服，再调用 `plan.withAdditionalArguments(jvmTokens, gameTokens)` 追加已准备的账号 agent 或房间参数。不得把令牌或完整参数打印到日志。计划 `toString()` 只含实例、Java 版本和 classpath 数量。

## 计划与安装判断

- `ServerPresets.defaults()/read({servers:[...]})` 严格读取三个稳定 ID，与 `server/shared/server-presets.mjs` 的字段、来源和 URL 约束一致；服务端配置是权威来源。
- `ServerPreparation` 使用实例隔离目录及根目录文件锁，依次选择同一 HXZUP 地址的状态/配置、安装游戏及加载器、运行既有 HXZUP 文件规则/事务引擎、重新读取最终元数据并组装启动计划。
- Java 要求优先读取 Mojang `javaVersion.majorVersion`，已验证官方 1.21.1=21、26.2=25。缺字段时按本项目 PC `java-policy.mjs` 的已知 release ID 回退；自定义名称不猜 Java 8。
- 元数据继承限制 12 层并检测循环；库按 group/artifact/classifier/extension 合并，子版本覆盖同一 artifact，JVM/game 参数按父→子连接。规则逐条匹配，最后一个匹配动作决定允许状态；OS/arch/version 与 feature 约束都参与。
- `inspect` 检查 client、所需普通库、全部继承元数据、本地元数据 receipt、资源索引、全部资源对象、旧版虚拟/resources 映射、日志配置及安装器生成文件 receipts；仅有 JSON 永远不等于完整安装。
- `prepare` 可以下载修复普通依赖；没有下载 URL 的处理器生成物丢失时必须重新执行安装器，不凭空生成文件。
- Fabric/Quilt profile 使用官方服务；空 Fabric 版本读取兼容列表并选 stable。Fabric API 通过官方 Modrinth 项目/版本元数据匹配游戏及 loader，下载 primary 文件并校验 SHA1，替换同目录旧 Fabric API。
- Forge/NeoForge 的现代 `install_profile.json` 支持 client sides、data 引用与前向引用、Maven classifier/extension、安装器内嵌数据/库、处理器 classpath、参数及输出 SHA1。循环 data、越界输出、缺入口/库、非 0 退出或缺产物均失败并保留 pending marker。
- NeoForge 官方 `DOWNLOAD_MOJMAPS` client 步骤通过新下载器获取 Mojang 元数据指定的 mappings，其他 processor 交给真实 `EngineHost.runJava`。无显式 outputs 的常见 `--output/--slim/--extra/--to` 产物也会检查非空；JAR 检查 ZIP 结构，并将最终 SHA256/大小纳入实例元数据。删除生成物后实例再次显示不完整。

## 下载与 HXZUP

新下载器复用本项目 PC 自研安装器的同文件 URL 路由，默认每文件官方首先；该文件所有候选完成一轮后才重试瞬态失败，最多 5 轮。404、鉴权失败与坏散列立即排除该源。最多 32 个候选、4–32 个在途任务；不为 100,000 个资源建立同等数量线程/排队任务。文件按大小先后安排，下载到临时文件后完整校验并替换。

`DownloadMirrors` 保留完整 Central 备用；Fabric/Forge/Quilt/NeoForge 使用各自明确代理路由。带查询、凭据、fragment、自定义端口或非 HTTPS 的地址不扩展至其他运营方。重定向限制 5 次并拒绝 HTTPS 降级。上游有 SHA1/SHA256 时以其为准；无上游散列时保存本地 SHA256 receipt 检测后续损坏，这不是发布者签名，且这类文件不做跨请求 Range 续传。

HXZUP 沿用 `resources/hxzup/updater-launcher.jar` 的 `up.hxz.Updater`，不另写同步规则。先完成游戏/加载器安装，再写入现有 portable 契约的 gameVersion/loader，运行 managed/headless 任务；这使原 HXZUP 只负责 pack 文件及事务，避免调用其 PC GameInstaller 的 `ProcessBuilder`。portable 的层级 0/1 映射限制更新器/实例目录，服务端换游戏/loader 时原有版本守卫会阻止错误更新。更新成功仍检查真实退出码、committed local-version、pendingVersion、transaction 和最终游戏完整性。maintenance 是选中源的权威状态，不切到别的源绕过；首次安装缺完整本地实例时会拒绝。

预检查 status/profile 共用真实 16 秒期限，每源最多 8 秒，单源的第二次 profile 读取只使用该源剩余时间；不以可被重定向、慢速响应重复消耗的 socket timeout 充当整个检查期限。阻塞读取最多占用四个 daemon worker，调用方按期限或取消退出，不为不可达地址无限堆线程。默认网络层的异常连接路径会 disconnect；并发下载调度使用短轮询观察取消，实际正在读取的 socket 仍受读取超时约束。

`ServerPreparation` 在所有源仅出现网络不可达/超时/408/429/5xx/TLS 传输故障、`updateRequired=false`、游戏完整且无 pending 时允许使用完整本地版本，发出 progress phase=offline，跳过 HXZUP 执行。401/403/404 等配置或鉴权错误、可达但格式错误的元数据、用户取消、强制更新和不完整实例不能借此降级。maintenance 同样先检查本地完整性。

整合包完整性不能以 local-manifest.json 存在代替。会检查 committed local-version、事务/pending、数字层级映射及文件存在，并验证模组 JAR 摘要。每次 HXZUP 真正提交后记录私有 local-completion.json：固定对应 manifest/version，记录实际规则结果及 JAR SHA256，保留规则允许的删除和用户可修改配置语义；未有 receipt 的旧缓存以原清单的存在性/JAR SHA1/大小作保守校验。只有 JSON、缺模组、坏 JAR、缺应有配置均不能通过离线准备。

明确边界：未实现 package 来源的整合包导入、旧版 Forge versionInfo 格式、OptiFine，以及在 Android 上运行 JVM/处理器/游戏的真实后端。这些路径会明确失败，不写假成功。HXZUP 使用现有规则对用户可修改文件的语义；整合包最终模组指纹/房间 ready 由宿主联机层另行完成。不要用 `inspect` 的游戏依赖检查代替整合包房间指纹。

## 0.8.4 Android 客户端模组预检

实现位于 `mobile/runtime/src/main/java/top/hxzmc/runtime/ClientModCompatibility.java`。这是独立编写的纯 Java 扫描器，不执行模组类，不使用旧 FCL 的扫描或禁用代码。历史 `mobile/game-engine/assets/hxz/android-compatibility.json` 只用于理解旧数据字段；其 SHA1/文件名记录不足以证明客户端专用，未导入自动规则。

目标是保留服务端内容与依赖，只处理少量已人工核验、字节完全一致的客户端可选功能。它不承诺广泛修复 Android 模组兼容性，也不把“没有自动禁用”解释为“全部模组可运行”。

### 内置最小规则及证据

| 5.5.4 / gom4UX66 | 196761 | `08c5581bda0ab0fbfdbb10c51102685b403f64b0e712517c4b2d918b2c83cea3` |
| 5.6.1 / JCFs4e8D | 222741 | `fcdb1755d5729aabc194cbfec65fcb1233b780e44216b037684d3edd256a8289` |

两者提供的 ID 都为 `imblocker`，没有声明模组依赖。分别对应 SHA1 `4910d4aeab9e5d23b4facb592a18136e64caf3e5`、`ae2f4c8b929d923b6fd637b5158fd93082a0fdb2`，已与真实两服 HXZUP manifest 的大小/SHA1 和官方文件 URL 核对。

客户端专用的证据来自原作者 [Modrinth 项目/版本](https://modrinth.com/mod/imblocker-original/version/JCFs4e8D)、[5.5.4 固定版本 API](https://api.modrinth.com/v2/version/gom4UX66)，以及原作者固定提交 `35d6b2df779bdd4ccb328ea5fa984fcf3e144a51` 中 [NeoForge 入口对非 CLIENT 分发立即返回](https://github.com/reserveword/IMBlocker/blob/35d6b2df779bdd4ccb328ea5fa984fcf3e144a51/neoforge/src/main/java/io/github/reserveword/imblocker/IMBlocker.java#L22)。

Android 不适用是依据实际文件字节码与固定提交中的桌面输入法路径作出的判断：`pgrep -l fcitx5`、`ibus engine`、`fcitx5-remote`，5.6.1 另使用 GLFW X11。手机输入由宿主管理。对应原作者源码为同提交的 `common/src/main/java/io/github/reserveword/imblocker/IMManager.java`、`IMManagerLinux.java`、`LinuxIMFramework.java`。作者没有据此宣布 Android 必然崩溃，其异常处理也会捕获部分桌面命令失败；报告不作这种承诺。

ModernUI、C2ME、spark、AcceleratedRecoiling、其他渲染/内容模组及本地实验 Voxy 均未加入自动规则。仅有 x64 原生库或旧 GL4ES 的记录不构成当前 OSMesa 环境下可靠的客户端专用证据。

### 元数据与依赖保护

先读取 ZIP 目录和元数据，只为 ID 集合可能精确匹配内置规则的文件计算整 JAR SHA256。普通模组不会为了这个预检反复全文件散列。隔离备份则每次重新读取真实字节校验。

支持 Fabric 的 `id/provides/environment/depends/recommends/suggests/jars`，以及 NeoForge/Forge TOML 的模组 ID、依赖表、等价内联数组。现代 `neoforge.mods.toml` 存在时优先使用它，避免将同包未展开的旧 Forge 模板作为当前元数据。NeoForge 的现代文件名和依赖结构见[官方说明](https://docs.neoforged.net/docs/gettingstarted/modfiles/)及 [20.5 文件名迁移公告](https://neoforged.net/news/20.5release/)。TOML 读取器独立实现，遇不支持或不完整的身份/依赖结构报告具体 JAR 并保守保留。

Fabric 声明的嵌套 JAR 和 JarJar `META-INF/jarjar/metadata.json` 递归读取：最多 4 层、每嵌套 JAR 32 MiB、每外层 JAR 累计展开读取 128 MiB、元数据 1 MiB、每 ZIP 最多 100000 项。已完整解析、没有模组元数据的嵌套普通库可以忽略其模组 ID；嵌套模组的 ID/依赖合并到外层依赖图。候选自身携带任何声明的嵌套 JAR 都保留，不扩大规则覆盖。

存在未知依赖结构时不自动隔离任何候选；重复 ID、`data/` 内容、服务端环境、用户恢复选择或保留模组指向候选的依赖同样阻止隔离。依赖保护迭代至稳定，避免移除间接仍被需要的客户端库。optional/recommended/suggested 等也保守保留，不把它们擅自视为可删除。

### 准备、HXZUP 与可恢复事务

`ServerPreparation.prepare(..., boolean joinPreset, ClientModCompatibility compatibility, ReportListener listener)` 在现有准备锁内持有实例隔离锁，并按以下顺序执行：

1. 读取/恢复上次事务，将已隔离且哈希正确的原文件移回原路径。
2. 执行完整安装、HXZUP 更新、维护/离线完整性检查。
3. 重新读取最终模组元数据与候选哈希，安全隔离后才返回 `LaunchPlan`。

因此 HXZUP 的下一轮 hash 检查看到原整合包文件，不会因本地隔离反复下载或悄悄重新启用。实际子 JVM 执行本项目 HXZUP 的夹具验证了第二次同步不重复下载；503/维护下完整本地包仍可通过检查，随后重新隔离。准备失败或取消不返回可启动计划，已恢复的文件留在原路径并有日志，下次准备重新核验。

备份位于实例 `.hxz/client-mods/objects/<uuid>-<sha256>.jar`，状态为 `.hxz/client-mods/state.json`，记录原路径、大小、散列、规则、证据与 moving/quarantined/restoring/restored/retired/conflict。先写入并同步日志再移动文件，完成后更新状态；中断恢复依据实际文件位置和哈希核对。移动不覆盖已有文件、不删除用户文件，拒绝符号链接和越界路径。原路径已出现其他内容时保留两份并记 conflict。备份缺失或损坏不会伪造成功。这里验证的是应用异常中断恢复，不承诺存储介质断电后的完整文件系统持久性。

`restoreAll(cancel)` 恢复已验证原件，并保存对应精确 SHA256 的用户保留选择；之后预检不会再次隔离同一文件。规则移除后原件仍可恢复，旧隔离记录不会再作为当前可信兼容调整。

### Activity / 房间 API

`Report` 公开 `findings / inspected / disabled / eligible`、`summary()` 与 `toJson()`；`toJson()` 声明 `JSONException` 以同时兼容 Android 与 JVM 的 org.json。每项 Finding 包含 `relativePath / decision / reason / ruleId / evidence`。Activity 负责展示摘要和保存诊断 JSON；扫描器本身不发 Toast、不操作界面。

`validatedQuarantine(cancel)` 返回 `List<QuarantinedFile>`，每项为真实备份 `file`、原 `relativePath`、重新核验的 `sha256`、`ruleId`、`reason`。每次要求备份真实存在且大小/哈希正确、原路径不存在、当前内置规则与元数据仍匹配、依赖图仍允许隔离。任意 `.disabled` 文件、损坏/缺失备份、伪造日志路径、被移除规则、冲突文件不会贡献摘要。

Android 的原整合包指纹可以将启用 JAR 与这些经过核验的实际原件按原路径合并；实际启动仍使用启用 JAR，调整原因单独诊断。PC 的严格原包指纹协议保持原样。此接口不能仅凭日志中的 digest 伪造一个已安装原件。

`dryRun(cancel, progress)` 不建目录、不加写锁、不改日志、不移动文件，仅用于只读审计。它不能代替实际准备事务。
