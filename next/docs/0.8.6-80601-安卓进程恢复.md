# Android 0.8.6 / 80601

修复游戏运行时清理后台后，社区重新打开仍停在“退出游戏后自动恢复”的问题。

- 会话保护与实际游戏进程关联，记录持有进程 PID。确认进程退出即移除残留状态，替换后的新游戏进程不能继承旧标记。
- 社区自己的登录会话使用 Android Keystore 加密保存，绑定社区地址、角色和登录客户端。社区进程重建时可恢复未过期会话，无需刷新正在使用的 Minecraft 登录凭据。登出、换角色、换社区和服务器拒绝认证时清除缓存。
- 游戏正常退出后立即尝试恢复社区连接，解除旧重试退避；系统无法确定进程状态时仍保留有时限的保护。
- 精简游戏诊断保留纹理上传的游戏调用来源，显示实际堆上限、自动或手动内存模式及扩展预算状态，继续限制复制文本总量和移除凭据。

用户提供的 80600 样本中，两次采样相隔约 807 ms，渲染线程 CPU 增长约 675 ms，位置为 `glTexSubImage2D`。这表明线程在进行原生纹理工作，不足以证明死锁，也无法仅从截断调用栈确定是哪张纹理或哪个模组。`ConnectException` 和未知物品日志不能直接证明渲染停顿的原因。本构建补足定位证据，不宣称该设备的纹理性能问题或 60 FPS 目标已经通过实机验证。

验证：使用实际生产方法复现旧的恢复阻塞；修复后覆盖进程清理、存活会话保护、正常退出重连、过期/损坏/错角色缓存、未知系统进程状态及替换进程。另回归账号验证、内存预算、诊断限长和敏感信息隐藏，并编译同证书正式 APK。设备验证由用户手动完成，本次未操控手机。

构建号从 80600 递增至 80601，沿用 0.8.6 版本名和签名，可覆盖安装并保留账号、整合包、存档和设置。运行模块继续复用已发布的 80400 文件。Windows 和社区服务器不需要此次修订。
