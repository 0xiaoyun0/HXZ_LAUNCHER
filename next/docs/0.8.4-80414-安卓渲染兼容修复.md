# 安卓 80414：Sodium 启动拦截与退出清理修复

## 已知故障

80413 在 vivo V2408A / Android 16 中已完成 Java、认证代理及 EGL 初始化。实际退出堆栈由 Sodium 0.8.12 的 `PostLaunchChecks.onContextInitialized` 抛出“不支持 PojavLauncher”异常；随后出现 `pthread_mutex_lock called on a destroyed mutex`。不是整合包下载失败。

已对本机模组 JAR 的实际字节码核对：该版本检查 `POJAV_RENDERER` 后主动抛出异常。没有隐藏该变量或修改第三方 JAR 来绕过检查。Sodium 官方支持说明也明确指出 Android 启动器不在支持范围：[Supported Launchers](https://github.com/CaffeineMC/sodium/wiki/Supported-Launchers)。

## 适配策略

- 沿用客户端兼容适配的事务备份。仅匹配下表 SHA-256、完整模组 ID 集合的文件；整包移动到实例私有 `.hxz/client-mods/objects`，不删除、不改写。仍可手动恢复。
- 当前两服的 Sodium 与 Iris 光影链一并隔离，并包含必需的客户端附属组件。默认保留机械动力、航空学、Veil、Connector、游戏内容和存档；没有按模组名称进行模糊批量禁用。
- 显式规则允许已经核验的嵌套库。区分 required 与 optional/incompatible；共享 API 必须仍有保留来源。未知依赖类型按必需处理，未知元数据保护全部候选。
- IrisVeil 唯一 data 文件是 GameTest 结构 `data/irisveil/structure/irisveilgametest.modloaded.nbt`，对该路径作精确例外；其他 data 内容不在例外内。
- HXZUP 校验前自动恢复字节一致的原件，更新后重新扫描、备份；联机指纹只接受重新校验过的真实备份，不伪造缺失文件。
- Java 通过 `System.exit` 退出时，使用标准 JNI `exit` 回调记录真实退出码、刷新日志并直接结束独立游戏/处理器进程，防止仍在执行的本地线程与 C++ 全局析构发生互斥锁竞争。保留 Java 正常的关闭流程；不拦截 libc 的 exit，也不影响社区主进程。

JNI 接口依据：[Oracle Invocation API](https://docs.oracle.com/en/java/javase/21/docs/specs/jni/invocation.html#jni_createjavavm)。

## 验证与限制

- 原始边界复现：80413 的只读清单检查确认 Sodium 仍保留，断言失败；新增 JNI 退出边界用例确认原函数没有退出回调，失败。
- 修复后：62 项元数据、依赖、备份/恢复、真实 HXZUP 子进程回归通过；两服真实模组目录只读扫描为 225/261 个文件，分别匹配 10/8 个可隔离文件（含原有输入法规则），未知元数据为 0，原件未修改。
- JNI 本地回归共 7 种情况：代理加载、缺失库、多个代理以及真实子进程退出码保留/跳过全局析构。Android 加载器与 JVM 创建边界使用桩实现，不能代替 Android 真机。
- 16 项可读诊断回归通过；Android Release 构建及原发布证书验证通过。
- 未连接手机、未进行游戏运行/入服或帧率验收。当前不提供这些不兼容 Sodium/Iris 版本的光影、远景优化；这次优先解除已确认的启动拦截，不承诺所有模组/GPU 都兼容。
- 覆盖安装 80414 或内置更新即可应用；现有 Java、运行模块、游戏与存档保留。
