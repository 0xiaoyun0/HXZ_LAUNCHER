# 安卓 80420：扩展内存与实机修复

## 内存分配

- 游戏 → 运行设置加入“使用交换内存（扩展预算）”，默认关闭，保存选择并在下次启动游戏时生效。
- 读取物理总量、当前可用内存和系统实际 `SwapFree`，在游戏真正启动前重新计算，避免沿用安装开始时已过时的内存快照。
- 给 Android、Java 原生内存和图形驱动预留 768–1536 MiB；开启后，交换预算仅计算空闲交换的一半，并限制为物理总量的四分之一、最多 1024 MiB。模组自动堆目标为物理总量的 45%，最终仍受当前可用预算与 6144 MiB 绝对上限约束；手动选择同样受此约束。
- 不创建交换文件、不修改系统设置、不要求 root。Android 决定实际换出哪些页面；没有可用交换空间时不会凭空增加容量。zRAM 本身也消耗内存，不能当作等量的额外物理内存。
- 关闭选项仅取消额外交换预算，不会也不能强制关闭 Android 系统换页。扩展内存可能增加卡顿和发热，不能保证低端设备运行大型整合包。

## 实机定位与修复

USB 实际连接的是 Xiaomi Pad 8 Pro（25091RP04C、Android 16），并非报错的 vivo V2408A。

1. 原 80419 模组一服自动分配仅 1200 MiB，实机出现 Java 堆耗尽；初轮候选堆约 4051 MiB，完成入服后发现大量换页，因此正式版本收紧自动目标和交换预算，改为默认关闭交换预算。4051 MiB 不是正式版的固定分配值。
2. 实机独立探针复现 LWJGL 3.3.3 默认 FreeType 缺少 `FT_Get_Transform`；为所有已适配 LWJGL 指定模块内完整 FreeType 后，实际初始化/释放均返回 0。无需重下运行模块。
3. 整合包核心两个客户端特效 mixin 直接引用已停用的 Iris。仅对已核验 SHA-256 的现有文件，在本机移除这两条 mixin 配置，保留其余 27 条和全部其他文件内容；原件备份，HXZUP 校验前恢复，不发布第三方修改 JAR。存在 Iris 时不处理，未知版本不处理，可恢复。
4. NG-GL4ES `glBindSampler` 的上限比较允许访问第 17 个纹理槽，实机两次在同一原生地址崩溃。图形桥修正容量声明和越界绑定，保留合法绘制及错误处理，原渲染库二进制不变。

## 验证范围

- 内存预算 13 项回归、默认关闭及 UI/最终启动参数接线检查。
- 完整 FreeType 的 LWJGL 3.3.3/3.4.1 启动参数回归及 Android 实机初始化探针。
- 实际整合包核心文件的 13 项可恢复补丁/校验/房间标识检查；现有客户端兼容事务 62 项及诊断建议 23 项检查。
- 图形桥纹理边界、基础顶点与实例化索引回归。
- 平板已越过原内存/字体/特效依赖/原生崩溃点，完成资源加载、皮肤站认证与服务器模组同步，进入 `s2.hxzmc.top` 模组一服实际世界。实际日志记录从主菜单至世界约 97 秒，本次游戏冷启动至世界约 260 秒；不是持续无响应。实机截图保留在本地验证目录。

未以此推断 vivo 或所有低端机均已通过；没有将正常等待线程当作死锁，也没有删除领地、火炮、小地图或存档。

本次入服约 20 分钟后出现系统 socket 的 `Software caused connection abort`，已保留脱敏日志；仍需进一步区分设备网络中断与客户端因素，不宣称长期连接稳定性已经通过。

## 帧率限制

本次模组一服出生点实测仅 1–2 FPS。初轮候选的游戏进程换出约 5.4 GiB，系统换页线程占用约 79% 单核，同时场景有约 840 个方块实体。此结果证明增大堆并不等于提速；本构建收紧内存策略，但不宣称已解决该整合包的帧率问题。Sodium 仍因已核验的渲染兼容问题隔离，不能直接恢复不兼容组件来承诺提速。
