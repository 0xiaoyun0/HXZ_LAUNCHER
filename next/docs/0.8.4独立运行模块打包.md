# 0.8.4 独立运行资源模块打包

`scripts/package-hxz-runtime084.mjs` 为 HXZ 自有 Android 引擎生成资源 ZIP 和**未签名 payload**，不使用已停用的 `package-gameengine-runtime.mjs`，不产生更新源、签名或发布操作，不包含外来启动器 Activity/JNI/launcher-agent。JRE、LWJGL、Mesa 等依赖以明确的上游制品和来源锁描述，不把下载到的候选制品当作已完成的源码构建。

## 输入

- 依赖锁：`mobile/runtime/dependencies.lock.json`，schemaVersion 1；默认 stage 为该锁的 `stageRoot`，当前 `.runtime/hxz-runtime-upstream/input/app_runtime`。
- 工具锁：`mobile/runtime/tools.lock.json`，由 `scripts/prepare-hxz-runtime-tools084.mjs` 明确刷新；工具 overlay 位于 `.runtime/hxz-runtime-upstream/tools/input/app_runtime`，不会改写依赖 stage。
- 依赖锁的 requiredComponents 必须含 java21、java25、lwjgl333、lwjgl341、mesa、openal、libsync、jna5140、jna5170、freetype。每个 ready 组件必须有已固定摘要的对应 source 制品和 runtime/local-build 制品。依赖归档、源码归档、生成库与全部 stage 文件均实际读取、流式验证 SHA256。任何 stage 增项、缺项、错误摘要、链接、越界路径、大小超限均失败。
- 工具锁必须含 hxzup、direct-lobby、authlib-injector 的 binary/source/license 和 runtime-build 的独立构建脚本、配置及许可证。项目自有原始 JAR 和源码变化会使旧工具锁失效，需要显式重新准备。现有 HXZUP 内含自己的 android/bridge.dex，保持原始 JAR；不在模块外层加入 dex/APK，不接受 com.tungsten、net.kdt.pojavlaunch、com.movtery.zalithlauncher 的类路径。

默认组件树为 `java/{21,25}`、`lwjgl/{3.3.3,3.4.1}`、`renderers/osmesa`、`audio/libopenal.so`、`tools`，另有 licenses、sources、provenance。JRE 保留自己的 legal 树。每版 LWJGL 必须有 core/opengl/stb/tinyfd/OpenAL 的 ARM64 .so 和七个官方 Java 模块 JAR；依赖的 ELF 会检查 64 位、小端、AArch64 头。

JNA 的 Android ARM64 native 单独位于 `jna/{5.14.0,5.17.0}/libjnidispatch.so`，不以 AAR 的 classes.jar 替换 Minecraft 的标准 JNA Java JAR。26.2 使用 5.17.0；JNA 许可、源码 commit/归档与 AAR/native 摘要一起固定。LWJGL 3.4.1 增加官方 freetype/shaderc/spvc/vma/vulkan Java JAR，core unsafe 必须精确匹配 Mojang 26.2 metadata 的 `lwjgl-3.4.1-unsafe.jar`：1062128 字节、SHA1 `129e06a04f93992cb2a45172435b21fc4b60dd7d`。FreeType 是 `lwjgl/3.4.1/libfreetype.so`，通过 core JNI 的函数指针调用，不是虚构的 liblwjgl_freetype.so。

模块的 `capabilities={vulkanGameBackend:false,preferredGraphicsBackend:"opengl"}` 与来源锁一致。当前自有 GLFW 使用 OSMesa OpenGL，不提供 Minecraft Vulkan 的 VkSurface；shaderc/spvc/vma 的 Vulkan 专用 native 不作为 OpenGL 模块必备文件，也不声称已经供应。OSMesa 内部 zink 对 Vulkan 的使用是另一层，仍可作为实际编译的渲染器列出。

打包器直接解析每个 ELF 的动态段和 DT_NEEDED，而非只判断扩展名。除明确的 Android 公共系统库外，依赖必须出现在对应 Java major 或可用 native 范围内；libc++_shared.so 不作为系统库放行。来源锁给出的 LWJGL unsafe JNI 审计及 Java/native 列表也要完整匹配。

## 本地候选

```powershell
node scripts/package-hxz-runtime084.mjs --candidate `
  --candidate-renderer .runtime/hxz-runtime-upstream/extracted/mesa25.3.4/libOSMesa.so
```

`--candidate-renderer` 必须精确对应依赖锁中 component=mesa、excludedFromStage=true 的文件路径和 SHA256；只有 --candidate 模式可用，不会将候选库复制进正式 stage。也可不加该选项，生成明确缺少 OSMesa 的本地检查包。

候选输出无论 --output 如何设置都必须在 `.runtime/review084` 内；父目录链接也会拒绝。候选 payload 的 kind 为 `android-runtime-candidate`，URL 为 local-candidate.invalid，candidate=true、releaseReady=false，不满足正式更新器的 kind/URL 约束。候选没有外层更新签名。

旧发布者 Mesa 候选的精确源码对应关系仍未核实，保持 blocked-source-correspondence 并排除出正式 stage。正式 stage 已改用官方 Mesa 25.3.4 + 官方 Mesa 24.3.4 OSMesa 及自有最小适配的独立源码构建，不使用该候选替代。候选的推断 driver 不作为可信启动选项。`module.renderers` 仅从与实际 OSMesa SHA256 匹配、status=ready 且 `capabilities.driversVerified=true` 的制品生成：

```json
{"capabilities":{"drivers":["softpipe","zink"],"driversVerified":true}}
```

支持 llvmpipe、softpipe、zink 选项；freedreno 可记入构建能力，但当前不会独立显示，因为缺少设备与驱动选择契约。llvmpipe 只有实际 LLVM 构建时才可列出；不能把 llvm disabled 的 softpipe 构建命名为 llvmpipe。选项包含 id/label/kind/osmesa library/driver/requiresVulkan，与 Activity 约定一致。

## 正式待签名材料

所有 requiredComponents 和所选 stage 文件均为 ready、对应源码/许可证/组件形状/driver 验证通过后，才允许：

```powershell
node scripts/package-hxz-runtime084.mjs `
  --version 0.8.4 --version-code 80400 `
  --url https://github.com/0xiaoyun0/HXZ_LAUNCHER/releases/download/v0.8.4/HXZ-Runtime-0.8.4.zip
```

这仍只写 ZIP 和同目录 `.payload.json`、`.provenance.json`。payload 的 `moduleSha256` 是 ZIP 内 module.json **原始 UTF-8 字节**的 SHA256，候选和正式模式均生成，必须随外层 payload 一起签名；Android 在提取与 validDeep 时比较，防止只修改本地清单及 verified.json。外层 payload 同时包含与 module 一致的 renderers、constraints、capabilities，以及 versionName；因此签名后 UI/设备兼容检查不用先信任未验证的 ZIP 内容。provenance 固定来源锁、工具锁、对应源码制品和归档/module 摘要，其原始字节 SHA256 写入 payload.provenanceSha256。签名必须由发布流程使用原 APK 更新证书规则完成；此脚本不读取私钥、不生成 signature、不修改正式更新源。`--stage`（app_runtime 或其父目录）、`--lock`、`--tools-lock` 可以显式选择已审计输入。

ZIP 只含 module.json 与 app_runtime/ 文件。module schema=1、kind=hxz-runtime-assets、interfaceVersion=1、abi=arm64-v8a，每个 files 条目都有完整 app_runtime 相对路径、字节数、SHA256。ZIP 按固定顺序、固定时间戳生成；生成后逐项解压读回并核对所有摘要，防止打包期间输入变化。模块行数、清单大小、解压总量和 ZIP 大小服从 GameRuntimeStore/GameEngine 限制。

当前 JRE 只支持 4096 字节页面；module/payload 均写 constraints.pageSize=4096、minimumAndroidApi=29、deviceTested=false。原生依赖自己的 16 KiB 对齐检查不能证明整个 JRE 支持 16 KiB 系统。打包成功只证明锁与文件一致，不证明真机、渲染或 Minecraft 启动成功。

## 检查

### Android 独立执行进程的堆指针兼容（80405）

NeoForge 的 `MERGE_MAPPING` 处理器曾以 134 退出，并由 Bionic 报告 `Pointer tag ... was truncated`。安装处理器与游戏通过 APK 内的 `libhxz_jvm_exec.so` 独立执行，不能依赖父应用的 manifest 堆标记策略。

`hxz_vm_heap.cpp` 只链接进该执行程序，在 `main` 最前、读取任务和加载渲染库/HotSpot 前设置兼容策略。API 31+ 使用公共 `mallopt(M_BIONIC_SET_HEAP_TAGGING_LEVEL, M_HEAP_TAGGING_LEVEL_NONE)`；API 30 动态查找旧 `android_mallopt`，仅在该版本使用其 `8 / uint32_t(0)` 接口，缺失或失败则拒绝启动。API 29 无此堆标记机制。设置成功后检查新分配的指针，始终用原始指针释放，不手动剥离标签。失败退出码为 69，原因写入安装/游戏日志。

不要将此兼容设置放入共享库 constructor 或整个社区应用的 manifest；ART、语音和社区进程保留原保护。不要用 `MEMTAG_OPTIONS=off` 代替：Bionic 将该值解释为 TBI，并未禁用软件堆指针标记。

依据：[Android 堆指针标签说明](https://source.android.com/docs/security/test/tagged-pointers)、[Bionic 公共 malloc 接口](https://android.googlesource.com/platform/bionic/+/android16-release/libc/include/malloc.h)、[进程初始化策略](https://android.googlesource.com/platform/bionic/+/main/libc/bionic/libc_init_mte.cpp)、[关闭标签后释放旧指针的 AOSP 测试](https://android.googlesource.com/platform/bionic/+/82c90724e/tests/heap_tagging_level_test.cpp)。这是现有原生依赖的进程级兼容措施，不代表修复了所有第三方库中的指针使用问题。

回归命令：`node scripts/tests/android-vm-heap084.mjs`。执行真实 helper、模拟 Bionic 接口，覆盖 API 分支、接口失败、残留标签、内存不足、原始指针释放和 executor 接入边界。该宿主测试不能替代 Android 实机完成安装及进服验证。

```powershell
node scripts/tests/package-runtime084.mjs
```

测试使用明确的合成 ELF/JAR 元数据夹具与固定真实工具及官方 unsafe JAR，41 项覆盖正式未签名/候选契约、候选输出隔离、发布阻断、重复输出摘要一致、缺失组件/来源/JNA、锁摘要、未锁文件、错误 ABI、禁止 launcher 类、renderer/OpenGL/unsafe 声明、未供应的 ELF 动态依赖和直接读取 ZIP 原始 module.json 验证 moduleSha256；结果写 `.runtime/review084/packager-test-*/results.json`。夹具不能运行，也不能作为真实运行资源使用。未执行设备测试、发布或正式签名。
