# 0.8.2 LINKING：第三值夜

本页记录 0.8.2 的新增内容、实际可完成的任务与无覆盖发布步骤。部署客户端或社区服务端不会自动发布剧情。是否已经上线，以正式接口和发布记录为准。

## 观察者世界与续写边界

LINKING 是观察多个世界、保存并核验其记录的世界。新增章节把这一职责落实为玩家亲手完成的校准、纸边复核与来源交接。它不把馆员与长明人物建立身份对应，也不让馆内操作改写长明人物经历。尚未在故事中揭示的背景继续保留，玩家只依据已经开放的记录推进调查。

原章与前两卷的已审定文本、档案标识、人物事实、音乐门禁和纪念物不变。白枝的伤亡不因一次校准撤销；莉莉安下落、北偏东缺帧及铃声来源继续保持未查明；第三颗星先碎与第四颗核心星片、水晶缺失不混为一事。新出现的溪岸二号只增加一个独立观察对象，不用于解释原作空白或复活人物。

前两卷沿用既定人物与事件的证据边界；本次只新增档案馆内的观察工作，不修改独立剧情项目。

## 0.8.2 管理能力与旧版本兼容

- 新后端在 `GET /api/admin/linking` 返回 `observerExpansion`，客户端以这个能力声明决定是否显示新建入口。旧服务没有声明时不展示会报错的新入口。
- `POST /api/admin/linking/observer-expansion` 接受 `{"chapter":"linking-volume-02","revision":最新第二卷草稿版本}`。要求第二卷已经正式发布、未归档、未结束且正式稿含最终任务。检查与创建在同一事务中执行。
- 创建只新增第三值夜草稿和缺失的两件纪念物，不修改第二卷及原章的正文、草稿、revision、正式状态或玩家记录。已有同 ID 章节时返回 `alreadyExists:true` 和已有稿，不覆盖它的内容、不重新创建物品、不发布。
- 同时创建仅有一次真正写入；过期 source revision 返回 409。目标已存在时重试可安全返回既有稿，即使输入 revision 属于上一次请求。调用者必须检查 `alreadyExists`，不得把已有自定义稿直接当作模板发布。
- `GET /api/admin/linking/chapters/{id}/published` 是管理员只读正式稿接口，返回正式 `revision`、当前 `draftRevision` 与正式正文；不返回口令及其哈希。普通玩家无权调用。该接口方便对照未经审阅的草稿，不自动替换或合并稿件。
- 新专用导入与正式稿读取接口最低后端版本为 0.8.2。实际章节仅使用 0.8.1 已支持的 `read`、`code`、跨章前置与 `collectible`，旧 0.8.1 桌面/安卓客户端仍可从普通目录阅读、做任务和领取纪念物；管理员应使用升级后的服务与管理页创建内容。

## 发布顺序：不得覆盖未审阅草稿

1. 在一致性备份和服务升级完成后，重新读取章节列表、正式稿与草稿。不要用本文记录的历史 revision 执行写入。登录凭据不要写进公开脚本、文档或日志。
2. 本次 2026-10-20 的只读快照中，原章 `chapter-1f7p9oe` 的正式/草稿版本均为 11；第一卷草稿 5 未发布；第二卷草稿 1 未发布。第一、第二卷所有可见正文、标题、顺序、奖励、排期与前置均与当前 0.8.1 模板一致；口令不回传，仅能确认已配置。**这不是固定线上状态。** 如果重新读取存在差异，先审阅该差异，不重新运行整组导入覆盖章节。
3. 原章正式稿已经包含归途灯标时，不重发原章。逐一核对第一卷、第二卷最新草稿，按第一卷 → 第二卷调用现有 `POST /api/admin/linking/chapters/{id}/publish`，body 为各自刚读取的 `revision`。任一 409 都应停止，重新读取；不得盲目用新 revision 把别人的编辑发布。
4. 再次读取第二卷，调用第三值夜创建接口。核对返回的新章为 `published:false`；如果 `alreadyExists:true`，先比对其内容与已审阅候选。打开管理员只读预览，确认 7 档案、10 任务、2 纪念物和第二卷前置。
5. 仅发布第三值夜目标 ID，使用刚读取、已核对的目标 revision。不要因追加新章而保存或发布第二卷未审阅草稿。
6. 使用普通角色验证：未完成第二卷时目录可见但正文与操作被锁；完成前置后可依次阅读和验证三个口令；最终两件物品各只发一次。已有音乐效果、其他章节进度和权限应保持不变。
7. 重新读取正式目录、正式第三值夜以及开头/两卷版本，保存发布记录。实际正式发布由主线程执行，本模块和隔离测试不会连接生产写入。

若上线后需要临时撤回，使用章节归档接口保留记录；不要删玩家 `linking_progress`、`linking_rewards` 或背包物品。要归档前卷时必须先处理依赖它的第三值夜，发布接口会阻止悬空前置。纪念物标识与已存在权限商品冲突时事务整体回滚，不能借剧情领取权限商品。
