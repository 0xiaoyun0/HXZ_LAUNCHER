# 0.8.1 使用与升级

0.8.1 基于 0.8.0，修复退出恢复与重复更新，精简桌面入口，统一实例文件管理，并重排 Android 的页面与设置。完整变更见 [发布说明](0.8.1发布说明.md)。

| 组件 | 本次版本 | 升级方式 |
| --- | --- | --- |
| Windows 启动器 | 0.8.1，x64 / ia32 | 安装版使用内置更新或同架构安装器；便携版保留 profile 后更换程序 |
| Android 社区客户端 | 0.8.1 / 80101 | 使用原正式签名覆盖安装，最低 Android 10 |
| 社区服务端 | 0.8.1 | 保留 data 与 .env，使用完整包或签名更新载荷 |
| MCDR / NeoForge 游戏服务端桥 | 0.8.0，原文件 | 本次原样复用 0.8.0，不需要为客户端升级重新部署 |
| Android 可选游戏运行组件 | 0.7.0 / 70003 | 继续使用原组件，不随社区客户端重复安装 |

两份桥附件保留 `hxz-community-bridge-0.8.0-mcdr.mcdr` 和 `hxz-community-bridge-0.8.0-neoforge-1.21.1.jar` 的名称与内部版本。其内容及 SHA256 与 0.8.0 发布原件一致；出现在 0.8.1 附件中不表示桥已经改为 0.8.1。部署方法继续参见 [游戏服务端桥说明](0.8.0游戏服务端桥.md)。

## 保留已有数据

Windows 安装版沿用既有应用身份和数据目录，使用与当前系统一致的 x64 或 ia32 安装器。账号、设置、卡片布局与游戏目录继续保留。便携版先完全退出并备份整个 profile，再覆盖程序或把 profile 复制到新版便携目录。保留原游戏目录及实例；无需重新复制 .minecraft。

Android 直接覆盖安装 80101，保留账号和设置。不要先卸载社区客户端或独立游戏运行组件；卸载会清除对应应用的数据。社区客户端与游戏组件使用各自的数据目录。

升级不会清空社区积分、背包、论坛、LINKING 进度或已发布章节，也不会自动创建或发布两卷续篇。入口精简不等于删除服务器中的历史记录。

## 新界面从哪里进入

桌面首页以角色、实例、启动和服务状态四张默认卡片为主，默认三服仍可在首页选择并启动。更新集中在设置的「下载与更新」；反馈位于右上角，任务与日志位于右下角。主导航保留常用栏目与 LINKING，可用「快速前往」或 Ctrl+K 查找入口。

实例管理中集中查看模组、资源包、光影和机械动力蓝图文件，可启用、禁用或拖入导入；同名文件受到保护，游戏运行期间暂停写入。原有实例隔离设置继续生效。

Android 默认打开聊天，底部导航为「聊天、社区、游戏、LINKING、我的」。点击语音房间可直接加入收听，底部通话控制跨页保留。社区切换论坛、蓝图、委托和音乐；游戏切换服务器、小游戏与联机大厅；账号、背包、商城与单页设置从「我的」进入。迷你播放器的曲名可直接返回音乐页；正在通话时，音乐分享使用当前房间。设置中的更新公告已移除，检查、下载和安装更新仍保留。

## 社区服务端升级

1. 停止服务，备份完整 data 目录、.env 和自定义代理配置。SQLite 运行时不要只复制一个数据库主文件。
2. 首次部署使用完整服务端包；已有服务使用更新载荷或后台签名更新。它们是同一服务的两种交付方式，无需启动两个服务。
3. 保留 data 与 .env，继续使用原启动方式。自行提供运行时需要 Node.js 24；Windows 完整包带有对应运行时。
4. 启动后检查管理员登录、普通账号、聊天、旧内容与 LINKING 原章，再处理新草稿。新版客户端的续篇管理、跨章前置和外观解锁需要 0.8.1 服务端接口。
5. 回退时停服，并同时恢复升级前的程序与完整数据备份。

## 管理员检查 LINKING 两卷

桌面管理员登录并连接社区后，进入 LINKING，活动上方可见「0.8.1 剧情预览」。此入口读取随客户端提供的只读稿，可直接切换《第七门的回声》和《迟到的北行信》，读完后选择「返回线上档案」。它不会创建线上草稿、保存进度、验证口令或发放奖励；普通成员不显示该入口。

要准备正式内容，先将社区服务升级到 0.8.1，再以管理员打开「管理活动 → 章节与档案」。在「两卷续篇草稿」中选择承接的原章，点击「检查原章与创建条件」。原章需要包含「归途灯标」任务；尚未具备时，按编辑器提示补齐原章续写并保存。随后点击「创建两卷续篇草稿」，系统保留原章，另建两卷未发布草稿；同名卷已存在时停止创建，不覆盖已有内容。

编辑器中的「只读预览当前草稿」用于检查当前编辑内容，与桌面内置稿的入口不同。检查正文、任务、跨卷条件与排期，保存后分别点击「发布当前草稿」，玩家才会收到正式内容；原章新增的前置任务也须先发布，玩家才能完成。

正式玩家须完成原章「归途灯标」后进入第一卷；第二卷还要求完成第一卷最终归档任务。卷内依次阅读并完成口令任务，由服务端验证前置。旧原章中的人工审核条件仍按原规则生效，两卷主线本身无需人工审核。任何管理员预览都不会替玩家完成这些条件，也不会解锁音乐档案等外观。音乐档案要求服务端确认完成已发布任务「让回声归位」（snow-ash-restore-audio）：先完成白枝阅读前置，再阅读「回声归档 · 重新接通」。完成后在音乐页出现一次解锁提示，可选择档案或经典外观；未解锁时隐藏档案样式入口。动画关闭或系统要求减少动态效果时显示静态提示。具体发布顺序与恢复边界见 [LINKING 上线准备](0.8.1-LINKING上线准备.md)。

## 验证范围

发布前的隔离功能回归、桌面本机运行和 Android 网页布局检查各有记录；它们不等同于实体 Android、实体 Windows 7、公网游戏服或所有网络环境的验收。第三方音乐与媒体仍受账号权限、地区、版权和网络状态影响。许可证及第三方声明随对应发行文件保留。
