# 幻想镇 0.8.4

本次基于 0.8.3，重点修复下载恢复、实例列表布局，并引入幻想镇自己的安卓游戏运行宿主。

## 安卓修订 80413

- 修复 80412 独立游戏进程启动时找不到 `libinstrument.so`、Java VM 在运行游戏前直接退出的问题。按 FCL 的运行时初始化方式，以绝对路径预加载 `libjli.so` 与登录/联机代理需要的 `libinstrument.so`，明确指定当前 Java 的引导库路径。
- 保留 `-javaagent` 原生语义，不移除皮肤站认证或联机代理，不降低账号验证要求。组件缺失或依赖加载失败会在进入 VM 前给出具体原因及修复提示。
- 保留 80412 的 FCL NG-GL4ES / EGL 直接呈现。运行模块内容不变，无需重下整合包，覆盖安装保留账号和存档。
- 已对真实 JNI 启动函数进行六种本地库加载边界回归，并验证编译和签名；这些检查使用模拟 Android 链接器边界，不等同于手机实机启动验收。

## 安卓修订 80412

- 按最新授权实际引入 FCL 官方 EGL 桥接源码和同一固定提交中的 ARM64 NG-GL4ES（Krypton Wrapper）渲染库，保留开源许可、署名、修改说明及完整 Android 构建源码。
- 自动模式改为 NG-GL4ES 硬件渲染，直接提交到 Android Surface；此路径不再分配双帧共享像素缓冲，不再每帧经 CPU 复制画面。兼容设置中仍可手动选择原有 Zink 或软件模式。
- 游戏 JVM 使用独立 `:jvm` 服务；Surface 通过 Binder 传递，触控和鼠标通过同 UID 通道传递。窗口销毁期间保留图形上下文，恢复窗口后重新绑定，退出时回收进程，防止崩溃服务重复重启。
- 保留既有皮肤站账号、HXZUP、整合包安装、输入与存档；图形组件随应用覆盖安装，无需重新下载已装好的游戏运行模块。
- FCL EGL 窗口生命周期、240 次 GLFW 直接提交、输入及原生构建定向检查通过；这些检查不等同于真机帧率或所有模组验收。现有 Java/上游图形库仍限 4 KiB 内存页设备。


## 安卓修订 80411

- 对照 FCL 固定官方源码审查游戏准备、认证、JVM、渲染、输入及原生依赖，按 HXZ 自有架构独立实现；阅读范围与未迁移的能力列入审查文档。
- 下载依赖和安装器时检查 JAR/ZIP 结构，错误页不会被当作有效缓存；重试安装时清理已损坏的处理器产物，取消任务保持明确的取消结果。
- 启动前验证皮肤站登录，凭据失效时按协议刷新并校验角色；设置页面不额外验证账号，防止网络请求拖慢设置操作。
- 校验 Java 的主版本和 ARM64 架构，修复嵌入 JVM 参数与显式 classpath 转换；失败时清理临时凭据文件。
- 修复缓慢触控拖动被当作点击、相对鼠标位移丢失、切换页面后按键残留；完善实体键盘、鼠标按键与滚轮处理。
- 修复核心 OpenGL 上下文的扩展查询方式和空扩展名处理，保留真实 GPU 探测与既有分辨率策略。
- 完成定向回归与 Android 编译；当前仍有像素传递成本，未宣称达到 FCL 的真机帧率。覆盖安装保留账号、运行模块、游戏与存档。

## 安卓修订 80410

- 修复 Minecraft 26.2 初始化键盘时调用缺失的 `glfwSetPreeditCallback` 导致空指针崩溃；补齐 LWJGL 3.4.1 所需的七项输入法/预编辑接口、状态与回调。Android 键盘继续负责实际输入与候选栏。
- 自动渲染改为在隔离进程中真实创建 OpenGL 3.3 上下文并验证试绘制，不再仅凭系统 Vulkan 声明跳过 GPU；拒绝把 softpipe/llvmpipe 等软件模拟当作 GPU 加速成功。
- GPU 检测失败时保留具体原因并提示本次使用软件兼容渲染，下次仍重新探测；手动选择软件渲染予以保留，手动选择 GPU 失败不静默换成软件。检测有 12 秒超时、取消及进程清理。
- 未自定义分辨率时默认限制为最多 1280×720 范围（保持屏幕比例），软件兼容模式默认最多 960×540；已有自定义比例继续生效。诊断显示请求渲染器、实际驱动和渲染尺寸。
- 仅在 Surface 或画面尺寸变化时重新设置缓冲；连续帧使用整块复制，保留翻转、留白和背压保护。保留必要的 GPU 完成同步，不以画面错误换取速度。
- 已完成真实 LWJGL 调用、原生接口、呈现内容及渲染选择的定向回归和编译。参考 FCL 官方渲染链路后独立实现，没有移植其启动器代码；这不是对真机帧率的保证，仍需设备验收。
- 当前构建 80410 可覆盖安装，运行模块不变；保留账号、游戏、模组、设置与存档。

## 下载与安装

- 登记 34 个文件来源，另列 5 个元数据来源；在下载节点页面区分官方和镜像，显示本机检测结果。
- 默认保持官方源优先、32 并发。同一文件失败后，依次尝试能提供相同版本、路径和校验值的备用来源。
- 修复官方源受其他任务的临时冷却影响而被错误后移的问题；扩大 Maven、加载器及公开发布文件的适用备用范围。
- 保留校验、断点、取消和重试机制。下载服务不可达时提示具体节点，不把单个服务失败误报成本地断网。

34 个来源分别覆盖不同资源，不代表每个文件都有 34 份副本。节点状态随地区和时间变化；全部来源失效、资源删除或权限不足仍会如实提示。

## 安卓游戏运行

- 社区 APK 内含自行实现的游戏准备、账号交接、窗口和触控宿主；首次玩游戏时在应用内下载运行资源，无需另装游戏引擎 APK。
- 支持按默认服务器配置准备游戏、加载器与 HXZUP 更新；社区选中的皮肤站角色直接传入游戏。
- Java 21/25 按游戏元数据选择；运行模块、文件清单及资源散列经过签名验证，下载中断可以继续。
- 提供内存、图形渲染、下载并发、触控大小、分辨率及灵敏度设置。Minecraft 26.2 使用 OpenGL 游戏后端。
- 接入与桌面大厅兼容的公网直连和 P2P 协议、实例核对及房间生命周期；游戏流量不经社区中继。
- 完整本地整合包在非强制更新且更新服务暂时不可达时可继续使用；不忽略缺文件、损坏、未完成事务或鉴权失败。
- 启动前核对客户端模组适配：仅对已核实的桌面专用客户端模组按文件散列隔离，保留原件及原因。HXZUP 更新前恢复原件参与校验，更新后重新检查，不删除服务端要求的内容模组。
- 游戏诊断区分有明确证据的内存不足、电脑架构库、图形接口、Java 版本及服务器模组不匹配；未知错误保留日志，不靠猜测自动删模组。

这是独立安卓宿主的首次验收版本。已做编译、协议和依赖检查；按用户安排，尚未进行设备上的安装、画面、音频、触控、三服连接及跨端联机验收，不能把这些检查等同于实机成功。

当前游戏模块要求 Android 10 或以上、ARM64、4 KiB 系统内存页。16 KiB 页设备会在下载前提示暂不兼容；社区功能不受此限制。大型整合包和电脑专用模组仍受设备内存、驱动与模组兼容性限制。

新引擎使用社区应用自己的游戏目录；旧版独立引擎中的存档不会自动迁移或删除。卸载社区应用前须先备份其游戏存档。
