# MC 联机大厅 · 0.8.4

Windows 房主使用自己的单人世界，玩家选择相同版本、加载器和模组，通过房间目录或邀请加入。社区负责开房授权、目录、连通性探测和 P2P 信令；MC 游戏数据在玩家与房主之间传输。

## 使用流程

1. 社区管理员在联机大厅授予房主创建权限。
2. 房主选择实例和网络范围，检测并启动。进入单人世界后，Java 助手自动开放本次世界；退出世界或关闭房间即断开。
3. 伙伴在公开房间或私有邀请中点击启动并加入。启动器自动核对已安装实例的版本、加载器与模组摘要；缺少可信默认服或原版实例时，确认安装后再加入。未知自定义整合包需先向房主获取整包。每个伙伴独立连接同一房主，不要求共用一台电脑。

连接优先顺序：可达的公网 IPv4 / IPv6 或已配置的虚拟局域网 → WebRTC P2P。P2P 使用 STUN 寻找地址，通过社区 /lobby-signal 交换握手，再使用有序可靠 DataChannel 传输现有加密游戏通道。不会通过社区发送 MC 游戏数据。

P2P 受 NAT、UDP 和系统防火墙影响，不能保证所有网络都成功。穿透失败会说明当前不可达；可改用公网地址或自行配置的虚拟局域网。未配置 TURN，也没有隐藏的社区游戏中继。社区仍然需要在线完成身份和初次握手。语音转发属于独立功能，继续保留。

## 配置与安全边界

- HTTPS 代理放行 /ws 和 /lobby-signal 的 WebSocket Upgrade；示例在 apps/community-server/nginx-community.conf.example。
- 游戏邀请仅本次房间有效，包含加入凭据，请私发。退出房间后凭据失效。
- 信令限制消息大小、频率、握手时间与待连接数量；拒绝二进制游戏流量和媒体/TURN 协商。MC 数据有背压和缓冲上限。
- 旧 /lobby-relay 已停用。若客户端仍显示社区中继，先更新客户端及社区至 0.7.1。
- Android 社区支持创建房间、验证邀请、加入电脑或手机房主，并通过本机游戏运行组件启动相同的默认游戏配置。

## 开发与验证

Electron 隔离隐藏窗口只运行本地 P2P 页面，无远程内容与游戏 UI；主进程只接受该窗口 IPC。代码在 apps/desktop/electron/p2p-runtime.mjs、p2p-preload.cjs、packages/engine/core/room-p2p.mjs；信令在 apps/community-server/src/lobby-signal.mjs。

本机已验证 Electron 44 x64 / 22 ia32，两名客人同时加入，分别传输 2MiB 并校验回显，以及慢读端背压。此结果只验证实现，不等于跨运营商 NAT 穿透成功。

## 0.7.3 连接选择

自动方式依次尝试可达公网 IPv4/IPv6 和 P2P；可指定仅 P2P、IPv4、IPv6，或选择路由器 UPnP、PCP、NAT-PMP、手动公网地址/端口。局域网与已有虚拟局域网分别选择对应范围。自动端口映射需要路由器支持，手动映射要求内外 TCP 端口一致。没有 TURN 或游戏中继。

新邀请采用 hxz-room://join/…，载荷放在 URL 路径，支持从聊天文本粘贴和安装版协议唤起。旧 hxzroom:// 格式继续解析。房主更新游戏后同步刷新房间版本清单；伙伴连接前再次核对。

## Android 与电脑互通

手机大厅可以直接加入公开房间或粘贴邀请，也可以在获得开房权限后创建房间。房主启动游戏后进入单人世界，运行组件通过本机端口助手自动开放世界，并向社区进程回报准备状态。客人启动时使用本机回环地址连接加密通道；加入地址绑定原生大厅当前连接，不接受页面自行指定任意游戏地址。

Android 使用原生 WebRTC DataChannel，标签 `hxz-minecraft`，有序可靠传输；与桌面共用 16 KiB 二进制帧、256 KiB 流量窗口和 JSON credit/end 控制帧。DataChannel 内继续使用邀请固定 SHA-256 指纹的 TLS，再发送 operation/id/key 换行握手。社区 `/lobby-signal` 只传递会话描述和直连 ICE 候选，不配置 TURN。

手机可以选择同一 Wi-Fi / 热点的局域网地址，或使用 P2P、公网 IPv4 / IPv6。手机端本轮没有自动 UPnP、PCP、NAT-PMP 或手动路由器映射功能。异地穿透受运营商、UDP 与防火墙影响；双方网络不允许直连时，界面会显示不可达。

公开房间定期更新目录并续验开房许可；失去账号所属关系、授权到期、退出账号或切换社区时关闭通道。独立的到期检查不等待网络续验请求完成。通知提供断开入口，游戏切到前台时社区进程的前台网络服务继续保持连接。

默认整合包允许 Android 经过 `hxz-android-1` 规则适配后的客户端模组差异，但必须同时满足：双方属于同一个已知 `HXZ-survival`、`HXZ-mod-1` 或 `HXZ-mod-2` 预设，Minecraft、加载器和加载器版本完全一致。电脑之间及自定义整合包仍核对完整模组摘要和数量。这条规则不能保证任意电脑模组支持手机，游戏本身仍可能拒绝不兼容的服务端模组协议。

本轮新增本机验证：Java 与 Node 双向 TLS、固定指纹拒绝、邀请与换行协议，以及每方向 600,000 字节回显；实际 Java GamePeer 与桌面 P2P 帧处理器通过内存传输适配器交换 1,200,000 字节，并验证停止发送直到接收方释放流量额度。真实 Vue 大厅在 320 / 390 像素宽度检查布局与启动参数。这些检查没有执行 Android 原生 ICE、AndroidKeyStore 或实体手机上的 Minecraft 世界；手机与电脑的实际游戏互通仍需用户在设备上验收。
