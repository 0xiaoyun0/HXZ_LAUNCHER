# UU远程 / 网易UU远程官方资料调研（0.9.0）

- 调研日期：2026-10-27（Asia/Shanghai）
- 资料范围：网易 UU 远程官网 `uuyc.163.com` 的产品页、帮助页与软件许可协议；只记录官方公开文字，不推断客户端内部实现。
- 目标：提取连接方式、NAT/隧道/线路、连接质量指标、失败回退和用户可关闭/开关等可合法借鉴的产品体验。

## 结论先行

1. **连接入口分层清楚。** 同账号设备从设备列表进入桌面；远程协助通过设备 ID + 验证码；TV 页明确写出局域网和非局域网均可一键串流。远程协助验证码可以按“关闭自动更新 / 每小时 / 每 12 小时 / 每 24 小时”配置。
2. **公开资料明确出现两类穿透能力。** 运维版命令行提供“打洞优化”布尔开关；端口映射页把能力称为“隧道穿透”，可把远端设备或其局域网 TCP 服务映射到本机，并复用已有远控连接。两者都没有公开完整的直连/中继拓扑或自动回退算法。
3. **路径选择主要通过代理模式和产品侧网络能力表达。** 代理页提供“不使用代理（本机直连，默认）/系统代理/手动 HTTP 或 SOCKS5”三种模式，并把“检测可用”和“启用生效”分成两个动作；办公页宣称“高速专网、全球网络节点、支持局域网远程”，但没有公开线路列表或用户选择具体节点的入口。
4. **质量控制是可见参数，不是黑盒承诺。** 官方公开了分辨率、画质、帧率和码率控制；真彩页写明最高 4K、144 Hz、自定义码率最高 500 Mbps；运维版命令还给出按帧率/分辨率组合的建议码率表，并说明参数冲突时尽可能取最低可用码率。
5. **失败处理偏“可操作回退”。** 错误码页给出关闭安全软件 → 重启 → 重装最新版 → 更换安装路径 → 联系客服并提交错误码/场景/系统/版本/截图的顺序；TV 连接出现“优化连接路径”时建议重启电视、降低被控端分辨率或帧率再试；端口映射失败则按在线状态、目标服务、地址端口、本地端口占用、TCP 协议逐项检查。
6. **用户拥有明确的即时停止和模式开关。** 被控方可断开连接或取消分享来停止授权；观看模式可在会话内随时关闭且无需重连；代理、端口映射规则、麦克风、隐私屏、静音、自动锁屏、精简版开机自启等均有显式开关或状态。

## 1. 连接方式与授权体验

### 1.1 同账号设备连接

- 电脑帮助页的流程是：两端登录就绪 → 控制端设备列表看到目标 → 点击“进入桌面” → 连接后从“控制中心”调整分辨率、画质、窗口、声音、安全。
- TV 产品页把网络范围写成“局域网或非局域网均可一键串流远控”，说明用户不必先判断是否同一局域网。
- 产品页的办公场景写有“支持局域网远程”，但未说明内部使用何种发现或传输协议。

### 1.2 远程协助连接

- 被控端复制设备 ID 和验证码，控制端输入两项后发起远控；精简协助版可免安装、免登录。
- 完整协助版可在验证码设置中选择关闭自动更新、每小时、每 12 小时或每 24 小时更新；移动端/PC 端还能查看最近连接历史。
- 协议明确：被控制方在会话中可以随时断开连接或取消分享，停止授权后控制方不得继续操作。这个“授权可撤回”是最直接的安全闭环。

## 2. NAT、隧道与线路选择

### 2.1 官方明确公开的 NAT/穿透相关点

- **打洞优化（仅运维版命令行）：** `uuycmgr.exe -l true/false`。官方原文说明运维版默认关闭“打洞优化”，打洞次数控制在十几次范围；开启优化策略时连接次数会明显上涨。该页没有把“打洞”解释成完整的直连/中继状态机，因此只能把它记录为一个可切换的穿透尝试策略。
- **端口映射隧道：** 官方称端口映射为“隧道穿透能力”，把远端设备本机或其局域网内 TCP 服务映射到本机端口；适用条件包括不方便配置路由器端口转发、公网 IP 或第三方内网穿透工具。已有远控视频/文件传输连接时会复用，不重新建立连接，也不影响远控画面。
- **端口映射状态与回收：** 面板显示“已连接”和“成功”；每条规则有独立启停开关，灰色停用但保留，关闭端口映射面板后映射不会继续（若仍有其他远控/文件连接，底层会话是否保留取决于那些连接）。仅支持 TCP，不支持 UDP。

### 2.2 线路/节点选择的公开边界

- 办公产品页公开“高速专网、全球网络节点、支持局域网远程”等产品能力描述；TV 页公开“局域网或非局域网一键串流”。这些页面没有公开节点清单、线路下拉框、直连/中继标签或用户手动选线流程。
- 代理帮助页是用户唯一明确可见的路径选择：不使用代理（本机直连，默认）、系统代理、手动 HTTP/SOCKS5。手动代理需要“检测”后再“启用”，切换回“不使用代理”可关闭。
- **未发现官方公开的自动“直连失败→中继”判定、候选线路排序、NAT 类型检测或中继节点选择说明。** 产品实现不应根据“专网/节点/打洞”宣传语反推这些内部细节。

## 3. 连接质量指标与可调参数

### 3.1 官方直接给出的参数

- 电脑互控帮助页：远控控制中心可调分辨率、画质、窗口、声音、安全。
- 真彩产品页：4K、最高 144 Hz、自定义码率最高 500 Mbps、真彩 4:4:4；真彩是可选显示模式，不是默认必开。
- 运维版命令行：被控端可限制码率上限 1–500，`0` 取消限制；官方给出按帧率（≤30/≤60/≤90/≤120/>120）与分辨率组合的 Mbps 建议表。页面特别说明当码率、画质、刷新率冲突时不能达到目标值，但会尽可能使用最低码率。
- 功能快捷键帮助页：可显示/隐藏“网络状态”，但该公开页没有说明网络状态包含 RTT、丢包、抖动、编码队列或吞吐中的哪些字段。

### 3.2 对产品体验的可借鉴点

- 让用户看到“分辨率/帧率/码率”的组合约束，并在冲突时解释哪个参数会被压低；不要只显示一个笼统的“网络差”。
- “检测”和“启用”分离（代理页）是可复用的状态设计：检测只回答配置是否可用，启用才改变连接路径。
- 可提供一个可隐藏的网络状态入口，但指标定义应在产品内明确；UU 官方公开资料目前不足以支持 RTT/丢包等具体字段的结论。

## 4. 失败回退与重试路径

### 4.1 通用错误码顺序

错误码帮助页给出的通用顺序是：

1. 退出 360、电脑管家等安全软件并结束相关进程；
2. 重启电脑或被控端后再试；
3. 卸载并重新安装最新版 UU 远程；
4. 安装/更新仍失败时更换安装路径；
5. 仍未解决时联系官方客服，并提交错误码、报错场景、系统版本、UU 远程版本和截图。

网络相关错误明确指向“内网限制或防火墙限制”，建议检查网络环境/防火墙后重试。

### 4.2 连接路径优化提示

TV 帮助页没有给出内部路径切换按钮；出现“优化连接路径”时给出的用户动作是：重启电视；或降低被控端分辨率/帧率后重启电视；仍无法解决就从 TV 端反馈并提交问题。该流程可借鉴为“提示原因 → 降级质量参数 → 重试 → 反馈”的可解释回退。

### 4.3 专项能力失败

- 端口映射失败：先确认目标设备在线且连接状态为“已连接”，再确认目标服务、目标地址/端口、本地端口占用和 TCP 协议；远端局域网服务还需确认跳板设备能访问该地址。
- 本地磁盘共享失败/超时：官方建议点“重新共享”；多次失败检查双端网络；极端情况断开远控后重连。
- Android 屏幕共享：被控端请求需在 60 秒内同意并完成系统授权；超时后由主控端重新发起请求。

### 4.4 官方未公开的自动回退

公开帮助页没有说明远控视频在直连失败时是否自动切换中继、切换耗时、重试次数、线路优先级或回退时是否降码率。因此这些行为不能写成 UU 的已证实实现。

## 6. 对 HXZ 远程体验的合法借鉴建议

1. **把路径模式做成显式状态。** 至少区分“直连/系统代理/手动代理”与“检测中/可用/已启用/不可用”；不要让“检测成功”暗示已经切换。
2. **把授权撤回放在会话内。** 提供明显的停止分享/立即断开，并在被控端显示当前授权状态；临时协助默认短时验证码，长期协助再允许可配置更新周期。
3. **给出质量参数的安全组合。** 让分辨率、帧率、码率联动，并在超出网络或设备能力时明确提示“已按最低可用码率运行”或建议降级。
4. **失败时给下一步。** 使用“原因 → 可执行动作 → 重试 → 收集诊断”的顺序；诊断至少带错误码、场景、版本、系统、截图/日志。
5. **把只看不控作为会话模式。** 观看模式无需重连、可一键恢复控制，适合排障/演示并降低误操作风险。
6. **仅借鉴已公开行为。** UU 的“高速专网/全球节点/打洞优化”可以作为交互文案或开关设计参考，但不能据此声称已有某种中继拓扑、NAT 分类或自动选线算法。

## 7. 资料缺口与使用边界

- 未找到官方公开的 NAT 类型检测、候选线路/节点列表、直连与中继状态指示、自动回退判定、RTT/抖动/丢包字段定义或中继节点选择规则。
- “高速专网”“全球网络节点”“超低延迟”等内容来自产品页的能力/宣传描述；除非另有技术文档，不应把它们写成协议细节或 SLA。
- “打洞优化”明确出现在运维版命令行教程，适用范围是运维版；不要把该开关默认行为直接外推到普通客户端。
- 本文只做产品体验研究，没有修改 HXZ 代码、协议或配置。
