# 安卓 80417：网络、会话与水体兼容

## 本次交付

- 接入 FCL 的 Android DNS 配置思路：优先写入当前网络的 IPv4 DNS，再添加区域公共备用 DNS，传给 Android OpenJDK 的 `ext.net.resolvPath`。这个路径供 JNDI/SRV 查询使用；保留游戏的 IPv4、IPv6 和正常 TLS 验证，不把所有网络失败都解释为 DNS 故障。
- 将社区会话获取放在最终游戏账号校验之前，避免社区 `/api/session` 刷新皮肤站 token 后，游戏仍使用旧 token。游戏运行中固定该认证会话，社区 bearer 未过期时正常使用；需要重新认证时暂缓，退出后恢复。每 20 秒续期，90 秒失联自动释放，社区进程重建可恢复未过期保护。手动注销或切换账号仍结束游戏会话。
- 已绑定角色的 token 刷新不再重复传 selectedProfile，与 FCL 的登录恢复方式一致；校验返回角色和 clientToken，失败不降为未验证在线会话。
- 针对 NG-GL4ES 的 GLES 3.0 基础顶点模拟路径中，16 位索引加偏移后回绕的问题，增加 32 位索引提升适配。只处理 EBO 三角面绘制，保留原件及其他路径，恢复原缓冲绑定；继续使用 EGL 直接呈现，不启用 CPU 像素复制。首次触发会记录 `[HXZ graphics] base-vertex 32-bit index repair active`。
- 游戏画面上方增加“日志”。即使停在模组加载画面，也能读取两份当前日志，并从实际游戏 JVM 请求两次线程快照；无响应时展示已获取日志，不强制结束游戏。诊断经过原有凭据脱敏。后台仅检查请求文件，线程抓取只在用户点击时运行。

## 参考依据与边界

- [FCL 固定源码](https://github.com/FCL-Team/FoldCraftLauncher/tree/efe4dcc5dbc78c55be177c330239e12845ae7ccf)：`SystemDns.kt`、`SplashActivity.kt`、`DefaultLauncher.java` 的 DNS 配置；`YggdrasilAccount.java` 和 `AuthlibInjectorAccount.java` 的校验、刷新与认证参数。
- 当前运行模块中的 Android OpenJDK 已含 `ext.net.resolvPath` 补丁，本次接上缺失配置，无需重新下载 Java/游戏运行模块。
- [NG 固定源码](https://github.com/FCL-Team/NG-GL4ES/blob/472f55e549e2bc76c87454905db52661c3cf57a9/src/gl/drawing.c) 中，GLES 3.0 模拟将 basevertex 加回 GLushort 数组，存在跨越 65535 的回绕风险。适配通过 LWJGL 的真实 GLX 查询入口接入；上游二进制与许可保持原样。
- 截图的水面条纹、拉伸不能单独证明所有场景都由同一索引问题造成。本次修复这一明确的溢出模式；没有连接 vivo 实机，因此不声称已验收截图场景、帧率、模组加载结束或服务器入服。其余卡住原因需从新增的实时诊断继续定位。
- 这不是复制 FCL 下载器后宣称更换游戏 TCP 模块。超时仍可能来自服务器端口、路由、认证服务或模组协议；不更改服务器验证模式，不绕过皮肤站认证。

## 定向验证

- `scripts/tests/android-network084.mjs`：生产会话方法及 DNS 生成器，复现 token 刷新顺序、游戏中防刷新、退出恢复、租约失效/重启恢复；另启动真实桌面 HotSpot 验证按需 agent 的两次线程快照。
- `scripts/tests/android-ng-render084.mjs`：索引边界回归，以及生产 C++ 适配器、真实 GLX 分发入口配合模拟 GL 缓冲，检查索引不回绕、原缓冲不变、绑定恢复、无效范围回退和多次绘制。
- 保留启动认证、崩溃诊断脱敏、触控边界回归。签名与构建验证针对正式 APK；不等同于手机实机游戏测试。
