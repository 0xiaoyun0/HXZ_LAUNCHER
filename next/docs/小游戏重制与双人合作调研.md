## 4. 可直接使用的 API 与输入边界

以下 API 来自锁定发布版源码。[NES](https://github.com/bfirsh/jsnes/blob/cbad9f1db57dfb275b90ffa26f9c479c355d8d5c/src/nes.js)、[ROM](https://github.com/bfirsh/jsnes/blob/cbad9f1db57dfb275b90ffa26f9c479c355d8d5c/src/rom.js)、[Controller](https://github.com/bfirsh/jsnes/blob/cbad9f1db57dfb275b90ffa26f9c479c355d8d5c/src/controller.js)

| 需求 | API / 行为 | HXZ 接入判断 |
| --- | --- | --- |
| 创建核心 | `new NES({onFrame, onAudioSample, sampleRate, onBatteryRamWrite})` | 同机与联机共用低层核心；无需 WebGL 或服务端 ROM。 |
| 导入原游戏 | `nes.loadROM(Uint8Array)`，也接受 ArrayBuffer / Buffer / 二进制字符串 | 读取文件原始字节；限制大小、验证完整头与声明的 PRG/CHR 长度，再交给核心。源码对截断内容存在提前 break，不能只依赖其 magic 检查。 |
| 推进一帧 | `nes.frame()` | 由统一时钟驱动。每个确认的游戏帧只调用一次；屏幕刷新或音频缺样不能擅自增加模拟帧。 |
| 原版画面 | `onFrame(buffer)`，256 × 240 像素 | Canvas 2D 显示，关闭插值并保持比例。官方 Screen 用 `0xff000000 | buffer[i]` 写入 Uint32 像素缓冲。[screen.js](https://github.com/bfirsh/jsnes/blob/cbad9f1db57dfb275b90ffa26f9c479c355d8d5c/src/browser/screen.js) |
| 原版音频 | `onAudioSample(left, right)` | PCM 环形缓冲送 Web Audio；模拟采样率双方固定，输出层适配真实设备。无需提取或额外打包原曲。 |
| 双控制器 | `buttonDown(1或2, button)` / `buttonUp(1或2, button)` | NES 本身已有两个控制器。选择原游戏自己的双人模式；不要在游戏外篡改角色数量/生命。 |
| 普通按钮 | A=0、B=1、SELECT=2、START=3、UP=4、DOWN=5、LEFT=6、RIGHT=7 | 每名玩家一字节按键掩码。默认仅映射原手柄八键。不要把现有冲刺或修改后的开火逻辑带入。 |
| 存档 | `nes.toJSON()` / `nes.fromJSON(state)` | 包含 CPU、PPU、PAPU、mapper 和双控制器状态，不含独立 `romData` 字段；恢复前必须加载相同 ROM。深复制/序列化保存，避免把带可变引用的返回对象直接当永久回滚快照。 |
| 重置 | `reset()` / `reloadROM()` | 联机中重开、暂停、恢复都要约定同一帧边界。 |

JSNES 有 turbo A/B 和 Game Genie 接口，但为了满足“原样”默认不启用。原版操作中 A/B 的实际功能以用户 ROM 为准；可提供玩家按键重映射，不改游戏内部逻辑。

### 同机键盘、手柄与触控

- **键盘：** 上游 Browser 默认 1P 为方向键、X/Z、Enter/Ctrl，2P 为小键盘。HXZ 应提供两人独立映射，避开页面快捷键；失焦和退出时释放所有键，防止卡键。[keyboard.js](https://github.com/bfirsh/jsnes/blob/cbad9f1db57dfb275b90ffa26f9c479c355d8d5c/src/browser/keyboard.js)
- **手柄：** 上游有轮询与两玩家分配，但 `poll()` 只有已有 `gamepadConfig` 时才处理游戏输入；源码没有通用手柄的开箱默认映射。因此需要 HXZ 提供标准 mapping 映射/配置和插拔后的释放逻辑，不能仅凭 README 的“支持手柄”宣称任何两只手柄无需设置即可用。[gamepad.js](https://github.com/bfirsh/jsnes/blob/cbad9f1db57dfb275b90ffa26f9c479c355d8d5c/src/browser/gamepad.js)、[W3C Gamepad API](https://www.w3.org/TR/gamepad/)
- **手机：** 上游未提供触控手柄。HXZ 可用 Pointer Events 维护多指状态，并将触控映射为同一八键掩码；需要支持“移动 + 跳跃 + 开火”同时按住、pointercancel 释放、横屏。社区模式手机各自控制自己的座位，同机双人则更适合外接手柄。

## 5. 社区双人建议：输入同步，双方本地运行

这是基于核心 API 的**待实现设计**，上游没有现成房间、匹配、网络合作或同步保证。

1. 两人分别从本机导入同一 ROM。握手比较完整 ROM 的 SHA-256、模拟器版本/构建哈希、协议版本、采样率与运行配置；不一致则说明具体原因并拒绝开始。服务器只需要哈希与房间信息。
2. 房主占 1P、访客占 2P。通过现有社区连接增加专用 NES 房间协议，发送 `{roomId, epoch, frame, player, mask}`。服务端将 player 绑定登录身份/座位，校验帧号、重复包、速率；不要信任客户端自报座位。
3. 双方从同一复位状态开始；缓冲少量帧。某帧收齐双方完整输入后，先调用该帧的 `buttonDown/buttonUp`，再调用一次 `nes.frame()`。包只含按钮，不含 ROM、画面或音乐。
4. 第一版采用等待完整输入的同步方式。晚包就短暂等候，超时暂停并显示网络状态；不凭空猜测对方的按键，也不让某一端自行追帧。输入缓冲从少量帧起实测调整，不能在没有网络测试时承诺低延迟。
5. 定期对双方同一确认帧的规范化模拟状态计算校验值。固定核心版本、模拟采样率与运行选项；不得按各设备 AudioContext 的不同采样率生成不同的模拟状态。失步即暂停，重新开始或从约定位置重放输入。保存和重放仍需实测，不能用存在 `toJSON` 推断已保证跨端确定性。
6. 断线恢复首版可从本地检查点加已确认输入重放；检查点由各端本地保存。`toJSON` 虽不包含独立 ROM 文件字段，CPU/PPU 内存仍可能包含 ROM 派生数据，不能把它当成“肯定不含游戏数据”的任意上传格式。常规协议只传输入与哈希。

JSNES 发布源码的模拟逻辑扫描未发现 `Math.random`；`Date.now` 用在 FPS 统计。但这只是良好的基础，不等于跨 Electron/Android 的长期确定性已经验证。[NES 与状态序列化](https://github.com/bfirsh/jsnes/blob/cbad9f1db57dfb275b90ffa26f9c479c355d8d5c/src/nes.js)、[utils.js](https://github.com/bfirsh/jsnes/blob/cbad9f1db57dfb275b90ffa26f9c479c355d8d5c/src/utils.js)

**联机不要直接使用上游 `Browser`。** 其 `onBufferUnderrun` 会调用两次 `generateFrame()` 自行补音频；双方设备缺样时间不同，就可能推进不同帧数。应使用低层 `NES`，音频缺样时补静音/等待，不改已约定的游戏帧序列。[browser/index.js](https://github.com/bfirsh/jsnes/blob/cbad9f1db57dfb275b90ffa26f9c479c355d8d5c/src/browser/index.js)

WebSocket 可用于第一版社区转发；WebRTC DataChannel 可作为后续降低中继延迟的选项，但仍需要信令与同步协议。DataChannel 本身不会自动解决一致性或穿透失败，故本次不把 WebRTC 作为必须先完成的前置大改。[WebRTC 规范](https://www.w3.org/TR/webrtc/#rtcdatachannel)

## 7. 实施顺序与验收门槛

1. **确定游戏文件来源：** 已核实公开反汇编仓库仍缺独立构建所需原版资源和明确再分发许可；这是当前原版交付的实际缺口。可先完成不依赖商业 ROM 的模拟器壳、输入与联机协议。后续对有合法来源的目标 ROM 记录 SHA-256、大小、头格式、mapper、地区信息，再做真实游戏验收；不自动修补或悄悄替换版本。
2. **同机原版双人：** 先完成离线画面/声音、原版标题菜单与双人开始，两路键盘/两手柄、手机触控、暂停/恢复/退出。验收原版流程与角色操作，不用替代关卡冒充成功。
3. **社区双人：** 双方同 ROM/同版本，验证同时移动跳跃开火、两名角色独立受伤死亡、切关同步、同帧状态校验、掉线与退出、100–300 ms 延迟和抖动下可理解的等待表现。
4. **跨端：** Electron 22 与 Android 10 实机、不同刷新率、后台再返回、音频设备切换、手柄拔出和触控 cancel。至少覆盖一段实际关卡与较长连续运行，记录平均/低位帧率、音频欠载和失步次数。
5. **交付：** 只有完成对应验收的功能才写入发布说明；打包模拟器许可与来源记录，发布目录为 `E:/hxz_la/release/0.6.3`。原版 ROM 是否可以随包分发需要独立授权依据，不能由模拟器 Apache 许可推导。

当前已完成源码/API、版本与许可核对，官方 npm 包 SHA-512 校验，以及本地集成位置调查。**尚未导入或运行用户的魂斗罗 ROM，也未验证同机双人、社区联机、Electron 22 或 Android 实机运行。**
