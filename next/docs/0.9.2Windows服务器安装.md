# 0.9.2 Windows 部署

先部署社区，再装三个游戏桥。社区与 MC 世界的数据均继续使用原目录。安装材料不包含任何账号、密码或接入令牌。

## 社区完整包

1. 停止原社区服务及其计划任务/服务管理器，备份整个原目录。
2. 将 `server/HXZ-Community-0.9.2-windows-x64.zip` 解压到新的固定目录。完整复制旧 `data` 和 `.env`；如果 `HXZ_DATA` 是外部绝对路径，保持它不变。复制数据必须在旧进程停止后进行。
3. 双击新目录的“启动社区服务.bat”，把原 Windows 服务/计划任务的启动路径也改到这里。继续使用原 HTTPS 代理地址。
4. 打开 `/admin/`，使用原管理员账号。在“运行与连接诊断”确认 **0.9.2**、程序目录、数据目录均正确；再检查原聊天、积分、论坛等数据。

完整包修复了旧 `data/.updates/active.json` 始终选择旧下载版本的问题。不要手动删除数据库或更新目录。后台增加“运行与连接诊断”“自动错误收集”“插件市场审核”，看不到这三个入口时先核对实际程序目录及代理是否转发到此进程。

后台“服务更新”使用 `HXZ-Community-0.9.2-update.zip` 和 `community-update.json`，沿用旧版签名及回滚结构。针对本次“更新后没变化”的情况，优先执行上述完整包迁移，以同时更新 supervisor 启动文件。

## 三个游戏服

| 服务 | 游戏桥文件 | 安装位置 |
| --- | --- | --- |
| 原版 `survival` | `hxz-community-bridge-0.9.2-mcdr.mcdr` | MCDR 根目录的 `plugins` |
| 模组一 `mod-1` | `hxz-community-bridge-0.9.2-neoforge-1.21.1.jar` | NeoForge 1.21.1 服务根目录的 `mods` |
| 模组二 `mod-2` | 同一个 NeoForge JAR | 第二个服务根目录的 `mods` |

MCDR 要求 2.12+；两个模组服分别按现有 NeoForge 21.1.250 和 21.1.251 验证编译。游戏桥只放服务端，玩家无需装这些文件。

在社区后台“游戏服接入”给三个服分别创建/轮换令牌。令牌只显示一次，三个服不要混用；轮换会使该服旧令牌立即失效。解压 `HXZ-MC-Server-Kit-0.9.2-windows.zip`，在解压目录打开 PowerShell，按自己的真实目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\install-windows.ps1 -ServerId survival -ServerRoot 'D:\MC\原版MCDR' -MinecraftDirectory 'server' -World 'world'
powershell -ExecutionPolicy Bypass -File .\install-windows.ps1 -ServerId mod-1 -ServerRoot 'D:\MC\模组一'
powershell -ExecutionPolicy Bypass -File .\install-windows.ps1 -ServerId mod-2 -ServerRoot 'D:\MC\模组二'
```

每次只停止对应服，输入 `STOPPED` 和对应令牌。安装脚本会备份旧桥和配置、安装新桥；不会删除世界。MCDR 的 `MinecraftDirectory` 相对 MCDR 根目录，`World` 相对 Minecraft 目录；若现有配置不同，要改为实际目录。也可以按表手动复制组件并填写示例配置。

默认开启状态和统计上报，聊天与白名单修改保持关闭。需要时同时在游戏服配置和社区后台打开；脚本可加 `-EnableChat` 或 `-EnableWhitelist`。开始运行后约 5 秒内应收到心跳，超过 30 秒没有心跳显示离线。后台诊断能查看完整玩家列表、时间和协议状态。

## HXZRE 部署位置和防火墙

社区与三个 MC 服在同一台 Windows 主机时，社区自动管理三个 origin。确认 `.env` 中 `HXZ_FEC_TARGETS` 与真实 MC 监听端口相同，默认依次为 `127.0.0.1:19999,127.0.0.1:19998,127.0.0.1:25599`。`HXZ_FEC_PUBLIC_HOST` 默认为 `ipv4.hxzmc.top`；公网需要放行 UDP 40000、40001、40002，并确认 NAT 转发到这台机器。不要只开放 TCP。

如果 MC 与社区分开部署，关闭社区的自动 origin（`HXZ_FEC_AUTO=0`），在 MC 主机运行安装包 `hxzre/start-origin.ps1`，每个服使用不同 UDP 端口和随机令牌。脚本启动的窗口需保持运行，长期运行可交由现有服务管理器管理。后台服务器预设填写对应 `origin` 和相同 token，并启用补偿。

社区后台对自动管理的本机 origin 提供传输测试；客户端“设置 → 下载与更新 → HXZRE”可从玩家网络实际测试所有配置。只有 Edge → Origin → MC 的完整往返成功才显示可用；端口被拦截时会显示具体失败并回退直连。

## 上线核对

1. 后台显示 0.9.2 和正确程序目录，三个桥收到新心跳。
2. 玩家进出游戏，后台与启动器人数和名单随之更新。MC 公开状态可能只返回名单样本，桥提供完整名单。
3. Windows 启动器能运行不同实例、单独结束进程，设置内可关闭“游戏运行时继续操作启动器”。同一实例同时运行须先创建副本。
4. 导入 SDK 示例，确认权限后启用、停用；提交市场后在后台审核，另一登录账号可下载。
5. 用安装包中的 `verify-community.ps1` 只读检查版本和公开接口；随后在客户端出现真实错误时，到后台“自动错误收集”查看环境、处理状态及说明。诊断关闭或网络离线时不会立即上传。

回滚：先停止新社区，再恢复完整旧目录及其备份的数据；游戏桥备份位于对应服务根目录的 `hxz-bridge-backups`。不要把正在使用的新数据库直接覆盖到旧备份上。
