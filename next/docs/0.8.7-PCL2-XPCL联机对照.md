# 0.8.7 联机实现对照与设计决策

更新时间：2026-10-25

## 调研范围

本次只参考公开项目的架构、状态机和故障处理思路，不复制代码或资源。

- [PCL（Plain Craft Launcher）](https://github.com/Meloong-Git/PCL)：主仓库，作为 PCL 的实现入口。
- [PCL-CE 发布页](https://github.com/PCL-Community/PCL-CE/releases)：核对社区版历史版本与联机相关发布记录。
- [PCL N Terracotta](https://github.com/Nexa-MC/PCLN.Terracotta)：公开仓库明确描述为 PCL N 官方 Minecraft P2P 联机插件，并公开了插件与本地 Helper 的分层结构。
- [XMCL 联机指南](https://www.xmcl.app/zh/guide/p2p)：作为公开 P2P 用户流程的补充对照。

用户提到的“XPCL”没有检索到能够确认身份的独立公开仓库。本轮将可核验的 PCL N/Terracotta 作为 XPCL 相关实现的对照对象，避免把不确定的项目误归给某个作者。

## 对照结论

### PCL 历史联机版本的具体记录

PCL 2.11.1 的公开更新记录（[Discussion #7413](https://github.com/Meloong-Git/PCL/discussions/7413)）是本次历史提交对照的主要依据：它记录了共享节点按负载选择、复制邀请码快速加入、关闭启动器时提示退出联机、节点状态/自定义节点、RPC 与监听端口占用修复，以及联机组件的 JSON CLI 输出。PCL 源码的历史更新文本也保留了“新增：联机功能”和“自动加入房间”的入口（[FormMain.xaml.vb](https://github.com/Meloong-Git/PCL/blob/main/Plain%20Craft%20Launcher%202/FormMain.xaml.vb)）。这些记录说明它把网络发现、节点选择、生命周期和 UI 提示拆开处理，而不是让一个请求承担所有职责。
### PCL / PCL-CE 的稳定性思路

PCL 系列的联机入口围绕实例、身份和房主/成员流程组织，关键状态由启动器统一驱动。稳定性的核心不是增加更多网络转发，而是：在发起连接前检查实例版本、加载器、模组和身份；把“创建、等待、加入、关闭、失败重试”变成有限状态；将游戏流量和控制面分开；把失败解释成可操作的检查项。

### 公开项目的风险边界

PCL 的公开讨论也记录过联机入口暂时隐藏，以及共享中继需要大量节点与抗攻击能力的现实约束（[2.12.0 更新日志](https://github.com/Meloong-Git/PCL/discussions/7858)）。因此 HXZ 0.8.7 默认关闭“全员开房”，只让管理员、明确授权成员或有效凭证创建房间；管理员可以按负载调小房间和连接上限。
### PCL N Terracotta 的可借鉴部分

Terracotta 的公开说明明确采用“托管插件 + 独立 Rust Helper”双进程结构：插件负责页面、游戏会话和生命周期，Helper 负责本地 IPC 与网络；实现包含 EasyTier、Scaffolding、mesh、同机发现、稳定身份心跳、退出清理、自动广播转发地址、双工 IPC、重连、Helper 崩溃恢复和 TCP 探测回退。这些边界使 UI 线程不会承担网络传输，也避免把探针误当成真实成员。

### HXZ 现有实现与不足

HXZ 已经采用“社区信令只交换候选，游戏流量直连”的边界，并有房间邀请和 P2P 协商。但旧实现把房间上限、连接上限和探测/协商超时散落在代码中，管理员无法根据负载调节；全员开房权限也没有单独的可见开关；在线时长榜只返回固定数量的条目；客户端缺少统一的联机状态提示。

## 0.8.7 的落地改动

1. 社区后台新增“允许所有用户使用完全联机功能”开关，默认关闭。关闭时仍保留管理员、授权成员和有效凭证三种开房途径。
2. 后台可配置最大房间数、单房间最大连接数、公网探测超时和信令协商超时；服务端统一把这些限制用于房间目录、探测和 WebSocket 信令。
3. 客户端在联机卡片显示全员联机状态和当前房间连接上限，避免用户误以为权限或网络已失效。
4. 在线时长榜支持 500 条默认结果和 `offset`/`limit` 分页，返回 `hasMore` 与总人数；仍只统计可信游戏服核验的时长，奖励规则保持每累计真实 24 小时 5 积分。
5. 新增四个轻量小游戏：星环采集、雾港配给、霓虹节拍、秘境炼金。它们复用同一回合接口、动作白名单和确定性状态机，桌面端与移动端共用规则。
6. 小游戏加入“简化显示”开关，只隐藏头图、标签和介绍，保留名称、开始和收藏操作；开关按用户本地保存，默认完整显示。
7. 联机卡片读取 `/api/lobby/access` 返回的房间连接上限，在客户端显示并限制到安全范围；旧服务端返回异常时回退到 32，避免旧版本无法创建房间。
8. 联机检查同时发起公网候选和 P2P 候选，优先使用先成功的直连路径，减少单一探针超时造成的假失败。
9. P2P 协商增加三次有限重试和递增等待，失败后返回可操作的连接状态，不会让界面无限等待。
10. 简化小游戏卡片重新按内容测量高度：保留标题、编号、类型提示、开始和收藏，移除头图及重复说明；三列网格自动对齐，已在桌面预览中检查完整显示与简化显示两种状态。

## 后续边界

HXZ 不会把 PCL、PCL N/Terracotta 或其他项目的源码直接搬入。后续若引入本地 Helper，应保持协议隔离、可替换网络后端、退出时强制清理和可诊断的重连状态；任何中继都必须显式标识，不得把控制信令伪装成游戏流量。
