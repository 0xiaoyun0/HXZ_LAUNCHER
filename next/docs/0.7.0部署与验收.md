# 0.7.0 部署与验收

交付目录：E:/hxz_next/release/0.7.0。保留已发布的 0.6.4，发布物与真实账号、游戏文件分开。

## 选择客户端

- windows-x64：64 位安装器及 portable 便携文件夹，正常 Windows 桌面优先使用。
- windows-ia32：共享功能的 32 位兼容安装器和便携版，使用 Electron 22。Minecraft 与 Java 对系统、架构的要求另行适用；没有在实体 Windows 7 验收。
- android：幻想镇社区 APK，以及可选的 HXZ-GameEngine ARM64 游戏运行组件。社区 APK 最低 Android 10。覆盖升级沿用现有证书和应用身份。
- server：独立社区服务端完整包。update.zip 仅供更新器下载，不是第二个必须部署的服务端。
- updates：供客户端、安卓游戏组件及社区服务使用的签名更新清单，与对应安装器/更新归档一同发布；普通玩家无需单独下载。

便携版升级时保留原 profile 与需要的 launcher-cache；勿用测试夹具覆盖真实配置。安装版维持原应用 ID 与安装目录规则。游戏目录及已有世界不随程序升级删除。

## 初次升级社区端

1. 停止旧进程，备份完整 data 目录与 .env。不要只复制 community.sqlite 而遗漏尚未检查点的 WAL。
2. 将新版完整服务端解压到独立目录，把原 data 与 .env 复制过来。不要覆盖备份。相对 HXZ_DATA 相对于服务端工作目录；也可设置绝对路径。
3. Windows 运行「启动社区服务.bat」。其他平台使用 Node.js 24+：`node --env-file=.env supervisor.mjs`。反向代理仍指向原端口，语音继续使用 /ws。
4. 登录后台，确认玩家、余额、周榜、总榜、帖子与图片。旧数据保留；新功能以建表方式加入。
5. 「服务维护 → 服务更新」中默认每六小时检查，自动安装默认关闭。开启自动安装后，指定北京时间 0–23 时中的时段。

更新文件校验 Ed25519 签名、大小、SHA-512、路径及版本。文件放在 data/.updates/releases；监督进程保持原 data/.env 路径。切换前关闭服务并用 SQLite VACUUM INTO 备份，随后启动新版；30 秒无法就绪或版本不匹配时恢复旧程序及数据库。备份位于 data/.updates/backups，结果在 last-result.json。数据量大时先安排维护窗口并留足备份空间。更新不会自动替换 Node.js 本身；若以后提高 Node.js 要求，后台会说明。

发布者使用 scripts/package-community.mjs 生成完整包，再用 scripts/package-community-update.mjs 生成更新包及 community-update.json。签名私钥仅存在发行机器。此后每版都要包含 supervisor、src/public/shared/integrations 的相容实现，不能只上传网页文件。

## 公会与积分

玩家积分委托先托管，管理员批准后公开。一次玩家委托由一位玩家认领；管理员主线可由多人各完成一次。提交凭证后，由委托人或管理员验收；主线必须由管理员验收。

玩家委托仅转移余额，不凭空增加周榜/总榜；取消或拒绝只退回原托管款，不增加榜单。管理员主线奖励属于新发放积分，进入本周，再按既有周结算并入年度总榜。结算使用唯一操作编号，重复请求不会重复支付。已有认领的委托由管理员协调撤销。道具奖励是游戏内承诺，不假装由社区自动发放。

后台账户发布时默认「管理员主线」。任务详情可复制 LINKING 主线任务标识；在 LINKING 管理 → 任务中选择「公会主线」并填入该标识，完成并验收后满足条件。草稿发布、排期及旧进度遵循《LINKING档案馆开发与管理》。

## 三服游戏统计

后台「默认服务器 → 游戏统计接入」为 survival、mod-1、mod-2 分别创建令牌。只在对应 Minecraft 服务端保存；不得放入整合包、玩家客户端或公开配置。轮换会立即停用旧令牌。

各服准备 Python 3.9+，运行随包的 integrations/game_stats_bridge.py。采集器只读世界下 stats 和 advancements，不修改存档、不安装游戏模组。world 指实际保存这些目录的主世界；MCDR 启动目录可能是其下 server/world。

在采集器旁创建 game-stats.json：

```json
{
  "community": "https://qqbot.hxzmc.top",
  "server": "mod-2",
  "token": "在本机填入该服统计令牌",
  "world": "服务器世界的绝对路径",
  "interval": 60,
  "uuid_map": {}
}
```

执行 `python game_stats_bridge.py game-stats.json`。需要持续运行可交给自己的进程管理器。只有变动文件会重新上传，逐文件流式处理并分批发送，不把整个世界统计常驻内存。异常下轮重试；时间须与社区相差不超过十分钟。首次大量数据会逐批同步。

使用皮肤站真实 UUID；如游戏服使用另一套离线 UUID，uuid_map 填「游戏 UUID → 皮肤站 UUID」。不能由玩家客户端自行声明统计真实性。

活动统计示例：游戏时间 `minecraft:custom/minecraft:play_time`（tick，72,000 为一小时）；死亡次数 `minecraft:custom/minecraft:deaths`；成就 `advancement:minecraft:story/mine_stone`（完成为 1）。后台任务使用 server、metric、value 三项。接口也接受服务器自定义的安全命名指标，但击杀某玩家、交易或任务道具等额外事件需要服务器自身插件调用上报接口，采集器不会虚构这些事件。

## Android 游戏组件

在「发现 → Minecraft」阅读提示后安装同签名的组件。也可手动安装交付包中 HXZ-GameEngine-0.7.0-arm64.apk，再返回社区刷新。Android 的 APK 安装确认由系统完成。

三服读取社区默认配置；原版服按配置安装游戏、Fabric、Fabric API。模组服读取 HXZ UP 的 gameVersion/loader 配置，并由 FCL 安装适用于 Android 的游戏本体、依赖和运行环境。更新器把 1/ 的实例内容和 3/ 的共享游戏内容映射到此服自己的游戏目录，同名时实例文件优先；0/、2/、4/、5/ 及其清理规则跳过。运行库 assets/libraries/versions、存档、截图和更新器自身始终保留。服务器的桌面 Java/native 文件不能直接覆盖 Android 运行环境。Fabric API 元数据和文件也有官方优先、失败五次换镜像的流程。

社区与组件分别运行。皮肤站令牌仅通过签名保护的显式本地调用传入内存；不使用网上的第三方 FCL 安装包接收令牌。组件高级设置可调触控、渲染等；社区入口可调内存、更新、自动进入服务器，或选择仅安装。游戏数据在组件自己的应用存储中，卸载组件前必须备份世界。管理员若改成归档包安装模式，当前入口会要求先在引擎导入或改为 HXZ UP 配置。

源代码固定上游提交 efe4dcc5dbc78c55be177c330239e12845ae7ccf，保留 GPL-3.0、版权与原依赖许可，修改版使用独立名称与应用 ID。对应源码归档、构建说明与修改入口随组件交付。

尚需真实设备确认：Android 各 GPU 与三服大型模组实际进服、麦克风和移动网络质量、Windows 7 32 位，以及公网三服部署统计采集器后的记录。没有修改公网社区数据或真实游戏存档。发行包通过 [GitHub v0.7.0](https://github.com/0xiaoyun0/HXZ_LAUNCHER/releases/tag/v0.7.0) 提供；发布新版本不会自动替管理员迁移线上服务端。
