# 0.8.0 使用与升级

本地交付目录：E:/hxz_next/release/0.8.0。源码：E:/hxz_next。安装器、便携版、安卓、社区服务端、游戏服务端桥分别存放；没有替换 E:/HXZL，也没有向线上写入测试数据。

## 入口

- 社区 → 工作台是集中办事区域，默认显示「我的待办」；待处理、等待结果、进行中、已办结共用原功能数据，操作完成后刷新分类。完整办事导航继续保留，管理员可进入管理待审事项。
- 按场景也可直接进入：聊天 → 好友与小队；公告 → 活动赛事；资源 → 作品共建/知识建造；实例 → 世界与入服；音乐 → 一起看视频；账号 → 玩家空间；商城 → 玩家交易；设置 → 帮助与反馈 → 申诉与协商。Android 使用相应页面的快捷入口，返回会回到原栏目。
- 一起看视频：在节目目录添加 B 站完整视频链接、BV/av 标识或 b23 短链接，创建放映房间，伙伴加入。首次播放可能需要点击。使用房间内的播放、暂停和定位控制同步；B 站自身会员、地区、登录、版权限制照常生效。
- 文件选择保留系统文件对话框，按钮采用统一卡片样式；长文件名不会撑出卡片。隐藏文件输入所对应的原有上传按钮继续有效。
- 棋局工坊：完成一局后明确分享，得到挑战码；打开回放、选择步骤、选择机器人或联机练习。分享会公开棋步和双方显示名；作者和管理员可以撤回。练习不获得榜单积分。
- 实例维护：从实例详情进入维护，可建立恢复点、复制实验实例、应用设置预设。迁移选空目录并在校验完成后切换，原目录保留。恢复点不是完整硬盘备份；共享存档的实例先开启隔离。
- Android 桌面组件：多端接续中点击添加，或在手机桌面的小组件列表选择「幻想镇 · 社区随行」。组件打开聊天、收件箱、接续和活动，显示上次访问的信息；退出账号会清空摘要。

## Windows 与 Android

Windows x64 为主版本；ia32 使用 Electron 22 兼容运行时和同一套功能源码。选择对应架构安装器，不把 x64 文件手工改名充当 32 位版本。安装版沿用已有应用标识和升级签名；便携版关闭后覆盖程序文件并保留 profile，或将 profile 复制到新版便携目录。

游戏目录和 Java 保持原设置。新建测试副本、迁移、恢复都需要在界面确认；本次构建没有改动用户的 .minecraft。

Android 沿用 top.hxzmc.community 包名和既有正式签名，80000 高于 0.7.3 的 70301，可覆盖安装并保留账号与设置。最低 Android 10。游戏运行组件保持当前 0.7.0 修订组件，与社区 APK 分开；不要卸载原组件来更新社区。

自动更新只有对应文件与签名清单公开发布后才会推送。本地 updates 目录的生成不等于 GitHub 已发布。

## 社区服务端

1. 停止社区服务，备份整个 data 目录、.env 和自定义反向代理配置。运行中的 SQLite 不能只复制单个主文件；停服后完整备份，或使用数据库备份接口。
2. 在原服务目录升级程序，保留 data/.env；完整服务包适合首次部署，update.zip 是已有服务的更新载荷，两者无需各开一个服务。
3. 保持 Node.js 24 或使用 Windows 完整包自带的 node.exe。原 supervisor 启动方式保留。自动更新发布后由后台校验签名、备份并执行更新。
4. 首次启动自动创建新增表，不重置积分、背包、论坛和用户会话。本机已用真实 0.7.3 数据结构建立隔离样本验证升级；仍必须备份真实数据。
5. 检查管理员登录、普通账号、聊天和旧内容，再开放新的活动、作品、交易与申诉入口。
6. 若回退，停止服务，将程序与升级前完整数据备份一起恢复；不要用旧程序任意修改新版数据后再反复切换。

真实游戏服务端的目录尚未提供。游戏桥单独交付，安装方式见《0.8.0游戏服务端桥》，本次没有把客户端目录当作服务端部署。

## 已知验证边界

Android 网页在多个手机尺寸验证，APK 编译、签名与 lint 已检查；没有连接实体设备验收屏幕观看、桌面组件及原生导出。ia32 在当前 x64 Windows 启动检查不等于实体 Windows 7。P2P 同机传输不等于所有 NAT 均可直连。本地识别/翻译需要运行环境与模型支持，不把不可用能力显示成已完成。
