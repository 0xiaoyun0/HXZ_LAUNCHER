# 公会、积分与游戏数据

玩家积分委托在创建时扣入托管，审核拒绝或允许撤销时原额退还。管理员审核发布，其他玩家认领，提交文字和至多三张图片，由委托人或管理员验收。已认领委托不能由委托人单方撤销，需要管理员协商处理。退款和结算具有唯一流水编号，重复请求不会重复发钱。

玩家之间结算只转移余额，不生成排行榜积分，避免反复互发任务刷榜。管理员发布的主线奖励计入完成者当周榜，随周榜结算进年度总榜。游戏道具是委托人的交付承诺，启动器不会伪装成已在游戏中发放。主线每人只可完成一次，已完成记录不会因关闭任务而丢失。

## LINKING

活动任务新增「完成公会主线」「达成服务器统计」。前者填写主线固定标识，后者填写服务器、统计项与目标值。解锁在社区服务端判定，已达成条件持久保存；客户端不能自报任务完成。

## 服务器统计接入

后台「游戏数据」为三个默认服分别创建专用令牌，一次显示，妥善保存在对应游戏服。每台服务器的令牌只能写自己的数据。更换令牌立即撤销旧令牌。

服务端包中的 `integrations/game_stats_bridge.py` 使用 Python 标准库，可独立运行，也可由 MCDR 的进程管理启动。不修改世界文件、不读取聊天、没有 RCON 权限。配置世界路径后读取原版 / NeoForge 共同使用的 `stats/*.json` 和 `advancements/*.json`。默认每 60 秒同步，网络失败下一轮继续。启动器中展示自己的统计，公会和 LINKING 可用作条件。需要游戏服确实部署采集器才能获得真实数据；只有启动器更新不会产生服务器统计。

示例统计项：`minecraft:custom/minecraft:play_time`（刻）、`minecraft:mined/minecraft:stone`（块）、`advancement:minecraft/story/mine_stone`（达成为 1）。账号 UUID 应与皮肤站角色 UUID 一致；代理服采用不同 UUID 时在配置的 `uuid_map` 映射。

请求：`POST /api/game-stats/report`，请求头 `Authorization: Bearer 专用令牌`、`X-HXZ-Server: survival|mod-1|mod-2`，正文 `{id, observed, players:[{uid,stats:{统计项:非负整数}}]}`。单次最多 100 名玩家、每名 500 项；服务端时间与社区相差不能超过十分钟。事件编号去重，旧快照不能覆盖新快照。`GET /api/game-stats` 只返回当前登录角色自己的记录。

公会接口：`GET/POST /api/guild`；列表参数 scope 为 public / main / mine / review（管理员）；详情 `GET /api/guild/:id`；POST 动作为 review / accept / submit / resolve / cancel。图片先 POST `/api/media/upload`（scope=guild、image=PNG data URL）；待审核图片只有提交人、相关委托人和管理员可见。公开图片保持同域，不接受远程图片抓取地址。
