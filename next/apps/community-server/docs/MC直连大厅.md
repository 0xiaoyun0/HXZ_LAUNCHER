# 0.6.2 MC 直连大厅

2026-09-30。0.6.2 配套功能，完整社区服务端与客户端分开交付；没有自动部署线上社区。

## 玩家怎么用

1. 管理员先部署完整社区服务端 0.6.2，重启社区服务。管理员在启动器“联机 → 管理员 · 房主授权”选择已登录过社区的成员并授权。社区管理员自身可以开房。
2. 房主登录皮肤站角色，选择已安装的实例，使用“异地联机 · 自动检测公网”，点击“检测网络并启动房间”。无法直连时可使用「允许社区限速中继」，或选择已有虚拟局域网适配器；均不可用时会明确提示。
3. 检测通过后正常进入自己的单人世界。本地 Java 助手尝试自动开放世界，看到“世界已开放”才表示其他玩家可以加入。不需要手动点击游戏的“对局域网开放”或输入映射端口。
4. 玩家在“正在联机的房间”卡片选择相同版本、加载器和模组的实例，点击“启动并加入”。也可以粘贴房主私发的邀请。加入前会再次检查房主网络和世界状态。
5. “在大厅公开房间”默认开启，关闭后只通过邀请加入。列表显示房主、版本、加载器、连接范围和世界状态，20 秒刷新，也可手动刷新。连接数是游戏 TCP 连接数，不能当作准确在线玩家人数。
6. 关闭联机或退出房主游戏会断开直连通道、尝试释放映射。世界和存档留在房主电脑。房主仍在游戏时关闭联机不会强制结束游戏，也不会删除存档。

## 网络边界

社区服务负责登录角色、创建权限、房间目录、公网探测及可选游戏中继。优先在玩家与房主之间直接传输 TLS 加密字节；直连失败后可经社区转发加密通道，默认每房间双向合计 256 KB/s。管理员可关闭或调整限速。普通成员可以查看公开房间并加入，没有开房权限时不能通过客户端创建房间。

异地模式优先检测可入站的公网 IPv6/IPv4，并尝试 UPnP 自动映射公网 IPv4。服务端必须具备对应地址族的出站能力才能完成探测。双方都要具备相容的可达网络；同一局域网模式不意味着已经具备异地连接能力。

运营商内网、路由器不支持/关闭 UPnP、入站防火墙阻断或双方地址族不相容时，无法承诺零配置直连。界面会报告失败原因，不自动改系统防火墙，中继开关在开房卡片中明确显示；传输方式和累计流量在连接状态中显示。首次使用时操作系统可能要求允许启动器接受网络连接。

## 完整服务端部署

推荐下载一个 `HXZ-Community-0.6.2-windows-x64.zip`，已经包含直连模块、网页后台及全部社区功能，无需第二个包。Windows 双击「启动社区服务.bat」，后台默认 `http://127.0.0.1:8787/admin/`，在「联机大厅」管理授权。升级前停服、备份并完整保留旧 data 与 .env，详见服务端 README。

### 虚拟局域网与中继

房主与访客须先自行加入同一个可信虚拟局域网，在开房卡片选择相应适配器。启动器不安装驱动，不改系统路由。中继复用社区的 `/lobby-relay` WebSocket，请确保与 `/ws` 一样配置反向代理 Upgrade。仅提供游戏通道，不是全局 VPN。

新增接口（均使用社区现有身份验证）：

| 接口 | 作用 |
| --- | --- |
| GET /api/lobby/access | 当前角色与创建权限 |
| GET /api/lobby/rooms | 查看公开房间 |
| POST /api/lobby/rooms | 授权房主登记/续期自己的房间 |
| DELETE /api/lobby/rooms | 房主或管理员移除房间 |
| POST /api/lobby/lease | 获取/续验创建权限 |
| POST /api/lobby/probe | 授权房主验证公网通道，仅允许公网数字 IP |
| GET /api/admin/lobby/grants | 管理员查看成员与授权 |
| POST /api/admin/lobby/grants | 管理员授权/撤销，参数 uid、enabled |

## 实现与验证范围

客户端每个房间生成临时 RSA 2048 / SHA-256 证书，邀请绑定证书 SHA-256 指纹；客户端核对指纹后才发送随机邀请凭据。最低 TLS 1.2。私钥只存在于本机内存；目录持有加入所需邀请，管理员和已登录社区成员能取得公开房间邀请，因此不要在其他公开平台分享私密邀请。

Java 助手随启动器分发，仅在房主通过大厅启动游戏时加载。当前限定 Java 版 1.20 及以后，兼容命名/中间映射并在需要时读取游戏官方映射；在游戏主线程调用内置 LAN 开放方法。不会给加入者开启作弊权限。助手的错误显示在大厅并保留在任务日志。

已完成：真实本机 HTTP 权限与房间目录、授权/撤销、等待世界/世界就绪/关闭移除；TLS 双端 2 MB 数据往返、错误凭据和错误证书拒绝；不可达网络阻止开房；64 位 Electron 44 和 32 位 Electron 22 运行时实际直连传输。曾发现 Electron 不支持初版的 PSK 密码套件，已改为标准 TLS 证书固定并通过两个运行时验证。

Java 助手在本机 Java 夹具中验证自动开放和退出世界事件。浏览器截图与操作检查覆盖管理员、普通玩家、公开房间加入、关闭弹窗、浅色/暗色、窄窗口大字号。生产包另做原生 IPC、导航与音乐检查。

尚需用户验收：两处真实异地网络、实际路由器 UPnP、具体整合包内的图形游戏自动开放及多人联机、实体 Windows 7。上述本机测试不等于这些场景已通过。新卡片列表在完整服务端升级或旧版扩展部署后才有真实内容。

## 后续维护

UI 继续遵循 UI卡片规范.md，页面入口在统一导航中管理。房间列表有内部滚动上限；卡片尺寸测量保留列表位置，支持拖动、缩放、隐藏与恢复。

`scripts/bundle-network.mjs` 对固定版本的 UPnP 库做有模式检查的构建适配：内联 SSDP 包元数据，发现结束后释放发现套接字，移除 SOAP 参数中的重复协议字段。升级依赖时如果模式不匹配，构建会报错要求检查；不得静默跳过。相关第三方许可证随便携包交付。
