# 0.6.4 合作游戏接口

沿用社区登录令牌与已有 HTTPS/WSS 连接，无需新增端口。仅玩家角色可参与，控制台管理员身份不能代替玩家进入游戏。浏览器携带 Authorization: Bearer；客户端原生桥接沿用现有会话。

## HTTP

| 接口 | 行为 |
| --- | --- |
| GET /api/coop/tanks | 列出可加入和本人已加入的房间，返回 items |
| POST /api/coop/tanks | body: {title}，创建房间并返回 {room,uid} |
| GET /api/coop/tanks/:id | 本房间成员获取 {room,uid} |
| POST /api/coop/tanks/:id | body.action: join / ready / start / pause / resume / leave |

房间限两人，双方需在线并准备，房主开始。每个用户只能参加一个未结束的房间。房间号为 8 位十六进制大写字符。离开等待中的房间会转移房主或销毁空房；离开已开始的房间会终止本局，不发放该局成绩。

## WebSocket

完成原有 auth 消息后发送：

```json
{"type":"coop-control","id":"A1B2C3D4","seq":1,"keys":["left","fire"]}
```

keys 仅接受 up/down/left/right/fire，最多三项。客户端每 350 ms 心跳，按键变化立即发送；松键发送更新后的集合，离开前清空。seq 在当前连接内递增，新连接可从头计数。身份由已认证的连接决定，不能指定另一个用户。不要传坐标、生命或分数。

服务端发送 `{type:"coop-state",room}`，仅发给本房间成员；playing 时约 15 Hz，其他状态约 1 Hz。room 包含 id/title/host/phase/reason/members/state。phase 为 waiting/playing/paused/finished。超过约 1.8 秒未收到任一方控制心跳，双方暂停；客户端需恢复连接后明确 resume。前台隐藏时主动 pause。

游戏按 30 Hz 固定规则运行，伤害和计分由服务端决定。正常结束仅结算一次，成绩写入既有小游戏周榜与长期榜，周积分口径不变。暂停房间闲置 30 分钟清除，已结束房间 5 分钟清除；重启服务端不恢复正在进行的对局。

## 更新和数据

停服并备份整个 data 和 .env，然后使用新版完整服务端程序，保留原 data/.env。不删除任何积分或账号表。旧客户端规则 2–5 继续验证，0.6.4 单人游戏使用规则 6；旧第 10 款历史榜单保留，新坦克榜独立使用 tanks 标识。
