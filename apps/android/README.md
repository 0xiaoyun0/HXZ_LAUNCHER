# 幻想镇 Android

手机和平板通常选择 ARM64，使用 x86_64 安卓系统的设备或模拟器请选择 x86_64。系统最低版本为 Android 8.0。0.9.2 安卓正式版玩家请直接下载新版 APK 覆盖安装。测试包与正式包独立安装，测试数据在对应的测试应用内。[正式版下载](https://github.com/0xiaoyun0/HXZ_LAUNCHER/releases/latest)

打开应用进入社区大厅。游客可以阅读服务器公告、查看近期讨论和浏览三个社区服务器。从公告或服务器卡片点「进入服务器」，首次使用会打开原生皮肤站登录窗口。选择角色后继续进入刚才选的服。下次打开应用会恢复这个角色。点顶部的角色名可以切换角色或重新验证。

游戏使用固定提交的 FCL 实例管理、版本安装、Java 运行时、渲染和触控。启动前按服务器要求匹配游戏和加载器版本。缺少实例时，可安装服主发布的整合包、安装指定游戏版本或导入本地整合包。首页和「游戏库」都使用幻想镇界面。公告里可以选择已安装的实例，也能查看和取消安装任务。打开游戏库可下载原版、导入整合包或启动单人游戏。已授予共享存储权限的旧安装继续使用原游戏目录，新安装默认在应用专属目录保存实例和存档。

社区使用 Kotlin、AndroidX WebKit 和 APK 内置的 React/TypeScript 页面。页面共用桌面端的标题、社区栏目和卡片样式，紧凑窗口可以在聊天标题中打开在线名单。皮肤站令牌由原生层保存和轮换，社区页面只接收限于社区的会话。进服时由原生层核对角色和服务器地址，向皮肤站在线验证，并将这个服务器作为本次游戏的连接目标。

社区服每次进服都检查 HXZUP 公布的版本。服务器详情会显示 Minecraft 和加载器版本，离线时标出上次核对的结果。下载使用清单里的文件来源和发布节点，首次安装逐文件核对 SHA-1。同一发布版本下载中断后，可以回到原实例补全。保留了本地修改的旧实例在游戏库仍可打开。手机只安装游戏目录中的内容。支持 Quick Play 的游戏在连接时使用服务器公布的原始域名，旧版本由原生端查询 Minecraft SRV 服务记录。显式端口优先。多人游戏列表保留同一批官方入口，断线后可在游戏里重新加入。检测到已知的桌面输入法模组时，玩家可以在当前实例中停用它，原 JAR 以 `.disabled` 后缀保留。

竖屏时，底部可切换社区、游戏库和游戏任务，横屏或宽屏使用顶部导航。右上角的调色板可以切换桌面同款的三套配色、调整动效和个性化大厅。首页默认用简洁标题。「社区大厅 → 自定义」可单独选择头图、设置裁切位置，也可使用模组一服实拍的「大厅实景」。三个服的图标来自各自 Minecraft 入口，内置图片的编辑源位于 `public/media/town`。

「背景」可以使用主题底色、手机图片或静音循环视频，并可调整画面位置和淡化程度。系统或应用开启减少动态效果时显示视频的静态画面。玩家通过 Android 文件选择器授权所选文件，外观副本保存在当前应用的本地存储。同一设备上的角色共用外观。选择「跟随主题」或「简洁标题」可暂时收起自选素材，「移除」可清除应用内的副本。「首页卡片」可独立调整服务器、公告、近期讨论的显示与顺序，随时恢复默认。

手机界面只显示一处主导航。页面在标题栏与导航之间滚动，弹窗保留可见的关闭按钮，系统返回键优先关闭当前弹窗。主导航提供至少 44 CSS 像素的点按范围。服务器图标紧邻名称。页面和开关的动效使用共享时长，切换页面不等待动画结束。社区回归覆盖 320 宽大字号、横竖屏切换、外观重开、导航边界和离线版本重试。

「游戏库 → 实例设置 → 内存」显示设备报告的物理运存、系统交换空间和上次实际生成的 Java 堆预算。「将系统虚拟内存计入游戏预算」是默认关闭的风险选项，按实例保存，下次启动生效。启用时会根据启动当刻的空闲交换空间、物理运存余量及系统低内存标记计算增量，同时为系统和原生渲染保留空间。标准档最多额外计入 1 GiB，加大档最多 2 GiB；两个档位都保留物理运存和交换空间余量。关闭后额外预算归零。系统仍按自身策略使用 zRAM 或厂商提供的交换空间。自定义 JVM 堆参数优先。手机画质和 ModernFix 按需加载模型可以独立选择，后者在整合包声明支持时显示。

部分整合包提供 JEI 的「低内存物品搜索」。在独立实例中开启它，会用较慢的搜索换取较小的物品索引。关闭可恢复原设置，两个操作都保留其他 JEI 配置和整合包配方。

`npm run test:android:policies` 验证预算、SRV 记录和实例配置的可逆修改。`npm run test:android:hxzup -- --serial <设备> --server HXZ-mod-1` 将真机实例逐项与当期 HXZUP 核对，分别统计完整文件、安卓停用的模组和发布规则允许保留的配置。`npm run test:android:launch -- --serial <设备> --package top.hxzmc.launcher.third.debug --server HXZ-mod-1 --instance HXZ-mod-1 --memory off` 通过社区页面冷启动到 Minecraft 游戏窗口。游戏握手、世界画面、触控移动和退出另行在设备验收。

从仓库根目录运行 `npm ci` 和 `npm run android:build`。构建使用 JDK 17、Gradle 8.14.4、Android SDK 35、NDK 27.0.12077973 和 CMake 3.22.1。设置 `ANDROID_HOME` 指向 SDK。默认使用上游 Gradle Wrapper；离线准备好的 Gradle 可用 `HXZ_GRADLE` 指定。传 `-- --x86_64` 构建模拟器架构。默认 ARM64 调试包独立安装在 `top.hxzmc.launcher.third.debug`。

`upstream.json` 记录仓库、提交和许可证。构建核对 Git 提交并应用 `fcl.patch`，新代码在 `src`、`res`、`community`。上游依赖、资源和补丁可由上述步骤重建。随下游分发的 FCL 和集成代码遵循 GPL-3.0-or-later，原始版权和第三方组件各自的许可证继续有效。发布 APK 时提供本仓库对应提交、补丁和固定上游的完整对应源码。

`--release` 使用发行方的 `HXZ_ANDROID_STORE`、`HXZ_ANDROID_STORE_PASSWORD`、`HXZ_ANDROID_KEY_ALIAS`、`HXZ_ANDROID_KEY_PASSWORD`。线上更新只识别幻想镇发布页上对应架构的正式包。生产社区部署的 `HXZ_ORIGINS` 若显式配置，需要包括 `https://appassets.androidplatform.net`，以允许 Android 的社区 HTTP 与 WebSocket 请求。

正式包沿用应用标识 `top.hxzmc.community` 和 0.9.2 的签名。分别运行 `npm run android:build -- --release` 与 `npm run android:build -- --release --x86_64`，再运行 `node apps/android/verify-apk.mjs --release` 检查两个正式 APK。生成 GitHub 附件时，运行 `node scripts/prepare-windows-draft.mjs <提交> --android`。本版本的完整修改见源码附件和仓库内的补丁。[对应的 FCL 上游源码](https://github.com/FCL-Team/FoldCraftLauncher/tree/722e2361f8f3013b6ebc026e52749c1bf3b5be71)

构建后运行 `node apps/android/verify-apk.mjs` 检查两种 APK 内的架构、四套 JRE、JNI、LWJGL、触控和上游版本记录。`npm run test:android:community` 启动临时社区服务，检查横竖屏的导航、图标和点击区域，并在 390×844 的浏览器视口验证从公告选服、取消登录、选择实例、查看和取消下载、聊天收发和在线名单、论坛、冒险者协会、LINKING、排行与钱包。同一测试会逐个打开 22 个社区栏目、解码游戏厅的 24 张封面、实际开始一局计分游戏，模拟丢失结算回包，并通过另一会话核对时长奖励、积分余额和榜单。它复用 APK 的网页构建产物。设备验收应从社区公告进服，核对服务器接收的角色，退出游戏并重开应用，检查角色和社区内容。单人世界从「游戏库」启动游戏，在游戏内创建或载入世界，保存退出后回到社区。
